# 支持者（付费方案）

只有在管理员启用后，本地用户才能在网页上订阅付费方案，并在持续付费期间拥有与该方案绑定的角色。这项计划默认关闭，启用之前，任何地方都不会出现方案或订阅的入口。部署配置键 `payments` 的说明见[配置参考](../reference/configuration.md#payments)。

**mycroblog 不保证符合任何法律，包括日本的《特定商取引法》。** 披露信息的内容、最终确认页面以及消费税和发票的处理方式，都需要运营者对照本国法律自行确认（见下文“运营者需要确认的事项”）。

## 订阅的工作方式

![订阅的流程：用户在支付服务商处付款，服务商的事件让服务器重新读取状态，服务器授予或移除方案的角色并记录收入。各步骤列在下文。](images/supporter-flow.svg)

按图中从上到下的顺序：

- **订阅。** 用户在 `/settings/supporter` 选择方案和周期（按月或按年）。最终确认之后，服务器（`my serve`）在 `payments` 所设置的服务商（`stripe` 或 `payjp`）处创建支付页面，用户在该页面上付款。
- **事件。** 服务商把事件发送到 Webhook 端点 `POST /payments/webhooks/{provider}`，端点将每个事件只记录一次并加入一个任务队列。事件只是一个信号：服务器从不根据事件内容获取状态。
- **回读。** 任务 `supporters.apply_payment_event`，以及每隔 `payments_reconcile_interval` 运行一次的对账 `supporters.reconcile_payments`，会从服务商的 API 回读订阅和资金往来。对账会补上没有送达的事件。
- **状态与角色。** 服务器根据读取到的内容和已经过去的期限（例如 7 天的宽限期）推导出订阅的状态，并据此授予或移除方案的角色。
- **收入。** 资金往来会变成收入记录（每笔付款、退款、拒付和手续费的总额、手续费和净额）。它们的合计显示在财务页面（`/finance`，面向拥有 `view_finance` 的人），并在 `income_visibility` 允许的范围内显示在 `/about/costs`（见 [instance-settings.md](instance-settings.md)）。

![订阅的状态：active、canceling 和 past_due 拥有方案的角色；pending、lapsed、expired、revoked 和 abandoned 没有。各状态之间的转换列在下文。](images/supporter-states.svg)

订阅的状态（管理界面和 `my admin supporters subscriptions` 中显示的样子）：

- `pending`：已开始，尚未付款。没有角色。首次付款后变为 `active`，在首次付款前结束的订阅变为 `abandoned`。
- `active`：已付款。拥有方案的角色，每次续订都会保留。
- `past_due`：付款失败。从失败起保留角色 7 天；在此期间付款则重新变为 `active`。
- `lapsed`：付款失败后已过 7 天。角色被移除。此后付款会重新变为 `active`，角色也会恢复。
- `canceling`：已设为在周期结束时取消。在此之前保留角色，之后变为 `expired`。
- `expired`、`revoked`（全额退款或拒付）和 `abandoned` 是最终状态，不拥有角色。

## 启用计划

1. 将部署配置键 `payments` 设为你的支付服务商，并传入服务商的密钥和 Webhook 密钥。各服务商的具体步骤见 [payments-stripe.md](payments-stripe.md) 和 [payments-payjp.md](payments-payjp.md)。该键为 `none` 时无法启用计划。
2. 配置服务器发送邮件（`mail` 不为 `none`）。只有邮箱地址已确认的用户才能订阅，因此不发送邮件的服务器无法启用计划。
3. 在管理界面“条款和政策”的“商业信息披露”页面（`/admin/documents/commerce-disclosure`），用 Markdown 撰写商业信息披露（在日本即《特定商取引法》要求的标示），也就是实例文本 `commerce_disclosure`。它发布在 `/about/commerce`，你可以在服务商的控制台中登记这个 URL。文本为空时也可以启用计划，但管理界面会显示警告。
4. 在管理界面的“角色”中，创建要与方案绑定的角色。它必须没有持有者，只有成员权限（`member` 组），并且 `position` 低于所有工作人员角色（包括 `moderator`）。成员权限就是方案可以提供的权益：`create_custom_emojis`（申请自定义表情）、`view_finance`（查看服务器的财务）、`start_voice_rooms`（在仅限获准用户时开启语音聊天房间）、`create_invites`（在仅限获准用户时邀请他人，受[成员邀请](registration.md#member-invites)的限制）以及 `keep_posts_longer`（让帖子保留超过[自动删除的上限](instance-settings.md#automatic-deletion-of-old-posts)，并在上限生效时关闭自动删除）。订阅结束时角色随之移除，权益也一并失去：支持者发出的邀请会失效，直到再次订阅；自动删除的上限在宽限期过后会重新作用于其帖子。
5. 在管理界面的“支持者”中（权限 `manage_supporters`），打开“方案”页面（`/admin/supporters/plans`）并选择“创建方案”。设置名称、说明、月价、按年付款的折扣、每月创建自定义表情的上限（每月 1 日按 UTC 重置；见[自定义表情](instance-settings.md#custom-emoji)）、顺序和可见性，并选择角色。服务器会在服务商处创建月度和年度价格（不要在服务商的控制台中创建价格）。在价格创建好之前，方案处于“准备中”状态，不接受订阅。
6. 在“支持者”的“计划”页面（`/admin/supporters`），勾选“启用支持者计划”并选择“保存”。同一表单还可以设置谁能查看支持者列表。

方案创建后，它的角色就不能再手动授予或撤销，角色的权限和位置要在方案的页面上修改（在“方案”页面选择该方案）。更高的方案（顺序更大）位于较低方案的角色之上，拥有它们的全部权限，表情上限也不低于它们。

## 在服务商处的设置

- **停用账号**：订阅仍然有效时（包括设为在周期结束时终止的订阅），订阅者不能停用自己的账号。设置页面会引导他们前往订阅，以免有人在隐身期间仍被扣款。
- **重试（催缴）**：付款失败 7 天后，服务器会移除角色（与服务商的重试无关）。请将服务商的重试期设为至少 7 天，并将最终操作设为“取消”。宽限期过后付款成功时，角色会恢复。
- **客户门户**：门户用于管理付款方式和发票。请在门户中关闭方案变更，只允许在周期结束时取消。方案变更和取消在服务器自己的页面上进行。
- **退款**：服务器只退还没有买到任何东西的付款：同一笔付款产生的第二个订阅，以及已关闭的待付款订阅的付款。服务商的指南（[Stripe](payments-stripe.md)、[PAY.JP](payments-payjp.md)）说明了这两种情况。其他所有退款都由运营者在服务商的控制台中处理。全额退款和拒付会立即移除角色，并立即取消服务商处的订阅。部分退款不会移除角色。赢得拒付争议不会恢复角色；用户需要重新订阅。

## 用户看到的内容

- 在网页上，用户打开“支持者方案”（`/settings/supporter`），选择方案和付款周期（按月或按年），经过最终确认页面，然后前往服务商的支付页面。卡片信息从不经过本服务器。支付页面会返回到这个页面，然后页面会重新读取订阅的状态。订阅期间，用户可以在同一页面变更方案（升级以及从按月改为按年，在按比例计算的差额付清后生效；降级以及从按年改为按月，在周期结束时生效）、取消已安排的变更、取消订阅（权益持续到周期结束）以及撤销取消，还可以打开客户门户管理付款方式和发票。当变更的付款失败，或者卡片要求进行变更流程无法发起的验证时，方案保持不变，用户会看到错误信息以及更新卡片的方法。这不会开始宽限期，也不会发送付款失败通知；续订失败仍然会。
- 只有本服务器上邮箱地址已确认、账号既未被暂停也未被安排删除的用户才能订阅。一个用户同一时间只能持有一个方案。
- `/about` 会显示一个列出公开方案的区块。在 Tauri 应用中，订阅页面、`/about` 中的方案区块以及指向它们的链接都不会出现。权益（徽章、自定义表情、财务）在应用中同样有效。

## 发给订阅者的通知

以下每种情况都会通过通知、Web Push 和邮件（发到主邮箱地址，使用用户的语言）告知订阅者一次。账号已停用的订阅者不会收到任何告知，当时不会，回来之后也不会。

- 付款失败（`supporter_payment_failed`）：订阅变为逾期（`past_due`）时。告知宽限期的结束时间（邮件中为 UTC）以及可以修改付款方式的页面链接（`/settings/supporter`）。
- 订阅结束（`supporter_subscription_ended`）：订阅因宽限期届满、到期或因退款或拒付而结束，从而离开拥有权益的状态时。消息会说明原因。因删除账号而结束的情况不会告知。
- 方案停用（`supporter_plan_retired`）：发给已停用方案的订阅者（待付款的除外）。告知订阅将不再续订。
- 服务终止公告（`supporter_service_closure`）：发给公告开始时订阅被设为在周期结束时取消的订阅者（待付款的除外）。告知订阅将不再续订。公告期间不接受新的订阅。

Web Push 和通知的文字不会引导到支付页面。只有网页客户端会在通知中放置订阅页面的链接；Tauri 应用不会。邮件中的链接会在浏览器中打开网页客户端。

## CLI

`my admin supporters` 可以执行管理界面的部分操作（`my admin supporters -help`）。

- `status`：计划是否已启用，启用前还缺什么（服务商、邮件），以及正在运行的订阅数。
- `enable`、`disable`：启用和停用计划。有订阅正在运行时拒绝停用。
- `plans`：方案列表（包括已停用的），以及准备中和已停用的方案数和订阅数。
- `subscriptions`：订阅列表（用 `-plan` 和 `-state` 筛选）。`cancel <subscription ID>` 立即取消一个订阅（不退款，但待付款订阅的付款除外，因为它没有买到任何东西）。

启用、停用和取消会作为 CLI 操作写入审计日志。方案的创建、修改和停用在管理界面或通过管理 API 进行。

## 成员列表

- 实例设置 `supporter_list_visibility`（在“支持者”页面上；见 [instance-settings.md](instance-settings.md)）决定谁能查看当前订阅者的列表（`/about/supporters`）。默认值为 `off`，此时列表和 `/about` 上的链接都不会出现。
- 列表只显示在自己设置的“徽章和支持者列表”页面上选择公开列出的订阅者（默认不列出任何人）。它显示方案名称以及每个人的头像、昵称和用户名，从不显示金额、按月还是按年付款、日期或次数。
- 订阅者变更方案时，公开列出的选择会保留；订阅结束（角色被移除）时会消失。重新订阅的人从不公开列出的状态开始。
- 无论搜索引擎设置（`search_indexing`）如何，列表页面及其 API 始终发送 `noindex, noarchive`。

## 修改价格、隐藏方案和停用方案

- 修改月价或折扣后，新价格适用于新订阅和方案变更。现有订阅者按原价续订。没有把现有订阅者迁移到新价格的操作。要迁移他们，请创建一个新方案并停用旧方案。
- 隐藏方案会停止对该方案的新订阅和变更。现有订阅继续有效。
- 停用方案无法撤销。它的订阅会在各自周期结束时取消（待付款的订阅会立即关闭，其支付页面停止收款，之后仍到达的付款会被退还；付款逾期超过宽限期的订阅会立即取消）。最后一个订阅结束后，该角色恢复为普通角色。

## 账号与订阅

- 删除账号和封禁账号（会安排删除）会立即取消其订阅，不退款（仍处于待付款状态的订阅的付款没有买到任何东西，会被退还）。撤销封禁不会恢复订阅。
- 暂停账号会安排在周期结束时取消订阅。解除暂停不会自动恢复；用户需要在周期结束前撤销取消，或者重新订阅。
- 在“支持者”的“订阅”页面（`/admin/supporters/subscriptions`），管理员可以打开某个订阅，并用“立即结束”立即终止它（不退款，但待付款订阅的付款除外，因为它没有买到任何东西；此操作会写入审计日志）。

## 停用计划和更换服务商

- 只要有任何订阅正在运行（待付款、有效、已安排取消、逾期或已过宽限期），就无法停用计划。请先停用所有方案，等订阅结束后再停用计划。
- 要更换服务商，请停用计划、修改 `payments`，然后用新服务商重新启用计划。现有订阅者需要重新订阅。当配置的服务商与启用计划时的服务商不同时，服务器会拒绝新的订阅和变更，管理界面会显示警告。

## 运营者需要确认的事项（尚未核实）

mycroblog 不对以下任何一项作出判断。请对照你所在国家的法律和服务商的条款自行确认。

- 商业信息披露必须包含的项目（卖方的名称、地址和电话号码、价格、付款时间和方式、提供服务的时间、取消方法等）以及必须如何公布。
- 将服务商的支付页面和 `my` 的确认页面合在一起看，最终确认页面（《特定商取引法》第 12 条之 6）是否显示了数量、价格、付款时间、交付时间以及取消方法及其效果。
- 消费税的处理方式，以及是否开具合格发票。
