# 支持者（付費方案）

只有在管理員啟用之後，本站使用者才能在網頁上訂閱付費方案，並在持續付款期間持有與方案綁定的角色。這個計畫預設為關閉，在啟用之前，任何地方都不會出現方案或訂閱的入口。部署設定鍵 `payments` 說明在[設定參考](../reference/configuration.md#payments)中。

**mycroblog 不保證符合任何法律，包括日本的《特定商業交易法》**。營運者必須依照自己國家的法律，確認揭露資訊的內容、最終確認畫面，以及消費稅和發票的處理方式（請參閱下方的「營運者必須確認的事項」）。

## 訂閱的運作方式

![訂閱的流程：使用者在付款服務提供者處付款，服務提供者的事件讓伺服器讀回狀態，伺服器再授予或移除方案的角色並記錄收入。各步驟列在下方。](images/supporter-flow.svg)

由圖表上方往下：

- **訂閱**。使用者在 `/settings/supporter` 選擇方案和週期（月或年）。最終確認後，伺服器（`my serve`）會在 `payments` 所設定的服務提供者（`stripe` 或 `payjp`）處建立付款頁面，使用者在該頁面上付款。
- **事件**。服務提供者把事件送到 Webhook 端點 `POST /payments/webhooks/{provider}`，端點會把每個事件記錄一次並把任務放入佇列。事件只是一個訊號：伺服器絕不會從事件內容取得狀態。
- **讀回**。任務 `supporters.apply_payment_event`，以及每隔 `payments_reconcile_interval` 執行一次的對帳 `supporters.reconcile_payments`，會從服務提供者的 API 讀回訂閱和金流。對帳會修補沒有送達的事件。
- **狀態與角色**。伺服器會根據讀到的內容和已經過去的各個期限（例如 7 天的寬限期）推導出訂閱的狀態，並據此授予或移除方案的角色。
- **收入**。金流會成為收入記錄（每筆付款、退款、退單和手續費的總額、手續費和淨額）。它們的合計會顯示在財務畫面（`/finance`，供擁有 `view_finance` 的人查看），並在 `income_visibility` 允許的範圍內顯示在 `/about/costs` 上（請參閱 [instance-settings.md](instance-settings.md)）。

![訂閱的狀態：active、canceling 和 past_due 持有方案的角色；pending、lapsed、expired、revoked 和 abandoned 則沒有。狀態轉換列在下方。](images/supporter-states.svg)

訂閱的狀態（依管理介面和 `my admin supporters subscriptions` 的顯示）：

- `pending`：已開始，尚未付款。沒有角色。第一次付款後會變成 `active`，在第一次付款前就結束的訂閱會變成 `abandoned`。
- `active`：已付款。持有方案的角色，每次續約都會保留。
- `past_due`：付款失敗。從失敗時起保留角色 7 天；在這段期間內付款會讓它再次變成 `active`。
- `lapsed`：失敗後已過 7 天。角色會被移除。之後付款會讓它再次變成 `active`，角色也會恢復。
- `canceling`：已設定在週期結束時取消。在那之前保留角色，之後變成 `expired`。
- `expired`、`revoked`（全額退款或退單）和 `abandoned` 是最終狀態，不持有角色。

## 啟用計畫

1. 把部署設定鍵 `payments` 設為你的付款服務提供者，並傳入服務提供者的金鑰和 Webhook 密鑰。各服務提供者的步驟請參閱 [payments-stripe.md](payments-stripe.md) 和 [payments-payjp.md](payments-payjp.md)。設定鍵為 `none` 時無法啟用計畫。
2. 設定伺服器寄送電子郵件（`mail` 不為 `none`）。只有電子郵件地址已確認的使用者才能訂閱，所以不寄送電子郵件的伺服器無法啟用計畫。
3. 在管理介面「條款與政策」的「商業交易資訊揭露」頁面（`/admin/documents/commerce-disclosure`）上，以 Markdown 撰寫商業交易資訊揭露（在日本是《特定商業交易法》所要求的標示），也就是實例文字 `commerce_disclosure`。它會發布在 `/about/commerce`，你可以把這個 URL 填入服務提供者的儀表板中。即使文字是空的也能啟用計畫，但管理介面會顯示警告。
4. 在管理介面的「角色」中建立要與方案綁定的角色。它必須沒有任何持有者，只有成員權限（群組 `member`），而且 `position` 低於所有工作人員角色（包括 `moderator`）。成員權限就是方案可以提供的福利：`create_custom_emojis`（申請自訂表情符號）、`view_finance`（查看伺服器的財務）、`start_voice_rooms`（在只有獲准使用者可以開啟時開啟語音聊天室）、`create_invites`（在只有獲准使用者可以邀請時邀請他人，並受[成員邀請](registration.md#member-invites)的限制），以及 `keep_posts_longer`（讓貼文保留超過[自動刪除的上限](instance-settings.md#automatic-deletion-of-old-posts)，並在上限啟用時關閉自動刪除）。訂閱結束時，角色會被移除，福利也隨之消失：支持者建立的邀請在他重新訂閱之前都會失效，而自動刪除的上限會在寬限期過後再次套用到他的貼文上。
5. 在管理介面的「支持者」（權限 `manage_supporters`）中，開啟「方案」頁面（`/admin/supporters/plans`），然後選擇「建立方案」。設定名稱、說明、月費、年繳折扣、每月建立自訂表情符號的上限（每月第一天以 UTC 重設；請參閱[自訂表情符號](instance-settings.md#custom-emoji)）、排序和可見性，並選擇角色。伺服器會在服務提供者處建立月繳和年繳的價格（不要在服務提供者的儀表板中建立價格）。在價格建立之前，方案會處於「準備中」狀態，不接受訂閱。
6. 在「支持者」的「計畫」頁面（`/admin/supporters`）上，勾選「啟用支持者計畫」，然後選擇「儲存」。同一個表單也可以設定誰能查看支持者名單。

方案建立後，其角色就無法再手動授予或撤銷，角色的權限和位置要在方案的頁面上變更（在「方案」頁面上選擇該方案）。較高的方案（排序較大）位於較低方案的角色之上，擁有較低方案的所有權限，表情符號上限也至少與它們一樣高。

## 服務提供者端的設定

- **停用帳號**：訂閱仍有效時（包括設定在週期結束時終止的訂閱），訂閱者無法停用自己的帳號。設定畫面會引導他前往訂閱，避免有人在隱藏的狀態下被扣款。
- **重試（催收）**：付款失敗 7 天後，伺服器會移除角色（與服務提供者的重試無關）。請把服務提供者的重試期間設為至少 7 天，並把最終動作設為「取消」。寬限期過後付款成功時，角色會恢復。
- **客戶入口網站**：入口網站是為了付款方式和發票而開啟的。請在入口網站中關閉方案變更，只允許在週期結束時取消。方案變更和取消要在伺服器自己的畫面上進行。
- **退款**：伺服器只會退還沒有買到任何東西的付款：同一筆付款的第二個訂閱，以及已關閉之待處理訂閱的付款。服務提供者的指南（[Stripe](payments-stripe.md)、[PAY.JP](payments-payjp.md)）說明了這兩種情況。其他所有退款都由營運者在服務提供者的儀表板中處理。全額退款和退單會立即移除角色，並立即取消服務提供者端的訂閱。部分退款不會移除角色。退單爭議勝訴並不會恢復角色；使用者需要重新訂閱。

## 使用者看到的內容

- 在網頁上，使用者開啟「支持者方案」（`/settings/supporter`），選擇方案和付款週期（月或年），經過最終確認畫面後，前往服務提供者的付款頁面。信用卡資料絕不會經過這台伺服器。付款頁面會返回這個畫面，畫面接著會重新讀取訂閱的狀態。訂閱期間，使用者可以在同一個畫面上變更方案（升級以及從月繳改為年繳，會在按比例計算的差額付款後生效；降級以及從年繳改為月繳，則在週期結束時生效）、取消已排定的變更、取消訂閱（福利會持續到週期結束）以及撤回取消，並開啟客戶入口網站管理付款方式和發票。當變更的付款失敗，或信用卡要求變更流程無法提出的驗證時，方案維持不變，使用者會看到一則錯誤訊息，說明如何更新信用卡。這不會開始寬限期，也不會寄送付款失敗的通知；續約失敗則仍會如此。
- 只有這台伺服器上、擁有已確認的電子郵件地址，且帳號既未被停權也未排定刪除的使用者才能訂閱。一位使用者一次只能持有一個方案。
- `/about` 會顯示一個列出公開方案的區段。在 Tauri 應用程式中，不會出現訂閱畫面、`/about` 的方案區段，以及指向它們的連結。福利（徽章、自訂表情符號、財務）在應用程式中也能使用。

## 給訂閱者的通知

以下每一種情況，訂閱者都會透過通知、Web Push 和電子郵件（寄到主要地址，使用使用者的語言）收到一次告知。帳號已停用的訂閱者當時不會收到任何告知，重新啟用時也不會。

- 付款失敗（`supporter_payment_failed`）：訂閱變成逾期（`past_due`）時。內容包括寬限期的結束時間（電子郵件中以 UTC 表示），以及可以修正付款方式的畫面連結（`/settings/supporter`）。
- 訂閱結束（`supporter_subscription_ended`）：訂閱因寬限期結束、到期，或因退款或退單而結束，離開有福利的狀態時。訊息會說明原因。因刪除帳號而結束的情況不會通知。
- 方案停用（`supporter_plan_retired`）：通知已停用方案的訂閱者（待處理的除外）。內容說明訂閱將不會續約。
- 服務結束公告（`supporter_service_closure`）：通知在公告開始時其訂閱被設定為在週期結束時取消的訂閱者（待處理的除外）。內容說明訂閱將不會續約。公告期間不接受新的訂閱。

Web Push 和通知的文字不會引導到付款畫面。只有網頁用戶端會在通知中放入訂閱畫面的連結；Tauri 應用程式不會。電子郵件中的連結會在瀏覽器中開啟網頁用戶端。

## CLI

`my admin supporters` 可以執行管理介面的部分操作（`my admin supporters -help`）。

- `status`：計畫是否已啟用、啟用前還需要什麼（服務提供者、電子郵件），以及進行中的訂閱數量。
- `enable`、`disable`：啟用和停用計畫。有任何進行中的訂閱時，會拒絕停用。
- `plans`：方案清單（包括已停用的方案），以及準備中和已停用的方案數量與訂閱數量。
- `subscriptions`：訂閱清單（以 `-plan` 和 `-state` 篩選）。`cancel <subscription ID>` 會立即取消訂閱（不退款，但待處理訂閱的付款例外，因為它沒有買到任何東西）。

啟用、停用和取消會以 CLI 操作的形式寫入稽核記錄。建立、變更和停用方案要在管理介面中或透過管理 API 進行。

## 成員名單

- 實例設定 `supporter_list_visibility`（在「支持者」畫面上；請參閱 [instance-settings.md](instance-settings.md)）決定誰能看到目前訂閱者的名單（`/about/supporters`）。預設為 `off`，此時名單和 `/about` 中的連結都不會出現。
- 名單只會顯示在自己設定的「徽章與支持者列表」頁面上選擇列出的訂閱者（預設不列出任何人）。名單會顯示方案名稱，以及每個人的大頭貼、顯示名稱和帳號代稱，絕不會顯示金額、月繳或年繳、日期或次數。
- 選擇列出的設定在訂閱者變更方案時會保留，在訂閱結束（角色被移除）時會消失。重新訂閱的人一開始不會被列出。
- 無論搜尋引擎設定（`search_indexing`）如何，名單頁面及其 API 一律傳送 `noindex, noarchive`。

## 變更價格、隱藏方案與停用方案

- 變更月費或折扣時，新價格會套用到新的訂閱和方案變更。現有的訂閱者會以原本的價格續約。沒有把現有訂閱者移到新價格的操作。要移動他們，請建立新的方案並停用舊的方案。
- 隱藏方案會停止新的訂閱，以及變更為該方案。現有的訂閱會繼續。
- 停用方案無法復原。其訂閱會在週期結束時取消（待處理的訂閱會立即關閉，其付款頁面也會停止接受付款，之後仍送達的任何付款都會退款；付款逾期超過寬限期的訂閱則會立即取消）。最後一個訂閱結束時，角色會回到一般角色。

## 帳號與訂閱

- 刪除帳號和封禁帳號（會排定刪除）會立即取消其訂閱，不退款（仍在待處理狀態之訂閱的付款沒有買到任何東西，會退款）。撤銷封禁並不會恢復訂閱。
- 停權帳號會排定在週期結束時取消。解除停權不會自動恢復；使用者需要在週期結束前撤回取消，或重新訂閱。
- 在「支持者」的「訂閱」頁面（`/admin/supporters/subscriptions`）上，管理員可以開啟某個訂閱，並以「立即終止」立即結束它（不退款，但待處理訂閱的付款例外，因為它沒有買到任何東西；這項操作會寫入稽核記錄）。

## 停用計畫與更換服務提供者

- 有任何進行中的訂閱（待處理、有效、已排定取消、逾期，或已超過寬限期）時，無法停用計畫。請先停用所有方案，並在訂閱結束後再停用計畫。
- 要更換服務提供者，請停用計畫、變更 `payments`，然後以新的服務提供者重新啟用計畫。現有的訂閱者需要重新訂閱。當設定的服務提供者與啟用計畫時的不同，伺服器會拒絕新的訂閱和變更，管理介面也會顯示警告。

## 營運者必須確認的事項（尚未驗證）

mycroblog 不會對以下任何一項做出判斷。請依照你所在國家的法律和服務提供者的條款加以確認。

- 商業交易資訊揭露必須包含的項目（賣方的名稱、地址和電話號碼、價格、付款的時間和方式、提供服務的時間、取消的方式等）以及必須如何公布。
- 最終確認畫面（《特定商業交易法》第 12 條之 6）是否顯示數量、價格、付款時間、交付時間，以及取消的方式及其效果，並把服務提供者的付款頁面和 `my` 的確認畫面合併考量。
- 消費稅的處理方式，以及你是否開立合格發票。
