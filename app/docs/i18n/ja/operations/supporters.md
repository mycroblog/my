# サポーター（有料プラン）

管理者が有効にしたときだけ、ローカルユーザーは Web で有料プランを購読でき、支払いを続けているあいだそのプランに結び付いたロールを持てます。この制度は既定ではオフで、有効にするまでは、プランや購読の入口はどこにも表示されません。
デプロイ時のキー `payments` は[設定リファレンス](../reference/configuration.md#payments)で説明しています。

**mycroblog は、日本の特定商取引法を含め、いかなる法令への準拠も保証しません。** 表記の内容、最終確認画面、消費税とインボイスの扱いは、運営者が自国の法令に照らして確認してください（下の「運営者が確認すべきこと」を参照してください）。

## サブスクリプションの仕組み

![サブスクリプションの流れ。ユーザーが決済の事業者で支払い、事業者のイベントを受けてサーバーが状態を読み直し、サーバーがプランのロールを付与または解除して収入を記録します。手順は下に列挙しています。](images/supporter-flow.svg)

図の上から順に説明します。

- **購読。** ユーザーは `/settings/supporter` でプランと間隔（月または年）を選びます。最終確認のあと、サーバー（`my serve`）が `payments` で設定した事業者（`stripe` または `payjp`）に支払いページを作り、ユーザーはそのページで支払います。
- **イベント。** 事業者はイベントを Webhook のエンドポイント `POST /payments/webhooks/{provider}` に送り、エンドポイントは各イベントを 1 回だけ記録してジョブをキューに入れます。イベントは合図にすぎず、サーバーがその内容から状態を取ることはありません。
- **読み直し。** ジョブ `supporters.apply_payment_event` と、`payments_reconcile_interval` ごとの照合 `supporters.reconcile_payments` が、事業者の API からサブスクリプションとお金の動きを読み直します。照合は、届かなかったイベントを補います。
- **状態とロール。** サーバーは、読んだ内容と、過ぎた期限（たとえば 7 日間の猶予期間）からサブスクリプションの状態を導き、それに従ってプランのロールを付与または解除します。
- **収入。** お金の動きは収入の記録（支払い、返金、チャージバック、手数料ごとの総額、手数料、純額）になります。その合計は、財務の画面（`/finance`、`view_finance` を持つ人向け）と、`income_visibility` が許す範囲で `/about/costs` に表示されます（[instance-settings.md](instance-settings.md) を参照してください）。

![サブスクリプションの状態。active、canceling、past_due はプランのロールを持ち、pending、lapsed、expired、revoked、abandoned は持ちません。遷移は下に列挙しています。](images/supporter-states.svg)

管理画面と `my admin supporters subscriptions` が示すサブスクリプションの状態は次のとおりです。

- `pending`: 始まったが、まだ支払われていない。ロールなし。最初の支払いで `active` になり、最初の支払いの前に終わったサブスクリプションは `abandoned` になります。
- `active`: 支払い済み。プランのロールを持ち、更新のたびにそれを保ちます。
- `past_due`: 支払いに失敗した。失敗から 7 日間はロールを保ち、そのあいだに支払われると `active` に戻ります。
- `lapsed`: 失敗から 7 日が過ぎた。ロールは外されます。そのあとに支払われると `active` に戻り、ロールも戻ります。
- `canceling`: 期間の終わりでの解約が決まっている。それまではロールを保ち、`expired` になります。
- `expired`、`revoked`（全額返金またはチャージバック）、`abandoned` は最終の状態で、ロールを持ちません。

## 制度を有効にする

1. デプロイ時のキー `payments` に決済の事業者を設定し、事業者の鍵と Webhook のシークレットを渡します。事業者ごとの手順は [payments-stripe.md](payments-stripe.md) と [payments-payjp.md](payments-payjp.md) にあります。キーが `none` のあいだは制度を有効にできません。
2. サーバーがメールを送れるように設定します（`mail` を `none` 以外に）。購読できるのは確認済みのメールアドレスを持つユーザーだけなので、メールを送らないサーバーでは制度を有効にできません。
3. 管理画面の「規約とポリシー」の「特定商取引法に基づく表記」のページ（`/admin/documents/commerce-disclosure`）で、商取引に関する表記（日本では特定商取引法が求める表示）であるインスタンスのテキスト `commerce_disclosure` を Markdown で書きます。これは `/about/commerce` で公開され、その URL を事業者のダッシュボードに登録できます。
   テキストが空でも制度は有効にできますが、管理画面に警告が表示されます。
4. 管理画面の「ロール」で、プランに結び付けるロールを作ります。そのロールは保持者がおらず、メンバーの権限（グループ `member`）だけを持ち、`moderator` を含むすべてのスタッフのロールより低い `position` を持たなければなりません。
   メンバーの権限は、プランが与えられる特典です。`create_custom_emojis`（カスタム絵文字の申請）、`view_finance`（サーバーの財務の閲覧）、`start_voice_rooms`（許可されたユーザーだけが開けるときの通話のルームの開設）、`create_invites`（許可されたユーザーだけが招待できるときの、[メンバーによる招待](registration.md#member-invites)の制限内での招待）、`keep_posts_longer`（[自動削除の上限](instance-settings.md#automatic-deletion-of-old-posts)を超えて投稿を残すことと、上限があるときに自動削除をオフにすること）です。
   サブスクリプションが終わるとロールが外れ、特典もなくなります。サポーターが作った招待は再び購読するまで使えなくなり、自動削除の上限は猶予期間のあとで再びその人の投稿に適用されます。
5. 管理画面の「サポーター」（権限 `manage_supporters`）で「プラン」のページ（`/admin/supporters/plans`）を開き、「プランを作成する」を選びます。名前、説明、月額の価格、年払いの割引、カスタム絵文字の作成の月間上限（毎月 1 日（UTC）にリセットされます。[カスタム絵文字](instance-settings.md#custom-emoji)を参照してください）、順番、公開の有無を設定し、ロールを選びます。
   サーバーは月額と年額の価格を事業者に作ります（事業者のダッシュボードで価格を作らないでください）。価格ができるまで、プランは「準備中」で、購読を受け付けません。
6. 「サポーター」の「課金」のページ（`/admin/supporters`）で「課金の機能を有効にする」にチェックを入れ、「保存」を選びます。同じフォームで、サポーターの一覧を誰が見られるかも設定します。

プランができると、そのロールは手作業では付与も取り消しもできなくなり、その権限と position はプランのページ（「プラン」のページでプランを選びます）で変えます。上位のプラン（順番が大きいもの）は、下位のプランのロールより上に位置し、それらのすべての権限を持ち、絵文字の上限もそれらと同じかそれより高くなります。

## 事業者側の設定

- **アカウントの停止**: サブスクリプションが続いているあいだは、期間の終わりに終わる設定のものも含め、購読者は自分のアカウントを停止できません。設定の画面はサブスクリプションへと案内し、隠れたまま課金される人が出ないようにします。
- **再試行（督促）**: 支払いの失敗から 7 日後に、サーバーはロールを外します（事業者の再試行とは無関係です）。事業者の再試行期間を 7 日以上にし、最後の動作を「キャンセル」にしてください。猶予期間のあとに支払いが成功すると、ロールは戻ります。
- **顧客ポータル**: ポータルは支払い方法と請求書のために開きます。ポータルでのプランの変更はオフにし、期間の終わりでの解約だけを許可してください。プランの変更と解約は、サーバー自身の画面で行います。
- **返金**: サーバーが返金するのは、何も買わなかった支払いだけです。1 回の支払いで生じた 2 つ目のサブスクリプションと、閉じた保留中のサブスクリプションへの支払いです。どちらも事業者のガイド（[Stripe](payments-stripe.md)、[PAY.JP](payments-payjp.md)）で説明しています。それ以外の返金はすべて、運営者が事業者のダッシュボードで行います。全額返金とチャージバックでは、ロールがすぐに外れ、事業者のサブスクリプションもすぐに解約されます。一部返金ではロールは外れません。チャージバックに勝ってもロールは戻らず、ユーザーが再び購読します。

## ユーザーに見えるもの

- Web では、ユーザーは「サポーターのプラン」（`/settings/supporter`）を開き、プランと支払いの間隔（月または年）を選び、最終確認の画面を経て、事業者の支払いページに進みます。カード情報がこのサーバーを通ることはありません。支払いページはこの画面に戻り、画面はサブスクリプションの状態をもう一度読みます。
  購読中は、同じ画面から、プランの変更（アップグレードと月払いから年払いへの切り替えは日割りの差額が支払われた時点で、ダウングレードと年払いから月払いへの切り替えは期間の終わりに適用されます）、予定された変更の取り消し、サブスクリプションの解約（特典は期間の終わりまで続きます）とその取り消し、支払い方法と請求書のための顧客ポータルを開くことができます。
  変更の支払いに失敗したときや、変更では求められない認証をカードが求めたときは、プランはそのままで、ユーザーにはカードを更新する方法を示すエラーが表示されます。これによって猶予期間が始まったり、支払い失敗の通知が送られたりはしません。更新の失敗では、これまでどおりそうなります。
- 購読できるのは、このサーバーのユーザーで、確認済みのメールアドレスを持ち、アカウントが凍結も削除予定もされていない人だけです。ユーザーが同時に持てるプランは 1 つです。
- `/about` には、公開しているプランの欄が表示されます。Tauri のアプリでは、購読の画面、`/about` のプランの欄、それらへのリンクは表示されません。特典（バッジ、カスタム絵文字、財務）はアプリでも使えます。

## 購読者への通知

購読者には、次のそれぞれについて、通知、Web Push、メール（メインのアドレスに、ユーザーの言語で）で 1 回ずつ知らせます。アカウントを停止している購読者には、そのときも戻ってきたときも何も知らせません。

- 支払いの失敗（`supporter_payment_failed`）: サブスクリプションが支払い遅れ（`past_due`）になったとき。猶予期間の終わり（メールでは UTC）と、支払い方法を直せる画面（`/settings/supporter`）へのリンクを示します。
- サブスクリプションの終了（`supporter_subscription_ended`）: 猶予期間が切れた、期限が来た、または返金やチャージバックで終わったために、サブスクリプションが特典のある状態を離れたとき。メッセージは理由を示します。アカウントの削除による終了は知らせません。
- プランの終了（`supporter_plan_retired`）: 終了したプランの購読者に（保留中のものを除く）。サブスクリプションが更新されないことを伝えます。
- サービス終了の告知（`supporter_service_closure`）: 告知が始まったときに、期間の終わりでサブスクリプションが解約された購読者に（保留中のものを除く）。サブスクリプションが更新されないことを伝えます。告知のあいだは、新しいサブスクリプションを受け付けません。

Web Push と通知の文面は支払いの画面には誘導しません。通知に購読の画面へのリンクを付けるのは Web クライアントだけで、Tauri のアプリは付けません。メールのリンクは、ブラウザーで Web クライアントを開きます。

## CLI

`my admin supporters` は、管理画面の操作の一部を行います（`my admin supporters -help`）。

- `status`: 制度が有効かどうか、有効にする前に必要なもの（事業者、メール）、実行中のサブスクリプションの数。
- `enable`、`disable`: 制度を有効・無効にします。サブスクリプションが 1 つでも実行中のあいだは、無効にすることは拒否されます。
- `plans`: プランの一覧（終了したものを含む）と、準備中と終了したプランの数、サブスクリプションの数。
- `subscriptions`: サブスクリプションの一覧（`-plan` と `-state` で絞り込みます）。`cancel <subscription ID>` はサブスクリプションをすぐに解約します（返金はしません。ただし、何も買わなかった保留中のサブスクリプションへの支払いは除きます）。

有効化、無効化、解約は、CLI の操作として監査ログに記録されます。プランの作成、変更、終了は、管理画面か管理 API で行います。

## メンバーの一覧

- インスタンスの設定 `supporter_list_visibility`（「サポーター」の画面にあります。[instance-settings.md](instance-settings.md) を参照してください）で、現在の購読者の一覧（`/about/supporters`）を誰が見られるかを選びます。既定の `off` では、一覧も `/about` からのリンクも表示されません。
- 一覧に表示されるのは、設定の「バッジとサポーターの一覧」のページで表示を選んだ購読者だけです（既定では誰も表示されません）。プラン名と、各人のアイコン、表示名、ハンドルを表示し、金額、月払いか年払いか、日付、回数は決して表示しません。
- 表示する選択は、購読者がプランを変えても残り、サブスクリプションが終わる（ロールが外れる）と消えます。再び購読した人は、表示しない状態から始まります。
- 一覧のページとその API は、検索エンジンの設定（`search_indexing`）にかかわらず、常に `noindex, noarchive` を送ります。

## 価格の変更、プランの非公開、プランの終了

- 月額の価格や割引を変えると、新しい価格は新しいサブスクリプションとプランの変更に適用されます。既存の購読者は元の価格で更新されます。既存の購読者を新しい価格に移す操作はありません。移すには、新しいプランを作り、古いプランを終了します。
- プランを非公開にすると、そのプランへの新しいサブスクリプションと変更が止まります。既存のサブスクリプションは続きます。
- プランの終了は元に戻せません。そのサブスクリプションは期間の終わりに解約されます（保留中のものはすぐに閉じ、その支払いページは支払いを受け付けなくなり、それでも届いた支払いは返金されます。猶予期間を過ぎて支払いが遅れているものはすぐに解約されます）。最後のサブスクリプションが終わると、ロールは普通のロールに戻ります。

## アカウントとサブスクリプション

- アカウントの削除と BAN（削除を予定します）は、そのサブスクリプションを返金なしですぐに解約します（まだ保留中のサブスクリプションへの支払いは何も買っていないので、返金されます）。BAN を取り消しても、サブスクリプションは戻りません。
- アカウントを凍結すると、期間の終わりでの解約が予定されます。凍結を解除しても自動では戻りません。ユーザーが期間の終わりまでに解約を取り消すか、再び購読します。
- 「サポーター」の「加入」のページ（`/admin/supporters/subscriptions`）で、管理者は 1 つのサブスクリプションを開き、「すぐに解約」ですぐに終わらせられます（返金はしません。ただし、何も買わなかった保留中のサブスクリプションへの支払いは除きます。監査ログに記録されます）。

## 制度の無効化と事業者の変更

- サブスクリプションが 1 つでも実行中（保留中、有効、解約予定、支払い遅れ、猶予期間後）のあいだは、制度を無効にできません。先にすべてのプランを終了し、サブスクリプションが終わってから制度を無効にしてください。
- 事業者を変えるには、制度を無効にし、`payments` を変えて、新しい事業者で制度をもう一度有効にします。既存の購読者は再び購読します。設定した事業者が制度を有効にしたときの事業者と異なるあいだは、サーバーは新しいサブスクリプションと変更を拒否し、管理画面に警告が表示されます。

## 運営者が確認すべきこと（未検証）

mycroblog はこれらのいずれについても判断しません。自国の法令と事業者の規約に照らして確認してください。

- 商取引に関する表記に含めるべき項目（販売者の名前、住所、電話番号、価格、支払いの時期と方法、サービスの提供時期、解約の方法など）と、その公開の方法。
- 最終確認画面（特定商取引法第 12 条の 6）が、事業者の支払いページと `my` の確認画面を合わせて、数量、価格、支払いの時期、提供の時期、解約の方法とその効果を示していること。
- 消費税の扱いと、適格請求書を発行するかどうか。
