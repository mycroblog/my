# 非機能要件

数値目標のうち「要検証」と付けたものは、M1〜M6 の計測で見直します。

## コスト（NFR-COST）

コストは設計の制約ではなく、工夫して減らす対象とする。サーバーには費用がかかるので、できるところで抑え、選択肢を費用だけで退けない。

| ID | 要件 |
| --- | --- |
| NFR-COST-1 | serverless ターゲットでは scale-to-zero できること（min instances 0 を既定とする）。アイドル時のコンピュートコストを抑えられること |
| NFR-COST-2 | 常時起動が必須のミドルウェア（Redis, Elasticsearch, 専用キューサーバー等）を **必須にしない**。RDB 1 つ + オブジェクトストレージ 1 つで全機能が動く |
| NFR-COST-3 | Self-hosted は 1 vCPU / 1 GB RAM の VM で、SQLite 構成なら数十ユーザー規模を運営できること（要検証） |
| NFR-COST-4 | リモートメディアは既定でキャッシュしない（プロキシ + CDN キャッシュ）。ストレージ消費を運営者が上限設定できる |
| NFR-COST-5 | 連合配送はバッチ化・共有 inbox 利用・ドメイン単位の集約で、リクエスト数（= 課金単位）を抑える |
| NFR-COST-6 | ターゲットごとに想定コスト（無料枠・固定費・従量）の目安を `docs/architecture/deployment-targets.md` に記載し、実測で更新する |

## 可搬性・差し替え可能性（NFR-PORT）

| ID | 要件 |
| --- | --- |
| NFR-PORT-1 | ドメイン層・アプリケーション層は、特定クラウドの SDK やランタイム固有 API に依存しない |
| NFR-PORT-2 | 外部資源（RDB, キュー, Blob, KV, メール, Push, 画像処理, スケジューラ）は「ポート」として定義し、アダプタを設定で選択する |
| NFR-PORT-3 | 各ポートにはアダプタ非依存の **コントラクトテスト** があり、新しいアダプタはそれを通過すれば採用できる |
| NFR-PORT-4 | 不要なアダプタ（とその依存）をビルドタグで除外できる（バイナリサイズ・攻撃面の削減） |
| NFR-PORT-5 | 設定は環境変数（12-factor）で完結し、任意で設定ファイルも使える。不正な設定は起動時に検証してエラーにする |

## 性能・スケーラビリティ（NFR-PERF）

| ID | 要件 |
| --- | --- |
| NFR-PERF-1 | 単一ノード構成で 1,000 ユーザー / 1 日 10 万アクティビティ受信程度まで動作すること（要検証） |
| NFR-PERF-2 | Web 層はステートレスで水平スケールできる。ワーカーは Web 層と同一バイナリ/バンドルで役割を切り替えられる |
| NFR-PERF-3 | API の p95 レイテンシ 300ms 以下（ホームタイムライン 20 件取得、ウォーム時、要検証） |
| NFR-PERF-4 | Inbox は署名検証と最小限の検証のみ同期で行い、処理本体は非同期キューに回す |

## 信頼性（NFR-REL）

| ID | 要件 |
| --- | --- |
| NFR-REL-1 | ジョブは at-least-once で実行され、ハンドラは冪等であること |
| NFR-REL-2 | 配送失敗は指数バックオフで最大数日リトライし、最終的に Dead Letter として記録・再実行できる |
| NFR-REL-3 | トランザクションは短く保ち、内部で外部 I/O をしない。重複実行に強い書き込み（一意制約・upsert・冪等キー）にする（[ADR-0003](../adr/0003-database-abstraction.md)） |
| NFR-REL-4 | バックアップ手順と、リストア後に連合鍵が変わらないことの保証 |

## セキュリティ・プライバシー（NFR-SEC）

| ID | 要件 |
| --- | --- |
| NFR-SEC-1 | リモート取得は SSRF 対策（プライベート IP・リンクローカル・メタデータエンドポイントへの接続禁止、リダイレクト追跡時も再検査） |
| NFR-SEC-2 | リモート HTML は許可リスト方式でサニタイズする |
| NFR-SEC-3 | パスワードは Argon2id（ランタイムで利用不可の場合は ADR で定めた代替）でハッシュ化 |
| NFR-SEC-4 | 公開範囲（visibility）の判定はドメイン層の単一の関数に集約し、API・連合・タイムラインのすべてがそれを通る |
| NFR-SEC-5 | レート制限（API・ログイン・Inbox） |
| NFR-SEC-6 | アップロード画像の EXIF（位置情報）を除去する |
| NFR-SEC-7 | 秘密情報（署名鍵・OAuth シークレット）は DB 暗号化 or シークレットストアに置けるようにする |
| NFR-SEC-8 | 依存関係の既知の脆弱性を継続的に検知し、更新を自動で提案する（[ADR-0081](../adr/0081-generated-files-policy.md)） |

## 国際化（NFR-I18N）

詳細は [ADR-0009](../adr/0009-internationalization.md)。

| ID | 要件 |
| --- | --- |
| NFR-I18N-1 | すべての UI 文字列・サーバー由来の利用者向けメッセージ（メール・API エラー・通知文言）は外部化し、ハードコードしない |
| NFR-I18N-2 | メッセージは ICU MessageFormat で記述し、CLDR の複数形・性別・select を扱える |
| NFR-I18N-3 | 日付・数値・相対時刻・リストは `Intl` 等のロケール対応 API で整形し、利用者のタイムゾーンで表示する |
| NFR-I18N-4 | RTL 言語に対応（CSS 論理プロパティ、利用者コンテンツは `dir="auto"`） |
| NFR-I18N-5 | 投稿は言語タグを持ち、ActivityPub では `contentMap` で表現する |
| NFR-I18N-6 | CJK を含む検索（ハッシュタグ・アカウント・将来の全文検索）でトークナイズ方針を定める |
| NFR-I18N-7 | v0 の対応ロケールは `en`（ソース）と `ja`。疑似ロケールを CI で使い、未翻訳・文字列連結・レイアウト崩れを検出する |
| NFR-I18N-8 | 翻訳者がコードを触らずに貢献できるワークフロー（Weblate / Crowdin 等）を用意する |

## モデレーション（NFR-MOD）

出典と根拠は [#327 の調査報告](https://github.com/mycroblog/my/issues/327) にあります。

| ID | 要件 |
| --- | --- |
| NFR-MOD-1 | 監査: FR-704 の操作は、その操作と同じトランザクションで監査ログに記録する。監査ログは追記だけで、更新・削除の API と CLI を持たない（保持期間による消去を除く）。操作者は利用者・CLI・システム・リモートのいずれかで、CLI からの操作も記録する（[ADR-0058](../adr/0058-moderation-admin-separation.md)） |
| NFR-MOD-2 | 即時性: 処分と解除は記録したトランザクションのコミットで効き、次の要求から判定に反映される。ログインを奪う処分は、同じトランザクションで既存のセッションとアクセストークンを失効させる。期限は読み取り時に判定し、期限切れの反映にジョブを待たない |
| NFR-MOD-3 | 連合への伝播: 処分が生むアクティビティ（FR-716）は outbox 経由で配送し、通常の配送と同じリトライ（NFR-REL-2）に乗せる。キューが滞留していなければ、コミットから 1 分以内に最初の配送を試みる（要検証） |
| NFR-MOD-4 | 単独運用の負荷: 通報 1 件を 1 つの画面で、対象の投稿・アカウントの履歴・過去の通報を見て、処分と解決まで行える。未対応の通報と承認待ちの登録の件数を管理メニューに出し、新着はモデレーターに通知する（FR-712）。通報が 0 件の日に運用者がする作業は無い |
| NFR-MOD-5 | 個人データ: 通報者の身元は対象に見せず、転送はインスタンス Actor から送る。IP アドレスとメールアドレスは `manage_accounts` を持つ人にだけ見せる。記録の種類ごとに保持期間を定め、期限を過ぎたものは定期ジョブで消す（[ADR-0058](../adr/0058-moderation-admin-separation.md)） |
| NFR-MOD-6 | 説明: 本人への処分の通知は、種類・公開の理由（カテゴリと文章）・違反とされた投稿・期限・異議申し立ての方法を含み、本人の UI 言語で表示する（NFR-I18N-1） |
| NFR-MOD-7 | 管理画面のアクセシビリティ: 管理画面も ADR-0110 の品質ゲート（axe・横スクロール・ARIA スナップショット・キーボード操作）の対象にする。取り消せない操作（BAN・ドメインの凍結・投稿の削除）は確認のダイアログ（WAI-ARIA APG の alertdialog）を挟み、結果は `role="status"` で知らせる |
| NFR-MOD-8 | 性能: 管理画面の一覧（通報・処分・監査ログ・アカウント検索）は、キーセットページングで 1 ページ 40 件、p95 300ms 以下（NFR-PERF-3 と同じ条件、要検証） |

| ID | 要件 |
| --- | --- |
