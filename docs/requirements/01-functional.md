# 機能要件（v0）

優先度は MoSCoW で表します（**M**ust / **S**hould / **C**ould / **W**on't in v0）。
各要件 ID（`FR-xxx`）は Issue や PR から参照してください。

## アカウント・認証（identity）

| ID | 要件 | 優先度 |
| --- | --- | --- |

| FR-003 | OAuth 2.0（Authorization Code + PKCE）で一次のクライアントとサードパーティのアプリを認可できる。サードパーティのアプリは、利用者による登録・Client ID Metadata Document・動的クライアント登録（RFC 7591）で `client_id` を得る。利用者は認可したアプリを一覧して取り消せ、管理者はアプリを無効にできる（[ADR-0090](../adr/0090-third-party-oauth-apps.md)） | M |

| FR-007 | 利用者ごとの UI 言語・既定の投稿言語・タイムゾーン設定 | M |

| FR-011 | 利用者による招待の作成: 権限 `create_invites`（プランのロールに付けられる）か、インスタンス設定 `invite_creators` が `everyone` のとき、利用者は自分の招待を作り、一覧し、取り消す。同時に持てる数・回数・期間の上限はインスタンス設定で変えられる。作成者が資格を失うと未使用の招待は使えない。モデレーターは招待した人を確かめられ、作成と取り消しは監査ログに残る（[ADR-0108](../adr/0108-member-invites.md)） | S |
