# 公開範囲の閲覧判定（canView）

> 前提にしている ADR: [ADR-0017](../adr/0017-visibility-local.md)、[ADR-0018](../adr/0018-federated-uris.md)、[ADR-0020](../adr/0020-data-modeling-principles.md)。
> 要件: NFR-SEC-4、FR-102、FR-201〜204。

投稿を誰に見せるかは、`internal/domain/content` の `CanView` だけが決めます（NFR-SEC-4）。
タイムライン・検索・クライアント API・配送・ActivityPub のオブジェクト取得は、すべてこの関数を通します。
タイムラインの SQL（[data-model §6](data-model/06-timeline-queries.md#6-タイムラインのクエリ)）は候補を絞り込むための写像で、返す直前に `CanView` を再適用します。

```go
content.CanView(ctx ViewContext, viewer Viewer, status StatusFacts, author AuthorRestrictions, rel Relation) bool
content.EffectiveVisibility(original Visibility, author AuthorRestrictions) Visibility
```

この表の正本はテーブル駆動テスト `internal/domain/content/view_test.go` です。表とテストが食い違ったらテストが正しく、この文書を直します。

## 1. 入力

| 入力 | 中身 |
| --- | --- |
| 閲覧者 `Viewer` | 種類（未ログイン / ログイン中のローカルアカウント / リモートのアクター）、アカウント ID、モデレーターか |
| 投稿 `StatusFacts` | 作者のアカウント ID、作者がローカルか、保存された公開範囲（不変） |
| 作者の制限 `AuthorRestrictions` | `profile_view`、`visibility_ceiling_private`、`public_discovery`（[data-model §5.2](data-model/05-states-and-policies.md#52-処分の種類と制限能力の剥奪)） |
| 関係 `Relation` | 閲覧者から作者へのフォロー（なし / 承認待ち / 承認済み）、閲覧者が作者をブロックしているか、作者が閲覧者をブロックしているか、投稿が閲覧者をメンションしているか |
| 文脈 `ViewContext` | 単体の取得 / ホーム / ローカル / 連合 / ハッシュタグ / プロフィール / AP のオブジェクト取得 / 配送 |

- 署名付きのオブジェクト取得では、閲覧者は署名者のドメインを表します。呼び出し側は関係をドメイン単位で集約します（そのドメインに作者の `active` なフォロワーがいればフォロー済み、メンション先がいればメンション済み）。
  ブロックは、署名者のアカウント（このサーバーが知っているとき）と作者の間のものを使います。
  リモートサーバーは受け取った投稿を自分のユーザーに見せるためです。
- 署名のない取得は未ログインとして扱います。
- 不正な値（未知の公開範囲・閲覧者の種類・文脈、リモートの投稿の `local`）はすべて閲覧不可にします（fail closed）。

## 2. 実効公開範囲

判定に使う公開範囲は、保存された値ではなく **実効公開範囲 = min(元の公開範囲, 上限)** です（[data-model §5.4](data-model/05-states-and-policies.md#54-サイレンスと公開範囲)）。
公開範囲は広い順に `public` > `local` > `unlisted` > `private` > `direct` と並び、`min` は狭いほうを取ります。

| 元の公開範囲 | 制限なし | `visibility_ceiling_private`（サイレンス） |
| --- | --- | --- |
| `public` | `public` | `private` |
| `local` | `local` | `private` |
| `unlisted` | `unlisted` | `private` |
| `private` | `private` | `private` |
| `direct` | `direct` | `direct` |

投稿時の切り詰めも同じ関数で行います。

## 3. 判定の順序

1. 文脈に合わない閲覧者は閲覧不可（下表）。
2. 作者に `profile_view`（凍結・削除など）があれば、作者本人とモデレーターが単体の取得とプロフィールで見る場合を除き閲覧不可。
3. 作者本人でなければ、ブロック（どちら向きでも）があれば閲覧不可。ブロックはフォロー・メンションより常に優先します。
4. 文脈ごとの絞り込み（下表）を実効公開範囲に適用。
5. 作者本人なら閲覧可。それ以外は実効公開範囲の閲覧者（§4）に入っていれば閲覧可。

| 文脈 | 受け付ける閲覧者 | 絞り込み |
| --- | --- | --- |
| 単体の取得 | 未ログイン・ローカル | なし |
| プロフィール | 未ログイン・ローカル | なし |
| ホーム | ローカル | 自分の投稿と、承認済みでフォローしている作者の投稿だけ。フォローしていない相手からの `direct` は会話一覧で扱う |
| ローカル | 未ログイン・ローカル | 作者がローカル、`public` / `local`、作者に `public_discovery` がない |
| 連合 | 未ログイン・ローカル | `public`、作者に `public_discovery` がない |
| ハッシュタグ | 未ログイン・ローカル | `public` / `local`、作者に `public_discovery` がない |
| AP のオブジェクト取得 | 未ログイン（署名なし）・リモート（署名者のドメイン） | 作者がローカル。閲覧不可は 404 で返し、存在を漏らさない（ADR-0018） |
| 配送 | リモート | 作者がローカル。`public` / `unlisted` でも「誰でも」ではなく、フォロワーとメンション先だけ（§4） |

## 4. 公開範囲ごとの閲覧者

作者本人は、ブロック以外の判定（§3 の 1・2・4）を通れば常に閲覧できます。モデレーターの権限は `profile_view` を越えるためだけのもので、公開範囲の規則は広げません。

| 実効公開範囲 | 閲覧できる人（配送以外） | 配送先 |
| --- | --- | --- |
| `public` | 誰でも | 承認済みフォロワー、メンション先 |
| `local` | ログイン中のローカルアカウント、承認済みフォロワー（リモート含む）。**未ログインは不可** | 承認済みフォロワーだけ。**フォロワーでないメンション先には届けない** |
| `unlisted` | 誰でも | 承認済みフォロワー、メンション先 |
| `private` | 承認済みフォロワー、メンション先 | 承認済みフォロワー、メンション先 |
| `direct` | メンション先 | メンション先 |

承認待ちのフォローはフォロワーとして数えません。

通報の証拠を見るモデレーターは、この表の外にいます。通報が指す投稿は公開範囲にかかわらず読めます（[ADR-0058](../adr/0058-moderation-admin-separation.md)）。
その投稿が引用する投稿は通報が指していないので、`CanView` を通します。ただし閲覧者はどのモデレーターでもない「作者と関係のないローカルアカウント」で、作者の制限も渡しません。
つまり投稿されたときの公開範囲だけで決まり、`public` / `local` / `unlisted` は読め、`private` / `direct` は `unauthorized` です。モデレーター自身のブロックと、作者の凍結・サイレンスは隠す理由になりません。

### 5.3 作者の制限

| 制限 | 効果 |
| --- | --- |
| `visibility_ceiling_private` | すべての文脈で、実効公開範囲（§2）で投稿された場合と同じ判定になる。過去の投稿も含め、このサーバー上ではフォロワー限定として扱う |
| `public_discovery` | ローカル・連合・ハッシュタグでは誰にも出さない。それ以外の文脈は変わらない |
| `profile_view` | 作者本人とモデレーターが単体の取得・プロフィールで見る場合だけ、表 5.1 / 5.2 のとおり閲覧できる。それ以外はすべて閲覧不可（AP 取得は 404） |

## 6. アカウントの表示

投稿ではなくアカウント（プロフィール・フォロー一覧・関係）を誰に見せるかは、クライアント API（`internal/interface/clientapi` の `Server.presentable`）が次の規則で決めます。

- 有効でないアカウント（停止・削除予定・削除済み）とインスタンスアクターは、誰にも見せません。存在しないアカウントと同じ 404 です。
- モデレーションがプロフィールを隠すアカウント（`profile_view`。凍結と、凍結されたドメインのアカウント。[data-model §5.2](data-model/05-states-and-policies.md#52-処分の種類と制限能力の剥奪)）は、本人以外には有効でないアカウントと同じに扱います。モデレーターは管理 API で見ます。
- 閲覧者をブロックしているアカウントは、閲覧者に対して存在しないものとして扱います。取得・ハンドルでの検索・フォロー一覧・フォローやミュートなどの操作はすべて 404 で、
  関係の一覧からも省きます。関係（`Relationship`）は「相手にブロックされているか」を返しません。ブロックしていることを相手に知らせないためです。
- 閲覧者がブロックしているアカウントは、閲覧者からは見えます（ブロックの一覧から解除できるように）。そのアカウントをフォローしようとすると 409 です。
- 他人のフォロー一覧では、閲覧者をブロックしているアカウントと有効でないアカウントを省きます。自分のブロック・ミュート・フォローリクエストの一覧では、有効でないアカウントだけを省きます。
