## アカウントの状態（`/settings/account-status`）とサーバーの状態の画面

処分を受けた本人が、いま何ができないか・いつまでか・何ができるかを知り、異議を申し立てる画面（FR-715、FR-707）。
同じ情報を 2 か所で出す。アプリを使える人には SPA の `/settings/account-status`、処分でアプリを使えない人には、ログインの後にサーバーが描画する状態の画面（`internal/interface/authpages` の `status.html`、§8）。
2 つは同じ表し方にする（下の 3 と 5）。違うのは、SPA が過去の処分も出し、日時も出すことだけである（サーバーの画面の文言は日時の引数を持てない）。

### 1. 使う人と頻度

- 処分を受けた本人。処分の通知かログインの直後に来る。まれだが、不安な状態で読む。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 設定から処分の内容と期限を確かめる | 1 |
| 処分に異議を申し立てる | 3 |

異議の申し立ては、「異議を申し立てる」を押す 1 つ、理由を書く 1 つ（入力は 1 つと数える）、送る 1 つ。サーバーの画面ではダイアログを通らず、欄に書いて送る 2 つ。

### 3. 情報の優先順位とまとまり

処分ごとに、要約を先に置く。

1. **適用中の処分**（`h2`。サーバーの画面では見出しの代わりに処分の一覧）: 処分ごとに
   1. 処分の種類（`h3`）と状態のバッジ（`StatusBadge`。適用中は警告の色とアイコン、期限切れは時計、解除済みは確認の印。サーバーの画面は同じ文言の丸いバッジ）。
   2. いつまでか: 「あと N 日で終わります」か「モデレーターが解除するまで続きます」（両方で同じ文言）。
   3. 理由のカテゴリ、処分の日時と期限の日時（SPA）、モデレーターの説明、対象の投稿。
   4. 異議申し立て（`h4`）: 申し立てていれば状態のバッジ（審査中・処分は維持されました・処分は撤回されました）と内容と回答。できるなら「異議の申し立ては 1 回だけ、あと N 日以内にできます」（SPA は日時も添える）と「異議を申し立てる」のボタン。できなければその理由。
2. **過去の処分**（`h2`、SPA だけ）: 同じ形。

### 4. 主な操作と保存の仕方

- 主な操作は「異議を申し立てる」。両方の画面で同じ名前にする。
- 保存は、まとめて保存（理由を書いて送る）。送った後は変えられないので、SPA は確かめのダイアログの中で書いて送る。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 異議を申し立てる（SPA） | ダイアログを閉じ、その場。処分の異議申し立ての区画が審査中のバッジと内容に替わり、見出しにフォーカスを移して、画面の上の `StatusMessage` に結果を出す。失敗はダイアログの中 |
| 異議を申し立てる（サーバーの画面） | 画面を描き直し、上に結果の知らせ（`role="status"`）。異議申し立ての部分が審査中のバッジと内容に替わる。理由が空か長すぎるときは欄のエラー |

### 6. 入口と出口

- 入口: 設定のメニューの「アカウントの状態」、処分と異議の結果の通知、ログイン（アプリを使えない人はサーバーの画面に来る）。
- 出口: 設定。サーバーの画面ではログアウト。
