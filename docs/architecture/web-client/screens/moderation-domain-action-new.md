## 新しいドメインへの処分（`/moderation/domain-actions/new`）

`manage_domains` を持つ管理者が、リモートのドメインとそのサブドメインに新しい処分（FR-702）を出すページ（[§14](../14-admin.md)）。
`?domain=` のときは、そのドメインをフォームに入れて始める（[一覧](moderation-domain-actions.md)の 1 つのドメインの表示から来たとき）。

### 1. 使う人と頻度

管理者（`manage_domains`）。スパムや嫌がらせの元のサーバーを制限・凍結するときに使う。月に数回より少ない。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 一覧から来て、ドメインを制限する | 4 |
| 一覧から来て、確かめてからドメインを凍結する | 5 |
| 期限と公開コメントを付けて、ドメインのメディアを拒否する | 8 |

手順は、一覧の「新しい処分」を押す 1 つから。制限は、ドメインの入力 1 つ、種類を選ぶ 1 つ、「処分する」を押す 1 つ（期間は既定の「解除するまで」のまま）。
凍結は、確かめのダイアログの「凍結する」の 1 つを足す。期限と公開コメントは、期間の選択を開く 1 つと選ぶ 1 つ、公開コメントの入力 1 つを足す。

### 3. 情報の優先順位とまとまり

`h1`（「新しい処分」）の下に「ドメインへの処分に戻る」のリンクを置く。

1. 処分の内容（`h2`）: ドメイン（必須、U-label のまま入れてよい）・種類（必須の `RadioGroup`、軽いものから重いものの順で、それぞれの効果の説明）・期間（`DurationSelect`、既定は「解除するまで」）・
   公開コメントと非公開メモ（`ReasonField`、残りの文字数）・ドメインの一部を公開の一覧で隠すか（`Checkbox`）、その下に「処分する」と結果の `StatusMessage`。

### 4. 主な操作と保存の仕方

- 主な操作は「処分する」（画面で唯一の `primary`）。保存はまとめて保存で、ブラウザの制約の検証（未入力のドメインと種類）を通ってから送る。
- 凍結は取り消せないものを含むので、`ConfirmDialog`（alertdialog、NFR-MOD-7）で確かめてから送る。ほかの種類はすぐ効く。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 処分を出す（凍結以外） | その場。フォームの下の `StatusMessage` が何がどのドメインに効いたかを言い、フォームはドメインを残して空になる。失敗はフォームの下の `InlineError`（`role="alert"`）で、入力は残る |
| 凍結する | 確かめのダイアログの後、その場（上と同じ）。失敗はダイアログの中に出し、開いたまま。キャンセルと Esc は何も送らず、フォーカスは「処分する」へ戻る |
| 「ドメインへの処分に戻る」を押す | 画面の遷移。[一覧](moderation-domain-actions.md)へ。新しい処分は一覧にある |

### 6. 入口と出口

- 入口: 一覧の「新しい処分」（`?domain=` を引き継ぐ）。
- 出口: 「ドメインへの処分に戻る」で一覧へ。権限がなければ `AdminError` が足りない権限を示す。
