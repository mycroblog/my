## ミニプレイヤー（通話中の、ルームの画面以外のすべての画面）

通話がページを越えて続く間、ルームの画面以外のすべての画面の `main` の最後に浮かぶ小さなカード（`VoiceCallBar`、見た目は `@my/ui` の `MiniPlayer`）。
ルート（画面）ではないが、どの画面にも出る操作の場所なので、画面と同じ形で要件を書く（[§9](../09-app-shell.md#9-アプリの外枠)）。

### 1. 使う人と頻度

- 通話に参加したまま、タイムラインや通知などほかの画面を見ている利用者。通話のたびに何度も目に入る。
- 話者は、ほかの画面を見ながらマイクを入れたり切ったりする。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| ほかの画面から、通話のルームの画面に戻る | 1 |
| ほかの画面で、自分のマイクをオフにする（話者） | 1 |
| ほかの画面から、通話を退出する（ホストでない人） | 2 |
| ほかの画面にいる間に通話が終わった知らせを読み、閉じる | 1 |

退出は、「退出」と確認のダイアログの「退出」の 2 つ。ほかに人がいるルームのホストは、次のホストか終了を選ぶ 1 つが加わる。

### 3. 情報の優先順位とまとまり

カードは「参加中の通話」という名前の `region` で、見出しを持たない。始まり側から次を並べる。

1. 話者のアバターの重なり（話している人を先に、輪付き。飾り）。
2. ルーム名（ルームの画面へのリンク）と、その下の 1 行。誰かが話している間は「{name}さんが話しています」、それ以外は接続の状態のバッジ（`CallConnectionBadge`。ルームの画面の頭と同じもの）。
3. ブラウザが止めた音を出すボタンと、話者のマイク（`CallMicrophoneButton`。ルームの画面のドックと同じ形と名前）。
4. 区切りの線の後に、退出。マイクの隣に置かず、押し間違えで通話が終わらないようにする。
5. 知らせの行: ほかの人が起こした自分への変化（`ChangeNotice`）、失敗。

### 4. 主な操作と保存の仕方

- 主な操作は、ルーム名のリンク（ルームの画面に戻る）。話者にはマイクも。
- 保存は、すぐ効く操作だけ。ただし退出は取り消せないので、確認のダイアログ（「残る」と「退出」）を挟む。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| ルーム名 | 画面の遷移（ルームの画面）。そこではミニプレイヤーを出さない |
| マイクのボタン | その場。待つ間はボタンが脈打ち、オンとオフで形・色・名前が変わる。失敗は知らせの行に理由 |
| 退出 | 確認のダイアログ。「退出」でカードが消える。失敗はダイアログの中に理由 |
| 通話が外から終わった（ルームが終わった、退出させられた、接続が戻らなかった、別の端末で参加した） | その場。カードの代わりに、ルーム名と終わった理由の知らせが残り、閉じるまで出す |
| 再接続 | その場。1 行が「接続し直しています…」のバッジ（回る矢印）になり、知らせと読み上げ |

### 6. 入口と出口

- 入口: ルームの画面で参加したあと、ほかの画面へ移ったとき。
- 出口: ルームの画面（ルーム名）。退出するか通話が終わると消える。
