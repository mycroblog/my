## 自動審査の記録（`/moderation/hook-decisions`）

外部の審査（判定フック、ADR-0147）が何を止めたか、止めるはずだったか、確かめられなかったかを読み、誤った判定を取り消す画面の最初のページ。
判定の記録には投稿の本文は出ない。1 つの判定のすべての事実は[判定のページ](moderation-hook-decision.md)に、`local.status` に拒否された投稿への作者の異議は[異議申し立てのページ](moderation-hook-appeals.md)にある。モードは[サーバーの設定の連合のページ](admin-settings-federation.md)で変える。

### 1. 使う人と頻度

- 通報を受け持つモデレーター（`manage_reports`）。`observe` で動かしている間は、`enforce` に進める前に誤りがないかを読む。導入のころは毎日、その後は週に数回。
- 外部の審査の失敗の通知を受けたモデレーターが、何が失敗したかを確かめに来る。まれ。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| フックごとの判定の件数と待ち時間を知る | 1 |
| 止められたものの一覧を読む | 1 |
| フックで一覧を絞る | 2 |
| 判定を取り消す | 1 |
| 1 つの判定の理由コードとメモを読む | 1 |
| 異議申し立ての一覧へ移る | 1 |

手順は、画面を開いた後から数える。件数と一覧は開いた画面で読める（1 つと数える）。絞り込みは、絞り込みを開いて項目を選ぶ 2 つ。取り消しは行の「判定を取り消す」の 1 つ。判定の詳細は行の対象のリンクの 1 つ。異議申し立ては、`h1` の下のページのリンクの 1 つ。

### 3. 情報の優先順位とまとまり

`h1` の下に、画面のページの間の `LocalNav`（「判定」と「止められた投稿への異議申し立て」。このページは「判定」が今のページ）。

1. フックごとの状況（`h2`）: 5 つのフックの行。今のモード（プラグインがなければ「未設定」）と、過去 7 日のモードと結果ごとの件数・平均と最大の待ち時間。失敗の種類は判定と別の結果として並ぶ。
2. 判定の一覧（`h2`）: `allow` を除いた判定を新しい順に、ページングした `RecordTable` の 4 列で出す。対象（判定のページへのリンク。キーは `dir="ltr"` で、下にフック）、結果（結果とモード、取り消したものには「取り消し済み」）、判定した日時、操作（取り消し）。
   アカウント・待ち時間・理由コード・プラグインのメモ・取り消した日時・取り戻せる期限は判定のページに置く。ツールバーにフックの絞り込み（URL の `hook` に保つ）。

### 4. 主な操作と保存の仕方

- 主な操作は行の取り消し。取り消せるのは、`enforce` で効果の出た判定だけで、`local.status` の `reject` は異議申し立てで扱うのでボタンを出さない。
- 保存はすぐ保存で、取り消しは確かめない。判定の種類ごとの結果はサーバーが決める。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 判定を取り消す | その場。行が「取り消し済み」になり、ボタンがなくなる。結果を `StatusMessage`（`role="status"`）で読む。失敗はトースト（`danger`）で、行とフォーカスはそのまま |
| フックで絞る | その場。URL が変わり、一覧が最初のページから出直す |
| 一覧の次のページを読み込む | その場。前後のページへ移る。失敗は一覧の中のエラーと再試行 |
| 対象のリンクを押す | 判定のページへ遷移する |
| ページのリンクを押す | 異議申し立てのページへ遷移する |

### 6. 入口と出口

- 入口: モデレーションのメニュー（`manage_reports`）、外部の審査の失敗の通知のリンク、監査ログの `hook_decision` の項目のリンク、判定のページの戻るリンク。
- 出口: 判定のページ、異議申し立てのページ、読み終えたらメニューへ戻る。権限がなければ `AdminError` が足りない権限を示す。
