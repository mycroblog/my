## 自動審査の記録（`/moderation/hook-decisions`）

外部の審査（判定フック、ADR-0147）が何を止めたか、止めるはずだったか、確かめられなかったかを読み、誤った判定を取り消す画面。読むのは判定の記録だけで、投稿の本文は出ない。モードは[サーバーの設定](admin-settings.md)で変える。

### 1. 使う人と頻度

- 通報を受け持つモデレーター（`manage_reports`）。`observe` で動かしている間は、`enforce` に進める前に誤りがないかを読む。導入のころは毎日、その後は週に数回。
- 外部の審査の失敗の通知を受けたモデレーターが、何が失敗したかを確かめに来る。まれ。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| フックごとの判定の件数と待ち時間を知る | 1 |
| 止められたものの一覧を読む | 1 |
| フックで一覧を絞る | 2 |
| 判定を取り消す | 1 |

手順は、画面を開く 1 つ（件数と一覧はそこで読める）、絞り込みを開いて項目を選ぶ 2 つ、行の取り消しのボタンを押す 1 つ。

### 3. 情報の優先順位とまとまり

1. フックごとの状況: 5 つのフックの行。今のモード（プラグインがなければ「未設定」）と、過去 7 日のモードと結果ごとの件数・平均と最大の待ち時間。失敗の種類は判定と別の結果として並ぶ。
2. 判定の一覧: `allow` を除いた判定を新しい順に。対象のキー（`dir="ltr"`）、フック、結果、モード、日時、詳細（待ち時間・理由コード・プラグインのメモ（`dir="auto"`）・取り消した日時）。ツールバーにフックの絞り込み（URL の `hook` に保つ）。

### 4. 主な操作と保存の仕方

- 主な操作は行の取り消し。取り消せるのは、`enforce` で効果の出た判定だけで、`local.status` の `reject` は異議申し立てで扱うのでボタンを出さない。
- 保存はすぐ保存で、取り消しは確かめない。判定の種類ごとの結果はサーバーが決める。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 判定を取り消す | その場。行が取り消した日時を持ち、ボタンがなくなる。結果を `StatusMessage`（`role="status"`）で読む。失敗はトースト（`danger`）で、行とフォーカスはそのまま |
| フックで絞る | その場。URL が変わり、一覧が最初のページから出直す |
| 一覧の次のページを読み込む | その場。前後のページへ移る。失敗は一覧の中のエラーと再試行 |

### 6. 入口と出口

- 入口: モデレーションのメニュー（`manage_reports`）、外部の審査の失敗の通知のリンク、監査ログの `hook_decision` の項目のリンク。
- 出口: 読み終えたらメニューへ戻る。権限がなければ `AdminError` が足りない権限を示す。
