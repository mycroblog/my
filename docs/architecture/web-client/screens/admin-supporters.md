## サポーター: 課金（`/admin/supporters`）

`manage_supporters` を持つ管理者が、サポーターの課金を有効にし、チップを受け付け、決済の事業者の状態を確かめ、サポーターの一覧を誰に見せるかを決めるページ（FR-910〜FR-912、FR-918、ADR-0072、[ADR-0162](../../../adr/0162-one-time-tips.md) §17、[§14](../14-admin.md)）。
サポーターの画面の最初のページで、`h1` の下の `LocalNav`（「課金」「プラン」「加入」）から[プラン](admin-supporters-plans.md)と[加入](admin-supporters-subscriptions.md)のページへ行く。

### 1. 使う人と頻度

- 管理者。課金を始めるときと、サポーターの一覧の公開を変えるときに。決済の事業者の状態は月に数回。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 決済の事業者の照合が成功しているかを知る | 1 |
| サポーターの一覧をログインした人に公開する | 3 |
| チップを 3 つの金額で受け付ける | 4 |

どれもメニューで画面を開く 1 つから。公開は「ログインした人」を選ぶ 1 つと「保存する」の 1 つ（`manage_settings` のある人だけ）。
チップは「チップを受け付ける」の 1 つ、金額の欄に金額をカンマで区切って書く 1 つ、「チップを保存する」の 1 つ（通貨を変えるならもう 1 つ）。

### 3. 情報の優先順位とまとまり

1. 課金: 有効か、事業者、続いている加入の数、警告、「課金の機能を有効にする」のチェックボックスと、その下の「サポーターの一覧」（`h3`。一覧を見られる人。`manage_settings` のある人には選択肢、ほかの人には今の値の文）。最後に「保存する」と `FormActionBar`。
2. チップ: チップが何か（利用者が運営に 1 回だけ払う見返りのないもの。プランがなくても使える）、いま払えるか、最後の変更、警告（事業者が 1 回の支払いを受け付けない、課金の機能が無効で払えない、この 1 時間でサーバー全体の開始の上限に達した = カードの試し打ちかもしれない）。
   その下に、チャージバックごとの dispute の手数料（日本の Stripe で 1 件 ¥1,500）、返金とチャージバックが収入から差し引かれること（返金は事業者のダッシュボードで行う）、
   公開する収入の合計がチップの額も件数も出さないこと（小さなサーバーでは内訳から誰が払ったかが分かるため。個々のチップは費用の画面の「支払いと返金」だけ）、事業者の審査と規約を運営者が確かめることを並べ、運営者向けの文書（新しいタブ）へリンクする。
   最後に「チップを受け付ける」のチェックボックス（事業者が 1 回の支払いを受け付けなければ無効）、有効にしている間は通貨（事業者が受け付ける通貨の `RadioGroup`）と金額の欄（1〜6 個をカンマで区切る。説明に通貨の下限と上限）、「チップを保存する」と `FormActionBar`。
   寄付・控除と読める言葉を使わない。
3. 決済の事業者: 設定の事業者があるときだけ。状態・最後の照合と「今すぐ照合する」。

### 4. 主な操作と保存の仕方

- 主な操作は「保存する」の 1 つ。課金の有効・無効とサポーターの一覧の公開は 1 つのフォームでまとめて保存し、変えたものだけを送る。
- チップは別のフォームで、「チップを保存する」でまとめて保存する。金額は小さい順に並べ、重なりを除いて送る。何も変えずに保存すると「変更はありません」。
- 「今すぐ照合する」は保存ではなく、決済の事業者に照合を頼む補助の操作。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 課金とサポーターの一覧を保存する | その場。フォームの `FormActionBar`。拒否の理由も同じ場所 |
| チップを保存する | その場。チップのフォームの `FormActionBar`。金額や通貨への拒否（数でない・個数・範囲）はその欄の下 |
| 今すぐ照合する | その場。区画の中 |

### 6. 入口と出口

- 入口: 管理のモードのメニューの「サポーター」。
- 出口: `LocalNav` のプランと加入のページ、課金の警告から規約とポリシーの画面の特定商取引法に基づく表記などのページ、チップの運営者向けの文書（新しいタブ）、メニューのほかの画面。
