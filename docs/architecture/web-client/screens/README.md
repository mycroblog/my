# 画面の要件（L1）

画面（ルート）ごとに 1 ファイル `<slug>.md` を置く（[ADR-0081](../../../adr/0081-generated-files-policy.md)）。このディレクトリが画面の一覧で、別の一覧は持たない。
[ADR-0110 §4](../../../adr/0110-web-experience-principles.md) の L1 で、[体験の原則](../21-experience-principles.md)を画面に当てはめた短いテキストにする。
書式は Shape Up の Breadboarding（場所・操作・つながり）と OOUX の ORCA（Objects・Relationships・CTAs・Attributes）を下敷きにする。

- UI を変える issue は、その画面のこのファイルがなければ着手しない。画面を変える PR は、挙動が変わるならこのファイルも同じ PR で直す。
- 画面を足すときに触るのは、その画面のファイル（と機能のコード）だけにする。L4 の課題テスト（[ADR-0015](../../../adr/0015-testing-strategy.md)）が要るものは、ファイルの先頭のフロントマター（下）に書く。
- 現在の状態だけを書く（[ADR-0000](../../../adr/0000-record-architecture-decisions.md)）。

## 雛形

```markdown
---
start: "/path"
persona: "yuki"
paths: ["app/web/src/features/<機能>/**"]
budget: {"controls": N, "helpers": N, "words": N}
---

## <画面の名前>（`/path`）

### 1. 使う人と頻度
誰が、何のために、どのくらいの頻度で使うか。

### 2. 作業
| 作業 | 最短の手順の数 |
| --- | --- |
| （L4 の課題になる。1 行 1 作業） | N |

### 3. 情報の優先順位とまとまり
区画の見出し（`h2`）を、優先順位の順に並べる。項目は `h2` の文言（日本語）で始め、データから来る見出しは `<お知らせの題名>` のように `<` で始める。ストーリーのテストが実装の `h2` の順と比べる。
入るものは、見せる情報と操作。説明の文は入るものに数えない（形・状態・既定値で伝わらないことだけを、`budget` の `helpers` の内で足す）。
1. <`h2` の文言>: 見せる情報と操作

### 4. 主な操作と保存の仕方
主な操作は 1 つ。保存は、すぐ保存か、まとめて保存かのどちらか 1 つ。

### 5. 操作ごとの結果の出し方
| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |

### 6. 入口と出口
どこから来て、終えたらどこへ行くか。

### 7. 載せないもの
この画面にあえて出さない情報・操作・説明と、それがある場所（別の画面、ドキュメント）か、出さない理由。
```

## フロントマター

L4 の課題テスト（`scripts/task.sh web:l4`、`app/web/l4/screens.ts` が読む）がデモサーバー（`app/web/demo/scenario.ts` のシナリオ）で画面の作業を始めるための値。
ファイルの 1 行目の `---` から次の `---` までに、1 行に 1 つ `<キー>: <JSON の値>` で書く（YAML としても読める）。
知らないキーや形の違う値は L4 を失敗させ、`app/web/l4/screens.test.ts` がすべての画面のファイルを確かめる。

| キー | 必須 | 値 |
| --- | --- | --- |
| `start` | はい | エージェントが始めるパス。「入口」に合わせる |
| `persona` | はい | ログインしておくシナリオの人の username。ログインしない画面は `null` |
| `paths` | はい | 画面のコードのパターン（`*` は 1 階層、`**` は何階層でも）。`SINCE` は、このファイルかこれらが変わった画面を測る |
| `starts` | | `start` 以外から始める作業: `{"<作業>": "<パス>"}` |
| `personas` | | `persona` 以外の人として（`null` ならログインせずに）始める作業: `{"<作業>": "<username>"}` |
| `seed` | | 作業の前に 1 回だけシナリオを変える手順: `{"my": [<bin/my の引数>]}` か `{"api": "<username>", "method": "PUT", "path": "/preferences/...", "body": {...}}` の並び |
| `mail` | | メールを読む作業と、Mailpit で受信箱を読む人: `{"<作業>": "<username>"}` |
| `push` | | Web Push をオンにする作業と、作業の後にログインした人へ返信する人: `{"<作業>": "<username>"}`。ブラウザは fake のプッシュサービスで購読し、成否はハーネスが判定する（サーバーの購読と、返信の通知を fake が受け取って復号できたこと。`app/web/l4/push.ts`） |
| `notes` | | 作業の注記（英語）。L4 で測れないことなど: `{"<作業>": "<注記>"}`。結果に載る |
| `unavailable` | | デモサーバーで用意できない作業と、その理由（英語）: `{"<作業>": "<理由>"}`。測らずに記録する |
| `budget` | | 画面の予算（下）: `{"controls": N, "helpers": N, "words": N}`。ほかの画面のルートの一部や状態（横のメニュー、始めたばかりの人）は `null` で、そのルートの画面と一緒に測る |

`<作業>` は「2. 作業」の表の行の文字どおりに書く。
始めたばかりの人（誰もフォローせず、投稿もプロフィールもない人）は `kai`。アカウントを作る作業は、ログインせずに始め、シナリオが作らない人 `mio` のメールアドレスで登録して、
確認のメールを `mail` の `mio` の受信箱で読む（`app/web/demo/scenario.ts` の `applicant`）。
1 つの画面の作業は、表の順に同じサーバーで続けて行う。シナリオを変える作業（フォローなど）は、その変化で始めの状態が変わる作業より後の行に置く。

## 予算

[体験の原則](../21-experience-principles.md) P3 の「1 つの区画の文字と操作の量の上限」を、画面ごとの数にしたもの。
ストーリーのテスト（`scripts/task.sh web:story-test`）が、画面のストーリー（英語、既定の幅）の 1 つずつを測り、超えたら失敗する。
測り方は `app/web/src/test/screenMeasure.ts`、照らし方は `app/web/l4/budget.ts` にある。

| 値 | 数えるもの |
| --- | --- |
| `controls` | 操作（ボタン、リンク、入力。ラジオのグループは 1 つ） |
| `helpers` | 説明の文（`Hint`、`description`、`Callout`） |
| `words` | 読める語の数（英語。日時は除く） |

- 数えるのは `main` と開いているダイアログ。一覧・表・フィードは、いちばん大きい 1 行ぶんとして数える。
- ストーリーは、最初の見出しのルート（バッククォートの中のパス）がストーリーの開くパスに合う画面のものになる。ルートは画面ごとに別にする。
- 予算を上げるのは、画面のファイルのフロントマターの差分で、オーナーがレビューする。上げる前に、画面から減らすかまとめる。
- 予算のない画面には `scripts/task.sh web:budget-init` が今の値を書く。
- 1 つの区画の操作は 7 個まで、`h2` の順は「3.」の順（[ADR-0110 §6](../../../adr/0110-web-experience-principles.md)）。
  今それを満たさないストーリーと、「7. 載せないもの」のない画面は `app/web/l4/screenBaseline.json` に並び、この一覧は減るだけにする。
