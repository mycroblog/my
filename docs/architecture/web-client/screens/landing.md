## ランディングページ（`/`、ログインしていない人）

ログインしていない人がルートのアドレスで見る、このサーバーの顔と入口。ソフトウェア（my）ではなく、このサーバーを紹介する。
誌面のように文字の大きさと余白で読ませる見た目にする（`@my/ui` の `Masthead` と `Section` の `chapter`。枠や面を重ねない）。区画の中身はページの幅いっぱいに置く。
上にマストヘッドを置き、その下を
「どんな場所か・どんな約束か・どう参加するか」の 3 つの区画と、区画へのリンクと今読んでいる区画を示す進み具合の線にする。
区画は順に読める 1 枚のページで、手順を 1 つずつ進めるウィザードにしない。動かしているソフトウェアのことは、フッターの「my で動いています」とソースコードへのリンクだけにする。

### 1. 使う人と頻度

1. **戻ってきた利用者**（いちばん多い）: すぐにログインする。来るたびに。ページの上端のログインのボタンだけを使い、スクロールしない。
2. **参加を考えている人**: このサーバーが自分に合うか（誰に連絡すればよいか・何が投稿されているか・どんな約束か）を確かめ、サーバーが許す方式（自由・承認・招待）で参加し、押した後に何が起きるかを知る。1 回から数回。
3. **ほかのサーバー（Mastodon・Misskey など）にアカウントのある人**: 見て回り、自分のサーバーからこのサーバーの人をフォローする。登録へ押し出さない。たまに。
4. **リンクのプレビューとクローラー**: サーバーの名前・要約・画像。画面ではなく、サーバーが返す外枠の HTML が答える（[§8](../08-server-rendered-pages.md)）。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 戻ってきた利用者がログインの画面へ進む | 1 |
| 誰に連絡すればよいかを確かめる | 1 |
| ルールを読む | 1 |
| 参加の方式と、押した後に起きることを読んで、登録の画面へ進む | 2 |
| ほかのサーバーのアカウントからフォローする手順を読む | 1 |
| ローカルタイムラインを見て回る | 2 |
| インスタンスの情報ページ・規約・ポリシー・ソースコードのどれかへ移る | 1 |
| パスワードを忘れた利用者が、再設定のメールのリンクから新しいパスワードを設定する | 7 |

- ログインは、マストヘッドの「ログイン」を押す 1 つ。
- 連絡先とルールは、進み具合の線の ①・② を押す 1 つ（スクロールでも読める）。
- 登録は、マストヘッドの「参加する」で ③ へ移る 1 つと、③ の方式の操作（「アカウントを作る」など）を押す 1 つ。マストヘッドから登録の画面へ直接行かず、ルールの区画を通る。
- ほかのサーバーからのフォローは、マストヘッドの「ほかのサーバーのアカウントでフォローする」で ③ のその手順へ移る 1 つ。
- ローカルタイムラインは、① へ移る 1 つと、① の「ローカルタイムラインを見る」を押す 1 つ。
- パスワードの再設定は、マストヘッドの「ログイン」・サーバーのログインの画面の「パスワードを忘れた」を押す 2 つ、メールアドレスを入れる 1 つと送る 1 つ、
  メールを開いてリンクを押す 1 つ（メールのアプリの中の手数は数えない）、新しいパスワードを入れる 1 つと保存する 1 つ。

### 3. 情報の優先順位とまとまり

見出し（`h2`）の前に、マストヘッドと進み具合の線を置く。

- **マストヘッド**（`Masthead`）: 上下に広い余白を取り、上から順に、サーバーの印（管理者が設定したアイコン、なければ my のワードマーク。装飾）とドメインの 1 行、
  名前（`h1`。表示用の大きさのセリフ体）、要約（`short_description`。本文より大きいリード文）、数の 1 行（利用者の数・動き始めた年月は `GET /instance/overview`、連絡先のアカウントの名前（① のそれへのリンク）は `GET /instance` の `contact`。中黒で区切る）、
  操作の行（「参加する」・「ログイン」・「ほかのサーバーのアカウントでフォローする」（③ のその手順へのリンク））を置く。サーバーの画像（`thumbnail`）があれば操作の下に出し、なければ何も置かない。
- **進み具合の線**（`SectionProgress`）: 3 つの区画への番号（`01`）付きのリンク。それぞれの上に細い線を引き、見えている区画を `aria-current="location"` で示し、そこまでの線をアクセントの色にする。
  区画をスクロールする間は上端のバーの下に貼り付き（バーとそのメニューより下に重なる）、どこを読んでいるかを示し続ける。
  リンクで移った見出しは線の下に止まる。`sm` 未満では番号だけを見せ（区画の名前はリンクの名前に残る）、背の低い画面では貼り付かない。

区画は次の順にする。見出しは、その区画が答える問いにする。区画（`Section` の `chapter`）は番号とセリフ体の見出しを持ち、上に細い線を引き（進み具合の線の直後の ① は除く）、区画の間を大きく空ける。

1. **どんな場所？**: 説明（`description`。空行で段落に分ける）、連絡先（「連絡先」。サーバーの設定 `contact_account` のアカウントのアバター・名前・ハンドル・ロールのバッジ、プロフィールへのリンク）、
   投稿の様子（「投稿の様子」。この 7 日の公開の投稿の数と日ごとの推移の `Sparkline`、最近の投稿 3 件、ローカルタイムラインへのリンク）。
   公開の投稿が 1 件もない静かなサーバーや新しいサーバーでは、空の一覧を出さず、説明と連絡先だけにする。
   管理者が数（`public_counts`）を隠したとき、連絡先のアカウントを設定していないときは、その部分を出さない。
2. **どんな約束？**: ルール（番号付き、本文とその補足）。ルールがなければそのことを 1 行で出す。
3. **参加するには？**: 「このサーバーのアカウントで」（`h3`）の下に、サーバーの登録の方式の手順（番号付きの 3 つ）と、最後にその方式の操作。
   - 自由（`open`）: 名前・メールアドレス・パスワードを入れる → メールアドレスを確かめる（メールを送らないサーバーではモデレーターが確かめる） → 使い始める。操作は「アカウントを作る」。
   - 承認（`approval`）: 参加したい理由を添えて申し込む → モデレーターが確かめる → 承認されるとメールが届く（メールを送らないサーバーでは、ログインすると結果が分かる）。操作は「参加を申し込む」。
   - 招待（`invite`）: このサーバーの人から招待のリンクをもらう → リンクを開いてアカウントを作る → 使い始める。操作は「招待でアカウントを作る」。
   - 受け付けていない（`closed`）: 手順を出さず、新しいアカウントを受け付けていないことを出す。
   - その下（広い画面では横）に「ほかのサーバーのアカウントで」（`h3`）: 見て回って、フォローしたい人を見つける → その人のハンドル（`@name@domain`）を写す → 自分のサーバーの検索に入れてフォローする。

最後にフッター（`footer`。サインインしていないときのどの画面とも同じ外枠のもので、`main` の外の `contentinfo`、[§9](../09-app-shell.md)）: インスタンスの情報ページ（`/about`）・規約とポリシー・「my で動いています」（ソースコードへのリンク。AGPL-3.0 の 13 条）。
3 列目（「このサーバーについて」）は出さない。

管理者が書いた文（名前・要約・説明・ルール・ロールのバッジ）は、どのロケールでも同じ 1 つの値なので `dir="auto"` と `lang=""` で出す。

### 4. 主な操作と保存の仕方

- 主な操作は「参加する」（マストヘッドの、塗ったボタン）。サーバーが新しいアカウントを受け付けていない（`closed`）か、まだ方式が分からないときは「ログイン」が主な操作になる。
- 保存するものはない。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| ログイン | 画面の遷移（サーバーのログインの画面。押した直後にボタンが処理中になる） |
| 参加する・ほかのサーバーのアカウントでフォローする | その場。③（かその手順の見出し）へスクロールし、見出しにフォーカスを移す |
| 進み具合の線のリンク | その場。その区画の見出しへスクロールし（`prefers-reduced-motion` でなければ滑らかに）、見出しにフォーカスを移し、線の印を移す |
| ③ の方式の操作 | 画面の遷移（サーバーが描く登録の画面 `/auth/sign_up`） |
| ローカルタイムラインを見る | 画面の遷移（`/local`） |
| 最近の投稿・数の読み込みの失敗 | その場。投稿は ① の中にもう一度試すボタンと出す。数は出さないだけで、ページの残りはそのまま使える |

### 6. 入口と出口

- 入口: ルートのアドレスを開く（ブックマーク・ほかのサーバーのリンク・検索）、外枠のサーバーの名前のリンク、見せるものがない画面の「トップページへ」。
  ログインしている利用者は、ここに来るとホームのタイムライン（`/home`）へ移る。
- 出口: ログインの画面（ログインの後は `/`、つまりホームのタイムライン）、登録の画面、ローカルタイムライン、連絡先のアカウントのプロフィール、インスタンスの情報ページ、規約とポリシー、ソースコード。
