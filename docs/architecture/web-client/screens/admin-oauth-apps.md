## OAuth のアプリ（`/admin/oauth-apps`）

`manage_oauth_apps` を持つ管理者が、このサーバーにログインできるアプリ（OAuth のクライアント）を一覧し、アプリを無効にする、OAuth のアプリの画面の最初のページ（ADR-0090 §1、[§14](../14-admin.md)）。
見出しの下のページの切り替え（`LocalNav`）で「アプリ」と「拒否したホスト」（[拒否したホストのページ](admin-oauth-apps-hosts.md)）を行き来する。

### 1. 使う人と頻度

- 管理者。悪質なアプリを見つけたとき、どんなアプリが使われているかを見るとき。月に 1 回より少ない。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 登録の経路でアプリを絞り込む | 3 |
| 利用者が登録したアプリを無効にする | 3 |

どちらもメニューで画面を開く 1 つから。絞り込みは、登録の経路の `Select` を開く 1 つと経路を選ぶ 1 つ。
無効にするのは、行の「無効にする」を押す 1 つと、確認のダイアログの「無効にする」を押す 1 つ。

### 3. 情報の優先順位とまとまり

見出しの下にページの切り替え（「アプリ」が今のページ）、その下に区画が 1 つ。

1. アプリ: 説明、登録の経路の `Select`、変更の結果、アプリの表（新しい順。アプリ（名前と無効の印、クライアント ID・ウェブサイト・登録した人・付与できる上限）・登録の経路（秘密を持つか）・登録日時・操作の 4 列）、前へ / 次へ。
   操作は「無効にする」か「有効にする」（このサーバー自身のアプリは「無効にできません」）と、メタデータ文書で登録したアプリの「ホストを拒否」。

### 4. 主な操作と保存の仕方

- このページの主な操作はない（一覧を見て、行ごとに操作する）。
- 無効にするのはトークンをすぐに失効させるので確認のダイアログ（`ConfirmDialog`）を経る。有効にするのはすぐ保存。ホストの拒否も確認のダイアログを経る。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 無効にする・有効にする・ホストを拒否 | その場。行の印とボタンが変わり、表の上に結果。失敗も表の上（ダイアログの中の失敗はダイアログ） |
| 登録の経路を選ぶ | その場。表を最初のページから読み直す（URL が変わる） |

### 6. 入口と出口

- 入口: 管理のモードのメニューの「OAuth のアプリ」。拒否したホストのページの切り替え。監査ログのアプリの行。
- 出口: ページの切り替えの「拒否したホスト」。メニューのほかの画面。
