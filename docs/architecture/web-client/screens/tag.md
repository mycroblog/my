## ハッシュタグ（`/tags/{tag}`）

1 つのハッシュタグの付いた投稿を新しい順に読み、そのハッシュタグをフォローするかを決める画面（FR-203、[ADR-0013](../../../adr/0013-timeline-strategy.md) §24）。
形は[ホーム](home.md)と同じ投稿のカードの一覧。フォローすると、作者をフォローしていなくても、そのタグの `public` と `local` の投稿がホームに入る。
ログインしていなくても読め、そのときはフォローのボタンを出さない。

### 1. 使う人と頻度

- ログインした利用者が、投稿の本文のハッシュタグ、ホームの「フォロー中のハッシュタグ」の印、プロフィールの注目のハッシュタグ、検索から来る。話題を追うか決める。週に数回。
- ログインしていない人が、共有されたリンクや投稿のハッシュタグから来て読む。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| ハッシュタグをフォローする | 1 |
| ハッシュタグのフォローをやめる | 1 |

フォローは、見出しの下の「フォロー」を押す 1 つ。やめるのは、同じボタン（「フォロー中」）を押す 1 つ。すぐ元に戻せるので、確かめのダイアログを出さない。

### 3. 情報の優先順位とまとまり

画面の上に戻るボタンを置く（`staticData.back`）。ハッシュタグはナビゲーションの項目ではないので、`h1`（「#散歩」）は常に見せる。

1. 見出しの行: ハッシュタグ（`h1`。利用者の文字なので `dir="auto"`）と、その下にフォローのボタン（ログインしているときだけ）。ボタンの下に、フォローするとホームに入ることを 1 文で添える。
2. そのハッシュタグの付いた音声チャットのルーム（開いているものがあるときだけ。`h2`）。
3. 投稿の一覧（`feed`）: ホームと同じ投稿のカード。
4. 一覧の終わり: 続きの読み込み、または失敗（`RegionError`）。

`xl` 以上の右帯には、ログインしている間、お知らせとサーバーについての間に最新の通知を置く（[アプリの外枠](../09-app-shell.md)）。

### 4. 主な操作と保存の仕方

- 主な操作は、投稿を読むこと。ログインしている人には、フォローのボタン（`@my/ui` の `FollowButton`）を見出しの下に 1 つ置く。
  フォローしていないときは塗った主な見た目、フォロー中は枠線の静かな見た目（チェックのアイコンと「フォロー中」）にする（[プロフィール](profile.md)と同じ形）。
- フォローしているかを読み込んでいる間は、ボタンと同じ大きさの場所を取って待つ。
- 保存は、すぐ保存（押すとすぐ送る）。
- フォローしたハッシュタグは 100 個まで。超えるフォローは、サーバーの答え（`/api/v1/problems/too-many-followed-tags`）をトーストで言い、ボタンを元に戻す。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| フォローする | その場。ボタンが処理中になり、「フォロー中」の静かな見た目に変わる。フォーカスはボタンに残り、「#散歩 をフォローしました。」を読み上げる（`useNotice` の `inPlace`）。ホームは次に開いたとき（表示中なら今）に読み直し、そのタグの投稿が再読み込みなしで入る。失敗はトースト |
| フォローをやめる | その場。ボタンが「フォロー」に戻り、「#散歩 のフォローをやめました。」を読み上げる。失敗はトースト |
| 続きの読み込みが失敗する | その場。一覧の終わりに `RegionError` |

### 6. 入口と出口

- 入口: 投稿の本文のハッシュタグ、ホームの投稿の「フォロー中のハッシュタグ」の印、プロフィールの注目のハッシュタグ（`/@{acct}/tagged/{tag}` からの置き換えの遷移も含む）、設定のフォローしたハッシュタグの一覧、検索。
- 出口: 投稿の詳細、プロフィール（名前とアバター）、戻るボタン。フォローした結果はホームで見える。
