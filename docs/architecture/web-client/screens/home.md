## ホームタイムライン（`/home`）

ログインした利用者が、自分とフォローしているアカウントの投稿を新しい順に読む画面（FR-201）。ログインした利用者がアプリを開くと最初に出る。
同じ形のタイムラインは、ほかに[ローカル](local.md)と[連合](public.md)がある。3 つは同じ投稿のカードの一覧なので、今どれにいるかを形で示す。

### 1. 使う人と頻度

ログインしたすべての利用者。毎日、何度も開く。新しい投稿を上から読み、気になった投稿に返信・ブースト・お気に入りをする。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 待っている新しい投稿を表示して、いちばん新しい投稿を読む | 1 |
| タイムラインの投稿にお気に入りを付ける | 1 |
| タイムラインの投稿への返信を読む | 1 |
| タイムラインの投稿に返信する | 3 |
| 新しい投稿を書いて送る | 3 |
| ホームからローカルタイムラインへ移る | 1 |

返信を読むのは、投稿の時刻のリンクを押す 1 つ。返信するのは、返信のボタン・本文の入力・送信の 3 つ。
新しい投稿は、投稿のボタン・本文の入力・送信の 3 つ。電話でローカルタイムラインがタブバーにないときは、メニューを開く 1 つが増える。

### 3. 情報の優先順位とまとまり

画面の `h1`（「ホーム」）は、`md` 以上では見た目から隠す（レールが今いる項目を示す）。`md` 未満では見せる: タブバーには項目の一部しか入らず、
今いるタイムラインがメニューの中にあるとタブバーの印が出ないからである。区画の `h2` は持たず、上から次の順に並べる。

1. サーバーからのお知らせ（あるときだけ）
2. 新しい投稿のボタン（待っている投稿があるときだけ、一覧の上に浮かぶ）
3. 投稿の一覧（`feed`）: 投稿のカード。カードの文脈の行（ブースト・固定）は、種類のアイコンと文で示す
4. 一覧の終わり: 続きの読み込み、または続きの読み込みの失敗（`RegionError`）

今いる場所は、ナビゲーションの今いる項目の形で示す: タブバーではアイコンの後ろの塗った丸い形、レールでは行全体の塗り。色だけで示さない（WCAG 1.4.1）。

### 4. 主な操作と保存の仕方

- 主な操作は、投稿を読むこと。書く入口は、外枠の投稿のボタン 1 つ（`md` 未満では画面の端に浮かぶ）。
- 投稿への操作（お気に入り・ブースト・ブックマーク）は、押すとすぐ効く。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 新しい投稿のボタンを押す | その場。投稿が一覧の上に入り、フォーカスは画面の見出しへ移る |
| 投稿にお気に入り・ブースト・ブックマークを付ける | その場。アイコンの形と件数が変わる。失敗はトースト |
| 返信を読む | 画面の遷移（投稿の詳細） |
| 続きの読み込みが失敗する | その場。一覧の終わりに `RegionError`（何が起きたか・理由・もう一度試す） |

### 6. 入口と出口

- 入口: ログインした後の最初の画面。ナビゲーションの「ホーム」。ログインしていないと、ログインの画面へ移り、終えるとここに戻る。
  サーバーに届かないとき（オフライン）は、このブラウザに残した投稿を時刻付きで出す。
- 出口: 投稿の詳細（返信を読む）、プロフィール（名前とアバター）、投稿のフォーム（返信・新しい投稿）。投稿がないときは、空の状態からローカルタイムラインへ導く。
