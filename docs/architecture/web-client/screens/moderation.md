## モデレーションのトップ（`/moderation`）

モデレーターが、いま何が待っていて、どれを先に処理するかを知る画面（ADR-0058、FR-712、[§14](../14-admin.md)）。
管理のモードのメニューの複製ではなく、要約を置く。各画面へはメニューから行く。保存する操作はない。

### 1. 使う人と頻度

- 通報を受け持つモデレーター（`manage_reports`）。モードに入るたびに、通報の待ち行列の状態と、先に処理する通報を見る。1 日に数回。
- 登録の審査と異議申し立てを受け持つモデレーター（`manage_accounts`）。待っている件数を見て、その画面へ行く。1 日に数回。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 待っている通報・登録・異議申し立ての件数を知る | 1 |
| いちばん古い通報がどれだけ待っているかを知る | 1 |
| 先に処理する通報を開く | 2 |
| 通報の待ち行列を開く | 2 |
| 承認待ちの登録の画面を開く | 2 |

手順は、ナビゲーションの「モデレーション」を開く 1 つ（件数はそこで読める）、タイルか通報の行のリンクを押す 1 つ。

### 3. 情報の優先順位とまとまり

1. 待っているもの: 閲覧者のロールが数えられる待ち行列ごとの `StatTile`（未解決の通報・承認待ちの登録・審査待ちの異議申し立て）。
   タイル全体がその画面へのリンクで、1 件以上待っていれば「対応待ち」の印を持つ。件数を読めなかったときは、その旨とメニューへの案内を出す。
   未解決の通報のタイルの隣に、いちばん古い未解決の通報が待った長さ（分・時間・日。1 日で注意、3 日で危険の印。なければ「待ちなし」）のタイルを置き、古い順の通報の一覧へリンクする。
2. 先に対応する通報（`manage_reports`）: 通報の待ち行列全体から、法的な通報を古い順に先に、次に未解決の通報を古い順に、重ねずに 5 件まで。
   各行は通報へのリンク（「@相手 の通報」）と、区分の `StatusBadge`（違法は危険の色、ルール違反は注意の色）、待ち時間の `AgeBadge`（1 日で注意、3 日で危険）、担当（あなた・ほかの人・未担当）の印。
   その下に「通報の一覧を開く」のリンク。未解決の通報がなければ空の状態を出す。

使える画面が 1 つもないロールには、2 つの区画の代わりに理由を `EmptyState` で出す。

### 4. 主な操作と保存の仕方

- 主な操作は、先に対応する通報の最初の行を開くこと。待っているもののタイルは、それぞれの待ち行列への入口である。
- 保存する操作はない。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| タイルを押す | 画面の遷移。その待ち行列の画面 |
| 通報の行を押す | 画面の遷移。通報の詳細 |
| 新しい通報・登録・異議申し立ての通知が届く | その場。件数を読み直し、タイルの数と印が変わる |

### 6. 入口と出口

- 入口: アプリのナビゲーションの「モデレーション」（待っている件数付き）、管理のモードのメニューの「概要」。
- 出口: 各待ち行列の画面と通報の詳細。メニューのほかの画面。「アプリに戻る」。
