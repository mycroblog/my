## ジョブ（`/admin/jobs/{id}`）

`manage_jobs` を持つ管理者が、1 つのジョブのすべての事実・最後のエラー・ペイロード・試行の履歴を読み、失敗したジョブを再実行するページ（ADR-0004、[§14](../14-admin.md)）。
`GET /admin/jobs/{id}` で未完了のジョブも失敗したジョブも開ける。完了したジョブはキューにもう無いので、見つからない。

### 1. 使う人と頻度

- 管理者。[ジョブの一覧](admin-jobs-list.md)の型のリンクから来る。失敗の理由を調べるときに。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 失敗したジョブが失敗した理由を読む | 2 |
| 失敗したジョブの試行の履歴を読む | 2 |
| 失敗したジョブを、理由を読んでから再実行する | 3 |

手順は、管理のトップのタイル「失敗したジョブ」で一覧を開く 1 つ、ジョブの型のリンクを押す 1 つ、「再実行」を押す 1 つ。理由と試行の履歴はページを開いただけで読める（開閉はない）。

### 3. 情報の優先順位とまとまり

1. 状態（`h2` の区画）: 状態・失敗の日時か予定・試行回数と、失敗したジョブの「再実行」。
2. 詳細: 型・作成の日時・実行中のワーカーとリースの期限・冪等キーと順序キー・最後のエラー。型・キー・ワーカーは `dir="ltr"`。
3. ペイロード（JSON の文字列のまま、`CodeBlock`、`dir="ltr"`）。
4. 試行の履歴: 成功しなかった試行を新しい順に、試行の番号と結果の見出し（`h3`）・開始と終了の日時・ワーカー・エラー。ページと一緒に読み、続きは「さらに表示」（詳細の中の短い証拠の一覧）。読み込み中は `Spinner`、失敗は `RegionError`、記録がなければ成功は記録しないことを書いた `EmptyState`。

### 4. 主な操作と保存の仕方

- 主な操作は、失敗したジョブの「再実行」。確かめずにすぐ送る。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 再実行 | その場。ジョブを読み直して待ちのジョブとして出し、ボタンが消えるので、フォーカスは「状態」の見出しへ。結果は読み上げ、失敗はトースト |
| 試行の履歴の「さらに表示」 | その場。続きの記録を足す |

### 6. 入口と出口

- 入口: ジョブの一覧の型のリンク、URL を直接。
- 出口: 「ジョブの一覧に戻る」、メニューのほかの画面。
