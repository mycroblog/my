## イベントの一覧（`/events`）

見られるこれからのイベントを開始の近い順に並べ、イベントの画面と、イベントを作る入口を置く画面（ADR-0161 §9）。
イベントはローカルの利用者のもので、ログインが要る。フォローしている人への「新しいイベント」の通知はないので、この一覧・3 列目の「近日のイベント」・主催者のプロフィールが知らせる場所になる。

### 1. 使う人と頻度

- ログインしている利用者。週末や今週に何があるかを見て、行きたいイベントを開く。週に数回。
- イベントを作る利用者。「イベントを作成」から作る。月に数回。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| ナビゲーションから来て、これからのイベントの 1 つを開く | 2 |
| イベントを作り始める | 2 |

手順は、ナビゲーションの「イベント」を押す 1 つと、カードの題名（見出しのリンク）か「イベントを作成」を押す 1 つ。

### 3. 情報の優先順位とまとまり

区画の見出し（`h2`）は置かず、ページの見出し（`h1`「イベント」）の下に次を並べる。

1. 「イベントを作成」（プラスのアイコン付きの主なボタン。イベントを作れない利用者には、エディタの送信の後にサーバーの理由を出す。インスタンスの `event_creators` はクライアントに出ないため）。
2. これからのイベントのカードの一覧（「これからのイベント」という名前の `ul`）。カードには上から次を出す。
   - 状態のバッジ（アイコンと文字。日時は未定・自分の答え（参加・たぶん参加）・招待されています）。中止したイベントは一覧に出ない。
   - 題名（`h2`、イベントの画面へのリンク。主催者の文なので `dir="auto"`）。
   - 日時: 閲覧者のタイムゾーンの曜日・日付・開始と終了の時刻。イベントのタイムゾーンが閲覧者と違えば、その下にイベントのタイムゾーンの曜日と時刻とタイムゾーンの地名（「Sat 9:00 – 11:00 PM (Tokyo)」）。日程の調整中のイベントは「日時は未定です」と言う。
   - 「主催: {名前}」（名前は主催者のプロフィールへのリンク）。
   - 参加者の数（定員があれば「3 / 20 人が参加」）。
3. イベントがないときは、カレンダーのアイコンを添えた空の状態（`EmptyState`）。続きがあれば「ほかのイベントを表示」。

### 4. 主な操作と保存の仕方

- 主な操作は、イベントの画面に移ること（カードの見出しのリンク）。出欠はイベントの画面で答える。
- この画面は何も保存しない。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| イベントの題名を押す | 画面の遷移（イベントの画面） |
| イベントを作成 | 画面の遷移（イベントのエディタ） |
| ほかのイベントを表示 | その場。ボタンが待ちを示し、続きを一覧の後に足す。失敗は一覧の後に理由 |

### 6. 入口と出口

- 入口: ナビゲーションの「イベント」（レールとメニューのシート。タブバーには置かない）。3 列目の「近日のイベント」の「すべてのイベントを見る」。見つからないイベントの画面の「すべてのイベントを見る」。
- 出口: イベントの画面、主催者のプロフィール、イベントのエディタ。

3 列目（`xl` から）の「近日のイベント」は、一覧の先頭の 3 件を同じカードの形（区画がカードなので中は平らに）で出し、終わりに「すべてのイベントを見る」を置く。一覧の画面では重なるので出さない。
プロフィールでは、そのローカルのアカウントが主催するこれからのイベント（見られるもの、3 件まで）を「イベント」の区画に同じカードで出す。リモートのアカウントにはない。
