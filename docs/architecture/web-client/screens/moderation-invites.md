## 招待の一覧（`/moderation/invites`）

`manage_invites` を持つ人が、スタッフとメンバーが作った招待（FR-001、ADR-0106 §18）を新しい順に読み、使える招待のリンクをコピーし、失効させる画面（[§14](../14-admin.md)）。
招待を作るのは[新しい招待](moderation-invite-new.md)で行う。招待の API に 1 件を返す操作はないので、招待の詳細のページはない。

### 1. 使う人と頻度

- 管理者か、`manage_invites` を持つロールの人。招待制のサーバーで、新しい人を迎えるたびに来る。週に数回。
- メンバーの招待を見直す人。誰がどれだけ招待したかを確かめ、問題のある招待を失効させる。まれ。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| モデレーションのメニューから来て、招待と使われた人数を読む | 1 |
| 使える招待のリンクをコピーする | 2 |
| 招待を失効させる | 2 |
| 新しい招待のフォームを開く | 2 |

手順は、メニューの「招待」を押す 1 つから。コピーと失効は行のボタンを押す 1 つを足す（確かめない）。フォームは「招待を作成する」を押す 1 つを足す。

### 3. 情報の優先順位とまとまり

登録モードが `closed` のときは、招待では誰も登録できないことを先頭に言う。その下に「招待を作成する」のボタン（`/moderation/invites/new` へのリンク）、招待の表を並べる。区画の見出し（`h2`）は持たない。

1. 招待の表（`RecordTable`）: 列は招待コード（`dir="ltr"`）・状態（状態と、その下に登録した人数（上限があれば「{上限} 人中 {人数} 人が登録」）と、作った人とその種類（モデレーターの招待・メンバーの招待））・期限・操作（使える招待の「リンクをコピー」と「失効」）の 4 つ。
   作成日時は一覧に出さない（新しい順に並ぶ）。40rem より狭いコンテナでは行ごとのカードになり、横にスクロールしない。

### 4. 主な操作と保存の仕方

- 主な操作は「招待を作成する」（`primary` のリンク）。
- 失効はすぐ保存で、確かめない（もう 1 つ作れば済む）。コピーはクリップボードに書くだけ。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| リンクをコピーする | その場。トーストで知らせる |
| 失効させる | その場。行が「失効」になり、ボタンがなくなるのでフォーカスは行の見出しへ移り、一覧の上の `StatusMessage` が言う。失敗はトースト（`danger`） |
| 「招待を作成する」を押す | 画面の遷移。[新しい招待](moderation-invite-new.md)へ |
| 次のページを読み込む | その場。前後のページへ移る。失敗は一覧の中のエラーと再試行 |

### 6. 入口と出口

- 入口: モデレーションのメニュー（`manage_invites`）、監査ログの `invite` の項目のリンク、新しい招待のページの「招待に戻る」。
- 出口: 新しい招待。権限がなければ `AdminError` が足りない権限を示す。
