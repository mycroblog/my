## 通知のリクエスト（`/notifications/requests`）

通知の振り分け（[通知の設定](settings-notifications.md)）が保留した通知を、差出人ごとのリクエストとして読み、1 人ずつ受け入れるか閉じる画面（[ADR-0158](../../../adr/0158-notification-policy.md) §7、§10）。
保留した通知は、通知の一覧と未読の数に入らず、プッシュ・メール・音でも届かない。受け入れると、その人の保留した通知が一覧に戻り、以後その人の通知は振り分けで保留も破棄もされない。閉じると、それまでの保留した通知は消え、次に保留した通知が来ればまたリクエストになる。

### 1. 使う人と頻度

通知の振り分けで、どれかの条件を「保留する」にした利用者。通知の画面の先頭の「{N} 人からの通知のリクエスト」を見て開く。週に数回まで。保留を選んでいない人には何も出ない。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| リクエストを 1 つ受け入れる | 2 |
| リクエストを 1 つ閉じる | 2 |

手順は、通知の画面のリクエストの行を押す 1 つと、リクエストの「受け入れる」か「閉じる」の 1 つ（リクエストを読むことは数えない）。

### 3. 情報の優先順位とまとまり

画面の `h1`（「通知のリクエスト」）の下に、何が並ぶかと受け入れる・閉じるが何をするかを 1 段落で言い、通知の振り分けを変えるリンク（[通知の設定](settings-notifications.md)）を添える。その下に、リクエストの一覧（名前「通知のリクエスト」の `list`）を、最新の通知が新しい順に並べる。区画の `h2` は持たない。

1. リクエストの行: 差出人（アバター・名前・ハンドル）と、保留した通知の数（「保留した通知 {N} 件」）、その下に「受け入れる」（`primary`）・「閉じる」と、通知を読むリンク「通知を見る」（[リクエストの通知](notifications-request.md)へ）。
   ボタンとリンクの名前は差出人の名前を含む（「受け入れる：{名前}」。Y2）。
2. 一覧の終わり: 続きの読み込み（「さらに読み込む」）
3. リクエストがないときは空の状態（`EmptyState`）: 「リクエストはありません」と、ここに何が出るか。

### 4. 主な操作と保存の仕方

- 主な操作は、リクエストに答えること（受け入れる・閉じる）。行ごとにすぐ送り、確かめない。受け入れは取り消せないが、止めたくなった相手はミュートかブロックで止められる（ADR-0158 §7）。
- 答えたリクエストは一覧から消え、フォーカスは次の行の最初のボタン（なければ前の行、どれもなければ見出し）へ移る（`useFocusAfterRemoval`）。
- 答えると、リクエストの数（通知の画面の先頭の行）を無効化して取り直す。受け入れると、通知の一覧（右帯を含む）と未読の数も無効化して、表示中のものを取り直してから結果を知らせる（S1）。再読み込みは要らない。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 受け入れる | その場。ボタンが送信中になり、終わると行が消えて「{名前} さんの通知を受け入れました」を読み上げる。次の行へフォーカス |
| 閉じる | その場。受け入れると同じで、文は「{名前} さんの通知のリクエストを閉じました」 |
| 答えが失敗する（ほかの端末で答え済みなど） | その場。行とフォーカスは残り、サーバーの理由を読み上げる（`assertive`） |
| 「通知を見る」 | 画面の遷移（[リクエストの通知](notifications-request.md)） |
| 続きを読み込む | その場。一覧の後ろに足す |
| 新しく通知が保留される（ストリーム） | 一覧には無効化の印だけを付け、表示中の一覧は変えない。次に開くと取り直す |

### 6. 入口と出口

- 入口: 通知の画面の先頭の「{N} 人からの通知のリクエスト」。リクエストの通知の画面で答えた後。
- 出口: 通知の画面（ナビゲーション）、[リクエストの通知](notifications-request.md)、通知の振り分けの設定。受け入れた通知は通知の画面に出る。
