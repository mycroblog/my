## 設定のトップ（`/settings`）

設定のメニュー（[settings-menu.md](settings-menu.md)）と並ぶ本文。広い画面ではメニューの横、`md` 未満ではメニューの下に出る。
アカウントが守られているかの要約を先に見せ、運営の入口・ログイン中のアカウント・規約をその後に置く（[§21.1](../21-experience-principles.md#211-原則と優先順位) の P1・P3）。

### 1. 使う人と頻度

- ログインしたすべての利用者。設定の画面を探すときに開き、そのついでにアカウントの守りの状態を見る。月に数回。
- スタッフ（モデレーションか管理の権限を持つロールの人）。管理とモデレーションのモードに入るために毎日開く。
- 共有の端末で使い終えた利用者。ログアウトするために開く。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| ナビゲーションから設定を開き、二要素認証がオンかを確かめる | 1 |
| 設定から、二要素認証を始める画面を開く | 1 |
| 設定から、登録したパスキーの数を確かめて、パスキーの画面を開く | 1 |
| 設定から、管理とモデレーションのモードに入る（スタッフ） | 1 |
| 設定からログアウトする | 1 |

### 3. 情報の優先順位とまとまり

1. セキュリティ: パスワード・二要素認証・パスキー・連携したアカウント（ログインの提供元があるとき）の 4 行。各行は、その画面へのリンク（名前は画面の名前）と、
   状態のバッジ（`StatusBadge`。アイコンと文言）を持つ。バッジはリンクの名前に入る。
   - パスワード: 「設定済み」（チェック）か「なし」（中立）
   - 二要素認証: 「オン」（チェック）か「オフ」（警告。始めることを勧める）
   - パスキー・連携したアカウント: 「N 件」（チェック）か「なし」（中立）
   - 状態を読み込む間と読めなかったときは、バッジを出さずにリンクだけを出す（各画面が自分の状態を出す）。
2. 管理とモデレーション（スタッフだけ）: モードへのリンクと、モデレーターを待つ件数のバッジ。
3. アカウント: ログイン中のアカウントとログアウト。
4. 規約とポリシー（サーバーに文書があるとき）: 利用規約とプライバシーポリシーへのリンク。

### 4. 主な操作と保存の仕方

- 主な操作は、セキュリティの行から、その画面を開くこと。
- この画面は何も保存しない。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| セキュリティの行を押す | 画面の遷移。メニューのその項目が `aria-current="page"` になる |
| 管理とモデレーションを押す | 画面の遷移（モデレーションの画面、権限がなければ管理の画面） |
| ログアウト | 画面の遷移（トップ） |

### 6. 入口と出口

- 入口: ナビゲーションの「設定」。設定の各画面の「設定に戻る」（`md` 未満）。
- 出口: セキュリティの各画面、管理とモデレーションのモード、ログアウト後のトップ。
