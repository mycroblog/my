## ジョブの一覧（`/admin/jobs/list`）

`manage_jobs` を持つ管理者が、ある状態のジョブを一覧し、失敗したジョブを再実行する、ジョブの画面の 2 つ目のページ（ADR-0004、[§14](../14-admin.md)）。
状態の絞り込みは `ListToolbar` の `Select` で、URL の `?state=queued` / `running` / `retrying` / `dead` に置く（既定は未完了）。一覧はページングした `RecordTable` で、ペイロードもエラーも出さない。

### 1. 使う人と頻度

- 管理者。管理のトップのタイル「失敗したジョブ」（`?state=dead`）、キューの状態のタイル、`LocalNav` から来る。失敗が溜まったときに、数千件でも 1 ページずつ。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 失敗したジョブを 1 つ再実行する | 2 |
| リトライを待っているジョブを一覧する | 2 |

手順は、失敗したジョブの再実行が、管理のトップのタイル「失敗したジョブ」で一覧を開く 1 つと「再実行」を押す 1 つ。
リトライを待つジョブの一覧は、メニューの「ジョブ」でキューの状態を開く 1 つと「リトライ待ち」のタイルを押す 1 つ。

### 3. 情報の優先順位とまとまり

1. 絞り込み（ジョブの状態の `Select`）。
2. ジョブの表（列は 4 つまで）: 型（ジョブのページへのリンク、`dir="ltr"`）・状態・日時（失敗したジョブは失敗の日時、ほかは予定）・操作（失敗したジョブだけ「再実行」）。試行回数・キー・ワーカー・エラー・ペイロード・試行の履歴は[ジョブのページ](admin-job.md)に置く。
3. 下に前へ / 次への `Pagination`（API のカーソルで 40 件ずつ）。

一覧できないキュー（Cloud Tasks）では、「失敗」以外の絞り込みで一覧の代わりに一覧できない理由の `EmptyState` を出す。

### 4. 主な操作と保存の仕方

- 主な操作は、失敗したジョブの「再実行」。確かめずにすぐ送る（再実行は何も壊さない）。アクセシブルネームはジョブの型と失敗の日時を含める。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 絞り込みを変える | その場。その状態の一覧の最初のページ（URL が変わる） |
| 型のリンク | 画面の遷移。ジョブのページ |
| 再実行 | その場。ジョブが一覧から消え、フォーカスは次の行のボタン（なければ `h1`）へ。結果は読み上げ（`useNotice`）、失敗はトースト |
| 前へ / 次へ | その場。前後のページ |

### 6. 入口と出口

- 入口: 管理のトップのタイル「失敗したジョブ」、[キューの状態](admin-jobs.md)のタイルと `LocalNav`、ジョブのページの「ジョブの一覧に戻る」。
- 出口: [ジョブのページ](admin-job.md)、キューの状態、メニューのほかの画面。
