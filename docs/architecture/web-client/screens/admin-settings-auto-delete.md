## サーバーの設定: 投稿の自動削除（`/admin/settings/auto-delete`）

`manage_settings` を持つ管理者が、新しいアカウントが始める自動削除の既定と、どのアカウントも超えられない保持の上限と、その猶予を決めるページ（FR-118・FR-121、[ADR-0151](../../../adr/0151-auto-delete-server-default-and-maximum.md)、[§14](../14-admin.md)）。
画面の名前の `h1` の下に、ページの間のリンクの並び（`LocalNav`。「全般」「アイコンとロゴ」「登録」「コンテンツ」「投稿の自動削除」「連合」「検索とクローラー」、サーバーが通話を出しているときだけ「通話」）を置き、今のページを `aria-current="page"` にする。管理のメニューは「サーバーの設定」の 1 項目のままで、どのページでも今いる項目になる。

### 1. 使う人と頻度

- サーバーを立ち上げた管理者。投稿を長く持たない方針のサーバーで、既定と上限を最初に決める。立ち上げのときに 1 回。
- 運営を続ける管理者。上限の日数や許す例外を見直す。年に数回まで。上限を有効にするか厳しくすると、縛られるアカウントすべてに通知が届くので、保存の前に確かめる。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 新しいアカウントが自動削除をオンで始めるようにする | 5 |
| 上限を 365 日で有効にする | 6 |
| 猶予の日数を変える | 5 |

手順は、管理のメニューの「サーバーの設定」を開く 1 つ、ページの間のリンクで「投稿の自動削除」を開く 1 つ、欄を変える 1 つ（数の欄は入力の 1 つ）、「設定を保存する」を押す 1 つ。上限を有効にする保存は、確かめのダイアログの「保存して通知する」を押す 1 つが増える。猶予の日数を変える保存は確かめない（すでに知らせた日付は変わらない）。日数の欄の今の値を消す操作は、入力の手順に含める。

### 3. 情報の優先順位とまとまり

1. 新しいアカウントの既定（`card`）: 既定は登録のときに写し、後で変えても今あるアカウントは変わらないことの説明、自動で削除するか（`Checkbox`）、削除する投稿の古さ（日数の `TextField`）、残す投稿（ピン留め・ブックマーク・お気に入り・メディア・投票のチェックボックスの `group`）、残す公開範囲（公開範囲ごとのチェックボックスの `group`。名前は投稿のフォームと同じ定義を使う）、ブーストとお気に入りの数のしきい値（`TextField`、0 は条件なし）。
2. 上限（`card`）: 上限がある間に起きること（自動削除をオフにできない、日数を超えて残せない、投稿を長く残す権限のあるアカウントは対象外、紹介のページに出る）の説明、残せる最長の日数（`TextField`、0 は上限なし）、上限の下で使える例外（チェックボックスの `group`。ピン留め・ブックマーク・お気に入り・メディア・投票・公開範囲・反応の数）、上限の下で残すピン留めの数（1〜5、5 はすべて）、猶予の日数（0〜365）。

数の欄は、サーバーの返す範囲を説明に書き、範囲の外の値は欄のエラーにして送らない。

### 4. 主な操作と保存の仕方

- 主な操作は「設定を保存する」（ページに 1 つ、`primary`）。保存は、まとめて保存だけ。このページの設定のうち変えたものだけを `PATCH /admin/settings` でまとめて送り、すべて通るか何も変わらないかのどちらかで、変更は 1 つずつ監査ログに残る。
- 上限を有効にする、日数を下げる、許す例外を外す、残すピン留めの数を減らす保存は、送る前に `alertdialog` で確かめる。ダイアログは、1 時間以内に縛られるローカルのアカウントすべてにアプリとメールで通知が届くこと、猶予の日数の後に上限で消え始めること、削除は戻せないことを並べ、権限のあるアカウントと、それまでに設定を上限の内に直したアカウントは変わらないことを添える。フォーカスは「キャンセル」から始まり、確かめのボタンは「保存して通知する」（`danger`）。
- 既定の変更、上限を上げる・外す変更、猶予の変更は確かめずに保存する（縛られるアカウントを増やさない）。
- 保存のボタンは `FormActionBar` に置き、画面より長いときのためにバーを画面の下に固定する。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 保存 | その場。`FormActionBar`（保存のボタンの横）に結果を出す |
| 上限を有効にするか厳しくして保存 | その場。確かめのダイアログを開く。「キャンセル」は何も送らず入力を残し、「保存して通知する」で送って `FormActionBar` に結果を出す |
| 変えずに保存 | その場。`FormActionBar` に保存するものがないこと |
| 範囲の外の数で保存 | その場。欄のエラーにして送らない |
| サーバーが拒否 | その場。`FormActionBar`（`role="alert"`）に理由を出し、入力を残す |

### 6. 入口と出口

- 入口: 管理のモードのメニューの「サーバーの設定」から、ページの間のリンクの「投稿の自動削除」。
- 出口: ページの間のリンクのほかのページ、管理のメニュー。保存した上限は、紹介のページ（[`/about`](about.md)）と利用者の[自動削除の設定](settings-auto-delete.md)で確かめられる。投稿を長く残す権限は[ロール](admin-role.md)で付ける。
