## 承認の依頼（`/settings/interaction-requests`）

自分の投稿への返信・ブースト・引用のうち、交流の許可で「承認制」にした相手からのもの（作者の承認待ち）を読み、1 件ずつ承認するか断る画面（[ADR-0155](../../../adr/0155-interaction-policy.md) §6、§10）。
承認するまで、返信はスレッドに出ず、ブーストは数えず、引用は投稿を出さない。答えると、相手のサーバーにも伝わる。

### 1. 使う人と頻度

返信・ブースト・引用のどれかを承認制にした利用者。承認の依頼の通知（`reply_request`・`boost_request`・`quote_request`）を見て、届いたときに開く。承認制にしていない人には何も届かない。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 返信の承認の依頼を 1 つ承認する | 3 |
| ブーストの承認の依頼を 1 つ断る | 3 |

手順は、設定のメニューの「承認の依頼」を開く 1 つ、依頼の「承認する」か「断る」の 1 つ（依頼を読むことは数えない）と、通知から来るときの「依頼を確かめる」の 1 つ。

### 3. 情報の優先順位とまとまり

画面の `h1`（「承認の依頼」）の下に、依頼の一覧（名前「承認の依頼」の `list`）を新しい順に並べる。区画の `h2` は持たない。

1. 依頼の行: 相手（アバター・名前・ハンドル）と、何を求めているか（「あなたの投稿への返信の承認を求めています」など）、その下に「承認する」（`primary`）と「断る」。
   その下に、相手の返信か引用している投稿（サーバーが持っていて閲覧者が見られるときだけ。ブーストにはない）と、自分の投稿を、引用と同じ小さな枠（「相手の返信」「相手の投稿」「あなたの投稿」の `group`）で出す。
2. 一覧の終わり: 続きの読み込み（「さらに読み込む」）
3. 依頼がないときは空の状態（`EmptyState`）: 「依頼はありません」と、ここに何が出るか。

### 4. 主な操作と保存の仕方

- 主な操作は、依頼に答えること（承認する・断る）。行ごとにすぐ送り、まとめて保存する操作はない。
- 答えた依頼は一覧から消え、フォーカスは次の行の最初のボタン（なければ前の行、どれもなければ見出し）へ移る（`useFocusAfterRemoval`）。
- 答えると、その投稿の返信とブーストの数、相手の投稿（承認した引用はあなたの投稿を出す）、スレッドがキャッシュで変わる。スレッドは無効化の印を付けて表示中のものを取り直すので、承認した返信は再読み込みなしでスレッドに入る。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 承認する | その場。ボタンが送信中になり、終わると行が消えて「{名前} さんの返信を承認しました」（ブースト・引用も同じ形）を読み上げる。次の行へフォーカス |
| 断る | その場。承認と同じで、文は「{名前} さんの返信を断りました」 |
| 答えが失敗する（答え済み・削除された投稿など） | その場。行とフォーカスは残り、サーバーの理由を読み上げる（`assertive`） |
| 続きを読み込む | その場。一覧の後ろに足す |

### 6. 入口と出口

- 入口: 設定のメニューの「関係」のまとまりの「承認の依頼」（フォローリクエストの次）。承認の依頼の通知の「依頼を確かめる」。
- 出口: 設定のメニュー。答えた結果は、投稿の詳細のスレッドと数、相手への通知に出る。既定の承認制は[表示・投稿・タイムライン](settings-preferences.md)で変える。
