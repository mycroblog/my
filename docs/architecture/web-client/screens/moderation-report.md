## 通報の詳細（`/moderation/reports/{id}`）

`manage_reports` を持つモデレーターが、1 つの通報の内容と証拠を読み、処分するか処分せずに解決する画面（FR-710、NFR-MOD-4、[§14](../14-admin.md)）。
`@my/ui` の `TriageLayout` で、判断の区画を証拠を読む間も手の届く所に置く。

### 1. 使う人と頻度

- 通報を受け持つモデレーター。通報を開き、担当になり、投稿と相手の履歴を読み、処分か解決を決める。通報ごとに 1 回、1 日に数件から数十件。
- 解決済みの通報を確かめるモデレーター。結果を見て、必要なら再開する。まれ。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 担当になる | 1 |
| 警告して解決する（処分の種類を選び、処分を出す） | 3 |
| 処分せずに解決する（対応不要） | 1 |
| ほかの画面で処分済みとして解決する | 1 |
| メモを残す | 2 |
| 解決済みの通報を再開する | 1 |

手順は、詳細を開いた後から数える。処分は、種類を選ぶ 1 つ、理由の種類が通報のカテゴリのままなら送信のボタンを押す 1 つ、確かめのない種類ならそれで終わる（BAN と投稿の削除は確かめのダイアログの 1 つを足す）。
メモは、欄に書く 1 つと「メモを追加する」の 1 つ。

### 3. 情報の優先順位とまとまり

1. 通報（要約）: 状態・カテゴリ・待ち時間（未解決）のバッジ、通報日時・通報者・通報元・転送、引用するルール、通報者のコメント。
2. 担当（判断）: 今の担当と「自分が担当する」「担当を引き継ぐ」「担当を外す」。
3. 対応（判断）: 未解決なら、処分のフォーム（`h3`）と「ここで処分せずに解決する」（`h3`）。解決済みなら結果と解決日時と「再開する」。
4. 通報された投稿（証拠）。通話のルームの通報では、代わりに通話のルーム。
5. 通報されたアカウント（証拠）: アカウント、プロフィール・アカウントの管理・監査ログへのリンク、ほかの通報と処分の件数。
6. アカウントへの処分（証拠、`manage_accounts`）: 処分の履歴。
7. メモ（証拠）: 古い順のメモと、新しいメモの欄。

広い画面では 1 と 4〜7 が左の列、2 と 3 が右の列の先頭に並ぶ。狭い画面では 1、2、3、4〜7 の順の 1 列。

### 4. 主な操作と保存の仕方

- 主な操作は、処分のフォームの送信（「処分して解決する」、画面で唯一の `primary`）。処分せずに解決する 2 つのボタンは既定の見た目で、主な操作より軽く見せる。
- 保存は、まとめて保存だけ（処分のフォーム、メモのフォーム）。担当・解決・再開のボタンは押すとすぐ送る。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 担当になる・外す | その場。担当の区画の `StatusMessage`。押したボタンにフォーカスが残る。失敗はトースト |
| 処分を出す | その場。対応の区画が解決済みに替わり、見出しにフォーカスを移して `StatusMessage` に結果を出す。失敗はフォームの下（BAN と投稿の削除はダイアログの中） |
| 処分せずに解決する・処分済みとして解決する・再開する | その場。対応の区画が入れ替わり、見出しにフォーカスを移して `StatusMessage` に結果を出す。失敗はトースト |
| メモを追加する | その場。メモの一覧に足し、欄を空にして `StatusMessage` に結果を出す。失敗は欄のエラー |

### 6. 入口と出口

- 入口: 通報の一覧の行、モデレーションのトップの「先に対応する通報」、新しい通報の通知、アカウントの管理の通報の一覧。
- 出口: 通報の一覧（解決した通報は未解決から消える）、通報されたアカウントの管理の画面、監査ログ。
