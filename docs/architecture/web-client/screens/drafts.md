## 下書きと予約投稿（`/drafts`）

サーバーに保存した下書きと予約投稿を読み、開いて続きを書き、予約の時刻を変え、予約を取り消し、削除する画面（[ADR-0156](../../../adr/0156-drafts-and-scheduled-posts.md)）。
下書きは本人だけのもので、どの端末からでも同じ一覧を読む。下書きを書く・保存する・予約するのは投稿のフォーム（[compose.md](compose.md)）で、この画面は一覧と、フォームを開かずにできる操作を持つ。

### 1. 使う人と頻度

下書きを保存するか投稿を予約した利用者。ほかの端末で書いた下書きの続きを書くとき、予約を確かめるとき、予約の失敗の通知（`scheduled_status_failed`）を見たときに開く。毎日は開かない。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 下書きを 1 つ開いて、フォームで続きを書く | 2 |
| 予約投稿を 1 つ開いて、時刻を変える | 4 |
| 予約を 1 つ取り消す | 2 |
| 下書きを 1 つ削除する | 2 |

手順は、投稿のフォームの「下書きと予約投稿」のリンクから来るとき（シートは開いている前提で、リンクの 1 つ）を数えない。続きを書くのは「編集する」の 1 つと、本文の入力の 1 つ。
時刻を変えるのは「時刻を変える」・時刻の入力・「予約する」の 3 つと、`/drafts` を開く 1 つ（ほかの作業も同じ）。取り消しは「予約を取り消す」の 1 つ。削除は「削除する」と確認の「削除する」の 2 つ（`/drafts` を開く 1 つを数えない）。

### 3. 情報の優先順位とまとまり

画面の `h1`（「下書きと予約投稿」）の下に、次の順に区画の `h2` を置く。予約は時刻に動き、失敗すれば手当てが要るので先に置く。

1. 予約投稿（`h2`「予約投稿」）: 予約された下書きの一覧（名前「予約投稿」の `list`）。サーバーの順（新しい順）。続きは「さらに読み込む」。ないときは空の状態（「予約した投稿はありません」）
2. 下書き（`h2`「下書き」）: 予約のない下書きの一覧（名前「下書き」の `list`）。同じく新しい順と「さらに読み込む」。ないときは空の状態（「下書きはありません」と、フォームの「下書きに保存」で保存できること）

行は、どちらの一覧も同じ形にする。

- 本文の初めの数行（`dir="auto"`、下書きの言語の `lang`。CW があれば CW を本文の代わりに出す）。本文も CW もなければ「（本文なし）」
- 添付の数・投票・返信か引用の印（あるときだけ。`Hint` の 1 行）
- 予約投稿: 「<日時> に公開」（利用者のタイムゾーンの日時、`<time>`）。下書き: 「<日時> に保存」
- 前の予約が公開できなかった下書き（`last_schedule` の `outcome` が `failed`）: 「<日時> の予約は公開できませんでした。<理由>」（`tone="warning"` の `Text`。理由は通知と同じ文）
- 操作: 「編集する」、予約投稿は「時刻を変える」（ポップオーバー）と「予約を取り消す」、どちらも「削除する」。ボタンの名前は、どの行のものか分かるよう、本文の初めを含む `aria-label` を持つ

### 4. 主な操作と保存の仕方

- 主な操作は「編集する」。下書きを `GET /drafts/{id}` で読み直し（`ETag` を得る）、投稿のフォームに入れてシートを開く。フォームに書きかけがあれば、置き換えるかを `ConfirmDialog` で確かめる（「置き換える」・「キャンセル」）。
  一覧はサーバーの値を出すだけで、別の状態に写さない（S2）。
- 保存は、行ごとにすぐ保存する（まとめて保存する操作はない）。
- 「時刻を変える」は、フォームの予約と同じポップオーバー（日付と時刻、タイムゾーンの名前、「予約する」）で `PUT /drafts/{id}/schedule` を送る。範囲の外の時刻はその場で欄の誤りにし、サーバーが断ればポップオーバーの中に理由を出す。
- 「予約を取り消す」は `DELETE /drafts/{id}/schedule` ですぐ送る。下書きは消えず、下書きの一覧へ移る（元に戻すのはもう一度予約すること）。
- 「削除する」は確認（`ConfirmDialog`、「削除する」は `danger`）の後に `DELETE /drafts/{id}`。予約も消える。元に戻せない。
- どの操作も、終わると両方の一覧に無効化の印を付けて取り直し（S1）、取り直してから結果を出す。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 編集する | ボタンが送信中になり、読めたらシートが開いて下書きがフォームに入る（フォーカスは本文）。読めなければ（消えていた・通信の失敗）その行に理由を読み上げる（`assertive`） |
| 編集する（フォームに書きかけがある） | 確認のダイアログが開く。「置き換える」でシートが開き、「キャンセル」でダイアログが閉じてフォーカスはボタンへ |
| 時刻を変える → 予約する | 範囲の外ならその場で欄の下に理由。通れば、ポップオーバーが閉じ、行の時刻が変わり、「<日時> に予約しました」を読み上げる。フォーカスは「時刻を変える」へ |
| 予約を取り消す | ボタンが送信中になり、終わると行が予約投稿の一覧から下書きの一覧へ移り、「予約を取り消しました」を読み上げる。フォーカスは次の行の最初のボタン（なければ前の行、どれもなければ見出し） |
| 削除する → 確認の「削除する」 | ダイアログが閉じ、行が消え、「下書きを削除しました」を読み上げる。フォーカスは取り消しと同じ |
| どの操作も失敗する | 行を残し、理由を読み上げる（`assertive`）。ポップオーバーとダイアログの失敗はその中に出し、開いたまま |

### 6. 入口と出口

- 入口: 投稿のフォームの「下書きと予約投稿」、予約の失敗の通知の「下書きを開く」。
- 出口: 「編集する」はこの画面の上に投稿のシートを開く（閉じるとこの画面に戻る）。ページの見出しの戻るボタンで前の画面へ。
