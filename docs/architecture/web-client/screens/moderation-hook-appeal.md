## 止められた投稿への異議申し立て（`/moderation/hook-decisions/appeals/{id}`）

`local.status` の外部の審査（ADR-0147）に拒否された投稿への、作者の 1 つの異議申し立てを読み、判定を維持するか撤回するかを決めるページ。
[異議申し立ての一覧](moderation-hook-appeals.md)の行と、`admin_hook_appeal` の通知（Web Push を含む）から来る。本文が出るのは作者が異議に添えたものだけ。

### 1. 使う人と頻度

- 通報を受け持つモデレーター（`manage_reports`）。作者が投稿しようとした本文とコメントを読み、判定が正しかったかを決める。異議ごとに 1 回、週に数件。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 作者が送った本文とコメントを読む | 1 |
| 異議に対して判定を維持する・撤回する | 3 |
| 元の判定のページを開く | 2 |
| 作者のアカウントの管理画面を開く | 2 |

手順は、異議申し立ての一覧（`start`）から数える。一覧の行の作者のリンクで異議のページを開く 1 つで、本文とコメントはそこで読める。審査は、それに「維持する」か「撤回する」と確認のダイアログのボタンの 2 つを足す。判定とアカウントは、それにリンクの 1 つを足す。一覧へ戻るのは `h1` の下の「異議申し立ての一覧へ戻る」の 1 つ。

### 3. 情報の優先順位とまとまり

`h1`（「止められた投稿への異議申し立て」）の下に「異議申し立ての一覧へ戻る」のリンク。

1. 申し立て（`h2` の `Section`）: 状態・作者・申し立ての日時、作者のアカウントの管理画面へのリンク、作者が送った本文とコメント（どちらも平文で `dir="auto"`。コメントがなければ「なし」）。
2. 審査の判定（`h2` の `Section`）: フック・対象のキー・結果・モード・判定した日時・待ち時間・理由コード（表示言語のラベル）・プラグインのメモ（`dir="auto"`）・取り消した日時と、判定のページへのリンク。作者は申し立ての区画に出すので、ここにはアカウントを出さない。
3. モデレーターの審査（`h2` の `Section`）: 待っている異議には説明と「維持する」「撤回する」。決めた異議には結果と決めた日時。

### 4. 主な操作と保存の仕方

- 主な操作は審査（維持するか撤回する）。審査は変えられないので、確認のダイアログ（`ConfirmDialog`、NFR-MOD-7）を経てから保存する。
- 撤回すると判定が取り消され、その作者の投稿はこのフックに送られなくなる。維持すると判定はそのまま残る。どちらでも作者に知らせる。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 判定を維持する・撤回する | 確認の後、その場。異議と一覧と判定を読み直し、ボタンが結果と決めた日時に変わる。結果を審査の区画の `StatusMessage`（`role="status"`）で読み、フォーカスは審査の見出しへ。ほかのモデレーターが先に決めていれば、読み直してそう伝える。ほかの失敗はダイアログの中に理由を出し、開いたまま |
| 確認のダイアログを取り消す | その場。何も決めずにダイアログを閉じる |
| 判定を開く・アカウントを開く・戻る | それぞれのページへ遷移する |

### 6. 入口と出口

- 入口: 異議申し立ての一覧の作者のリンク、`admin_hook_appeal` の通知のリンクと Web Push。存在しない異議は 404 のエラーのページ。
- 出口: 「異議申し立ての一覧へ戻る」、判定のページ、アカウントの管理画面。権限がなければ `AdminError` が足りない権限を示す。
