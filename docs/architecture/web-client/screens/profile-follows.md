## フォローとフォロワーの一覧（`/@{acct}/followers`・`/@{acct}/following`）

1 つのアカウントをフォローしている人と、そのアカウントがフォローしている人の一覧（FR-204）。知っている人のつながりから新しい人を見つける導線なので、
行から相手が誰かが分かり、その場でフォローできるようにする。

### 1. 使う人と頻度

- ログインした利用者が、プロフィールのフォローとフォロワーの数から来て、新しい人を探す。ときどき。
- 自分のフォロワーを見て、フォローを返す利用者。フォローの通知の後に。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| フォロワーの中から、まだフォローしていない人をフォローする | 1 |
| 一覧の人のプロフィールを開く | 1 |

### 3. 情報の優先順位とまとまり

見出し（`h1`、「〇〇のフォロワー」「〇〇がフォローしている人」）とプロフィールへ戻るリンクの下に、アカウントの行を新しいフォローの順に並べる。

1. **アカウントの行**: アイコン・表示名・ハンドル（プロフィールへのリンク）、その下にリンクの外で「フォローされています」の印とプロフィールの文の 1 行（切り詰める）、
   行の終わりにフォローのボタン（`FollowButton` の小さい形、メニューなし）。自分の行と、ログインしていない人には、ボタンを出さない。
2. 続きを読み込むボタン（続きがあるときだけ）。

### 4. 主な操作と保存の仕方

- 主な操作は、行のフォローのボタン。フォローしていない行だけが塗った見た目になるので、フォローできる人が一目で分かる。
- 行の関係は、表示した行の分をまとめて 1 回（40 件ごと）で読む。読み込みの間、ボタンは同じ大きさの場所を取って待つ。
- 保存は、すぐ保存（押すとすぐ送る。やめるときは確かめのダイアログ）。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| フォローする | その場。行のボタンが「フォロー中」（承認制なら「リクエスト中」）に変わり、フォーカスが残る。結果を読み上げる。失敗はトースト |
| 行を押す | 画面の遷移（プロフィール） |
| 続きを読み込む | その場。行が足され、ボタンにフォーカスが残る。失敗は一覧の下の文と読み上げ |

### 6. 入口と出口

- 入口: プロフィールのフォローとフォロワーの数。
- 出口: 行のプロフィール、元のプロフィール（戻るリンク）。
