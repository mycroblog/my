## 通報の一覧（`/moderation/reports`）

`manage_reports` を持つモデレーターが、通報の待ち行列から次に処理する通報を選ぶ画面（FR-701、FR-710、[§14](../14-admin.md)）。
保存する操作はない。絞り込みは URL に置く。

### 1. 使う人と頻度

- 通報を受け持つモデレーター。未解決の通報を見て、急ぐもの（違法な内容、長く待っているもの）と自分の担当を選んで開く。1 日に数回。
- 過去の対応を確かめるモデレーター。解決済みの通報を見る。週に数回まで。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| いちばん長く待っている未解決の通報を開く | 2 |
| 違法な内容の通報を開く | 4 |
| 自分の担当の通報を開く | 4 |
| 解決済みの通報を見る | 3 |

いちばん長く待っている通報は、モデレーションのトップの待ち時間のタイル（古い順の一覧）を押す 1 つと、最初の行のリンクを押す 1 つ。
ほかは、メニューの「通報」を開く 1 つ、絞り込み（カテゴリ・担当・状態）を開く 1 つと選ぶ 1 つ、行のリンクを押す 1 つ。
絞り込みと並び順はサーバーが待ち行列全体に対して行うので、最初のページに限らずに探せる。

### 3. 情報の優先順位とまとまり

区画の見出しはない。絞り込みの帯（状態・カテゴリ（すべて・4 つのカテゴリ）・担当（すべて・自分の担当・未担当）・並び順（新しい順・古い順））の下に、1 ページの表を置く。
カテゴリか担当で絞り込んで 1 件もないときは、「条件に合う通報はありません」の空の状態を出す。

1. 通報: 対象のハンドル（詳細へのリンク）、投稿の数、通報者のコメント（2 行に省略）。
2. カテゴリ: `StatusBadge`（違法は危険の色、ルール違反は注意の色、ほかは中立）。
3. 通報者。
4. 担当（未解決）: 「あなた」・「担当あり」と名前・「未担当」の印。解決済みは結果。
5. 待ち時間（未解決）: `AgeBadge`（1 日で注意、3 日で危険）。解決済みは解決日時。

### 4. 主な操作と保存の仕方

- 主な操作は、行の通報を開くこと。
- 保存する操作はない。絞り込みと並び順は選ぶとすぐ一覧が替わり、URL に残る（`state`・`category`・`assignee`・`order`。既定の値は URL に出さない）。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 通報を開く | 画面の遷移。通報の詳細 |
| 絞り込みか並び順を変える | その場。一覧が最初のページから替わり、URL が変わる |
| 前・次のページ | その場。表が替わる |

### 6. 入口と出口

- 入口: モデレーションのトップのタイル「未解決の通報」と「通報の最長の待ち時間」（古い順）と「通報の一覧を開く」、メニューの「通報」、新しい通報の通知。
- 出口: 通報の詳細。処理を終えたら、詳細の画面からこの一覧に戻る。
