## アカウントの管理（`/moderation/accounts/{id}/manage`）

ローカルのアカウントの利用者を支える作業（ロール・メールの配信・サインインの回復・メールアドレスと IP アドレス）のページ（FR-720、FR-005、FR-002、FR-714、[§14](../14-admin.md)）。
アカウントの管理画面の 3 つめのページで、画面と同じ `manage_accounts` で開き、各区画はそれぞれの権限を持つ閲覧者にだけ出す。`h1` の下に `LocalNav`（「審査」「処分の履歴」「管理」）、その下にどのアカウントのページかを示すアバター・名前・ハンドルを置く。
どれもモデレーションの判断ではないので、処分を決める審査のページ（[moderation-account.md](moderation-account.md)）から分けた。リモートのアカウントにはどの区画もないので、`LocalNav` に「管理」を出さず、URL で開いたときは管理するものがないことを `EmptyState` で書く。

### 1. 使う人と頻度

- 管理者（`manage_roles`・`manage_login_recovery`）。ロールを変える、二要素認証を外す、パスワードの再設定のリンクを出す。月に数回まで。
- モデレーター（`manage_accounts`）。メールアドレスと IP アドレスを見る（同じ人の別のアカウントを探す）、メールの配信の抑止を解除する。週に数回まで。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| quickdeals のメールアドレスと IP アドレスを見る | 5 |
| quickdeals のパスワードのリセットのリンクを発行する | 6 |
| yuki に moderator のロールを付与する | 6 |

手順は、アカウントの検索から数える。ユーザー名を入れる 1 つ、検索する 1 つ、結果のアカウントを開く 1 つ、`LocalNav` の「管理」の 1 つ。
メールアドレスと IP アドレスは「表示する」の 1 つ。リンクの発行とロールの付与は、ボタンとダイアログの確定の 2 つ。

### 3. 情報の優先順位とまとまり

1. ロール（`manage_roles`）: このサーバーのロールごとの、このアカウントが持つかと「付与する」「剥奪する」。
2. メールの配信（主たるアドレスが抑止されているときだけ）: 抑止の種類と時刻、`manage_accounts` には「抑止を解除」。
3. 二要素認証（`manage_login_recovery`）: 使っているかと「二要素認証を解除」。
4. パスワードのリセット（`manage_login_recovery`）: リンクの説明と「パスワードリセットのリンクを発行」、発行したリンク（1 度だけ）。
5. メールアドレスと IP アドレス（`manage_accounts`）: 「表示する」を押すまで出さない。

### 4. 主な操作と保存の仕方

- 主な操作はない（`primary` のボタンを持たない）。区画ごとに、確かめてから送る操作を 1 つ持つ（付与・剥奪、抑止の解除、二要素認証の解除、リンクの発行）。表示は確かめずに送り、監査ログに残る。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| ロールを付与する・剥奪する | その場。区画の `StatusMessage`、ボタンが反対のボタンに替わるのでフォーカスは区画の見出しに移る。失敗はダイアログの中 |
| 抑止を解除する・二要素認証を解除する | その場。区画の `StatusMessage`、ボタンが消えるのでフォーカスは区画の見出しに移る。失敗はダイアログの中 |
| パスワードのリセットのリンクを発行する | その場。区画の `StatusMessage` とリンク・コピーのボタン（コピーの結果はトースト）。失敗はダイアログの中 |
| メールアドレスと IP アドレスを見る | その場。区画に出し、見出しにフォーカスを移す。失敗はトースト |

### 6. 入口と出口

- 入口: 審査と処分の履歴のページの `LocalNav`。ロールの画面（`/admin/roles`）の、ロールを付与するためのアカウントの検索へのリンクから、検索を経て来る。
- 出口: 審査のページ、アカウントの検索（メールアドレスのドメインと IP アドレスの検索、同じ IP アドレスのほかのアカウント）、監査ログ。
