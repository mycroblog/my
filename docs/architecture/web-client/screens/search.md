## アカウントの検索（`/search`）

アカウントを探して、そのプロフィールを開くかフォローする画面。このサーバーのアカウントは表示名とハンドルの一部で（FR-307）、
ほかのサーバーのアカウントは `@user@host` か URL で（FR-305）見つける。投稿の全文検索はしない。

### 1. 使う人と頻度

ログインしたすべての利用者が、知っている人やこのサーバーの人を探すときに、ときどき使う。アカウントを作った直後に、ホームのおすすめの「ほかの人を探す」から来る。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| このサーバーの人を名前の一部で探し、プロフィールを開く | 2 |
| このサーバーの人を名前の一部で探し、その場でフォローする | 2 |
| ほかのサーバーの人を `@user@host` で探し、プロフィールを開く | 2 |

手順は、検索の欄に入れる 1 つ（入力は 1 つと数える）と、結果の行を押すかフォローを押す 1 つ。

### 3. 情報の優先順位とまとまり

見出し（`h1`、検索）の下に検索の欄を 1 つ置く。欄は入力の途中で名前の検索（`GET /accounts/search`）を 300 ms 待ってから送り、`@user@host` か URL の形なら送信で解決（`GET /accounts/lookup`）する。

1. **結果**（`h2`、件数付き）: アカウントの行（アバター・表示名・ハンドル・フォローのボタン）。行を押すとプロフィールを開く。
   入力がないときは区画を出さず、欄の下に何を入れられるかの 1 行（「名前の一部か、@user@host を入れてください」）を出す。結果がないときは「見つかりませんでした」と、ほかのサーバーの人なら `@user@host` を入れることを言う。

### 4. 主な操作と保存の仕方

- 主な操作は、検索の欄に入れること（送信のボタンは `@user@host` と URL の解決だけに使う）。
- 保存は、すぐ保存（行のフォローはその場で効く）。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 入れる | その場。結果の一覧が入れ替わり、件数を読み上げる（`aria-live="polite"`） |
| `@user@host` か URL を送る | 押した直後にボタンが処理中になり、見つかれば画面の遷移（プロフィール）。見つからなければ欄のエラー（その場） |
| 行を押す | 画面の遷移（プロフィール）。戻ると、同じ入力と結果の画面に戻る |
| フォロー | その場。ボタンが処理中から「フォロー中」（承認制なら「リクエスト済み」）に変わる |

### 6. 入口と出口

- 入口: ナビゲーションの「検索」、ホームのおすすめの「ほかの人を探す」、ランディングページの「ほかのサーバーのアカウントで」の手順。
- 出口: 見つけたアカウントのプロフィール。
