## 検索（`/search`）

アカウントを探して、そのプロフィールを開くかフォローする画面。このサーバーのアカウントは表示名とハンドルの一部で（FR-307）、
ほかのサーバーのアカウントは `@user@host` か URL で（FR-305）見つける。
全文検索があるサーバー（`Instance.full_text_search.available`）では、ログインしている人は投稿も言葉で探せる（FR-309、[ADR-0149](../../../adr/0149-full-text-search.md)）。
全文検索のないサーバーとログインしていない人には、投稿の検索のタブも入口も出さず、アカウントの検索だけの画面になる。

### 1. 使う人と頻度

ログインしたすべての利用者が、知っている人やこのサーバーの人を探すときに、ときどき使う。アカウントを作った直後に、ホームのおすすめの「ほかの人を探す」から来る。
全文検索があるサーバーでは、読んだ投稿や話題の投稿を言葉で探すときにも使う。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| このサーバーの人を名前の一部で探し、プロフィールを開く | 2 |
| このサーバーの人を名前の一部で探し、その場でフォローする | 2 |
| ほかのサーバーの人を `@user@host` で探し、プロフィールを開く | 2 |
| 全文検索があるサーバーで、投稿を言葉で探す | 3 |

手順は、検索の欄に入れる 1 つ（入力は 1 つと数える）と、結果の行を押すかフォローを押す 1 つ。投稿を探すのは、「投稿」のタブを選ぶ 1 つ、欄に入れる 1 つ、送る 1 つ。

### 3. 情報の優先順位とまとまり

見出し（`h1`、検索）の下に検索の欄を 1 つ置く。欄は入力の途中で名前の検索（`GET /accounts/search`）を 300 ms 待ってから送り、`@user@host` か URL の形なら送信で解決（`GET /accounts/lookup`）する。

1. **結果**（`h2`、件数付き）: アカウントの行（アバター・表示名・ハンドル・フォローのボタン）。行を押すとプロフィールを開く。
   入力がないときは区画を出さず、欄の下に何を入れられるかの 1 行（「名前の一部か、@user@host を入れてください」）を出す。結果がないときは「見つかりませんでした」と、ほかのサーバーの人なら `@user@host` を入れることを言う。

全文検索があるサーバーのログインしている人には、見出しの下に「アカウント」「投稿」のタブを置く。アカウントが先で、既定である。選んでいるタブは URL（`?type=posts`）に置く。
「投稿」のタブには、検索の欄（`GET /statuses/search` の `q`、200 文字まで）と送信のボタンを置く。

1. **投稿**（`h2`）: 見つかった投稿を、新しい順に、タイムラインと同じ描画（内容の警告と閲覧注意のメディアも同じ）の `Feed` で並べる。バックエンドのハイライトや本文は描かない。
   まだ送っていないときは区画を出さない。結果がないときは、このサーバーの検索で見つかる投稿（`full_text_search.visibilities` に合わせて公開、公開範囲が「このサーバー」、その両方）と、許可しているアカウントのものだけであることと、投稿した人はプロフィールの設定で外れられることを言う。

### 4. 主な操作と保存の仕方

- 主な操作は、検索の欄に入れること（送信のボタンは `@user@host` と URL の解決だけに使う）。
- 投稿の検索の主な操作は、送ること（Enter か「投稿を検索」）。回数に厳しい制限（30 回 / 5 分）があるので、入力の途中では送らない。IME の変換中の Enter は変換を確定するだけで、検索しない。
- 保存は、すぐ保存（行のフォローはその場で効く）。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 入れる | その場。結果の一覧が入れ替わり、件数を読み上げる（`aria-live="polite"`） |
| `@user@host` か URL を送る | 押した直後にボタンが処理中になり、見つかれば画面の遷移（プロフィール）。見つからなければ欄のエラー（その場） |
| 行を押す | 画面の遷移（プロフィール）。戻ると、同じ入力と結果の画面に戻る |
| フォロー | その場。ボタンが処理中から「フォロー中」（承認制なら「リクエスト済み」）に変わる |
| 投稿の検索を送る | その場。ボタンが処理中になり、区画に骨組みを出す。答えが来ると投稿の一覧か結果がないことの説明に替わり、件数を読み上げる（`role="status"`）。検索語は URL（`?q=`）に置き、今の履歴を置き換える。フォーカスは欄に残る。同じ言葉をもう一度送ると読み直す |
| 投稿の一覧の終わりに近づく | その場。次のページを読む。ページが短くても空でも、`next_cursor` がある間は続ける。結果がないことは `next_cursor` がなくなってから言う |
| 投稿の検索が失敗する（503 や通信の失敗） | その場。区画に `RegionError`（理由と「もう一度試す」）を出す。読み込み済みの投稿は残し、その下に出す |
| 投稿の検索が制限される（429） | その場。区画に、回数が多すぎることと、制限が解けると自動で実行されることを出す。試し直すと制限を使うだけなのでボタンを出さない。外枠の帯が再開の時刻を言う（`lib/rateLimit.ts`） |
| サーバーが全文検索をやめていた（404 の `search-unavailable`） | `GET /instance` を取り直し、タブが消えてアカウントの検索に戻る |

### 6. 入口と出口

- 入口: ナビゲーションの「検索」、ホームのおすすめの「ほかの人を探す」、ランディングページの「ほかのサーバーのアカウントで」の手順。
- 投稿の検索の入口: この画面の「投稿」のタブ。全文検索のないサーバーでは、`?type=posts` の URL を開いてもアカウントの検索を出す。
- 出口: 見つけたアカウントのプロフィール。投稿の検索では、投稿の詳細。戻ると、同じ検索語と結果の画面に戻る。
