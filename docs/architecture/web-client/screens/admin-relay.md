## リレーのページ（`/admin/relays/{id}`）

`manage_settings` を持つ管理者が、1 つのリレーの事実と直近 24 時間の取り込みを見て、脱退・もう一度参加・削除をするページ（[ADR-0006](../../../adr/0006-federation-protocol-scope.md)、[§14](../14-admin.md)）。
1 つのリレーを返す API はないので、一覧（`GET /admin/relays`）から読む。一覧にない ID は「このリレーは登録されていません」の空の状態にする。

### 1. 使う人と頻度

- 管理者。リレーが多すぎる投稿を運んでいないかを確かめるとき、リレーをやめるとき。月に数回以下。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| relay.example が直近 24 時間に取り込んだ投稿の数を知る | 2 |
| relay.example から脱退して登録を削除する | 5 |

手順は、メニューで一覧を開く 1 つ、リレーの名前を押す 1 つ（取り込んだ数と捨てた数は事実の説明リストにある）、「脱退する」を押す 1 つ、「削除」と確かめの「削除」の 2 つ。

### 3. 情報の優先順位とまとまり

1. 見出し（`h1`「リレー」）と「リレーの一覧へ戻る」。
2. リレー（区画の見出しは URL のホスト名、`dir="ltr"`）: ドメインへの処分で停止中なら、何も送らず受け取らない旨の警告。状態と変更日時・方式・URL・inbox・リレーの Actor（承認されたときだけ）・受信の有無・直近 24 時間に取り込んだ数と上限を超えて捨てた数（捨てた数が 1 以上なら警告の色）の説明リスト。URL と Actor は `dir="ltr"`。
3. 参加: いまの状態でできることの説明と、「脱退する」か「もう一度参加する」（同じ位置のボタン）、拒否と脱退済みのときだけ「削除」。

### 4. 主な操作と保存の仕方

- 主な操作は「脱退する」か「もう一度参加する」。確かめずにすぐ送る。
- 削除は元に戻せないので `ConfirmDialog` で確かめる。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 脱退する・もう一度参加する | その場。ボタンが切り替わってフォーカスが残り、状態の説明が変わる。参加の区画の `StatusMessage`、失敗は同じ場所（`role="alert"`） |
| 削除 | 画面の遷移とトースト。確かめの後、一覧へ移り、削除したことをトーストで知らせる。失敗はダイアログの中 |

### 6. 入口と出口

- 入口: リレーの一覧の行、参加のページの「参加する」。
- 出口: 「リレーの一覧へ戻る」、削除の後の一覧。
