## 設定のメニュー（`/settings` と `/settings/*` の横のメニュー）

### 1. 使う人と頻度

ログインしたすべての利用者が、設定の画面を探して開くために使う。アカウントを作った直後と、何かを変えたくなったときに、ときどき使う。
`md` 未満では `/settings` の画面そのもの、それより広いと設定の各画面の横に出る。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 設定の画面から、パスワードを変える画面を開く | 1 |
| 設定の画面から、ブロックしたアカウントの画面を開く | 1 |
| 設定の画面から、自分の OAuth アプリ（ボット）を登録する画面を開く | 1 |
| 設定の画面から、アカウントのアーカイブを求める画面を開く | 1 |

### 3. 情報の優先順位とまとまり

メニューは、見出しを持つまとまり（`role="group"`、見出しの文言が名前）の並びにする。見出しは `h2` にせず、横の画面の見出しの順に入らない。
すべての項目にアイコンを付け、1 つのまとまりの項目は 7 個までにする（ADR-0110 §5・§6）。

1. プロフィールとコミュニティ: プロフィール・バッジとサポーターの一覧・あなたのカスタム絵文字（権限のある人）・招待（招待を作れる人）・サポーターのプラン（サポーターの制度が有効なとき）
2. 表示と通知: 表示・投稿・タイムライン・通知・通話の履歴（通話が有効なとき）
3. つながり: フォローリクエスト（承認を待つ件数のバッジ。0 件ではバッジを出さない）・ブロックしたアカウント・ミュートしたアカウント・ミュートしたドメイン
4. セキュリティ: パスワード・二要素認証・パスキー・連携したアカウント
5. アプリ: 認可したアプリ・あなたのアプリ（自分で登録した OAuth アプリ）
6. アカウントとデータ: アカウントの状態・別名・アカウントの移転・インポートとエクスポート・古い投稿の自動削除・アーカイブと削除

メニューの下に、線で分けて、サーバーの状態のページへのリンク（サーバーにあるとき）を置く。

### 4. 主な操作と保存の仕方

主な操作は、設定の画面を開くこと。メニューは何も保存しない。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 項目を押す | 画面の遷移。その項目が `aria-current="page"` になる |

### 6. 入口と出口

ナビゲーションの「設定」から来る。項目を押して設定の各画面へ行き、各画面からはこのメニュー（`md` 未満では戻る操作）で別の画面へ移る。
