## リストのタイムライン（`/lists/$id`）

1 つのリストのメンバーの投稿を新しい順に読む画面（ADR-0122）。中身は[ホーム](home.md)と同じ規則（公開範囲・ブロック・ミュート・ドメインのミュート・ブーストの表示）で、作者をメンバーに限ったもの。自分の投稿は入らない。
ホームと同じ投稿のカードの一覧なので、同じ部品と動きで組む。持ち主以外にはリストの存在を含めて見せない（アドレスを開いても「見つかりません」を出す）。

### 1. 使う人と頻度

リストを作った利用者。気になる人だけの投稿を、ホームの流れとは別に読む。日に数回。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| リストの新着を表示して、いちばん新しい投稿を読む | 1 |
| リストのタイムラインの投稿にお気に入りを付ける | 1 |
| メンバーのいないリストを開き、メンバーの管理へ移る | 1 |

新着の表示は、待っている投稿のボタンを 1 つ押す（新着を自動で差し込む設定のときは 0）。お気に入りは投稿の操作の帯の 1 つ。
空のリストを開いた状態から、空の状態の「メンバーを管理」を押す 1 つ。

### 3. 情報の優先順位とまとまり

区画の `h2` は持たない。画面の上に戻るボタンを置く（`staticData.back`。来た画面へ、履歴がなければ `/lists` へ）。リストはナビゲーションの項目の下の画面なので、`h1` はリストの名前にして常に見せる。

1. 見出しの行: リストの名前（`h1`）、メンバーの数、「リストを管理」（`/lists` へ）。
2. 新しい投稿のボタン（待っている投稿があるときだけ、一覧の上に浮かぶ。新着を自動で差し込む設定のときは、先頭から離れている間だけ）
3. 投稿の一覧（`feed`）: ホームと同じ投稿のカード。
4. 一覧の終わり: 続きの読み込み、または失敗（`RegionError`）。

メンバーが 0 人のときは、一覧の代わりに空の状態を出す（「このリストにはまだ誰もいません。フォロー中の人を足すと、その人の投稿がここに並びます。」と「メンバーを管理」）。
メンバーはいるが投稿がまだないときは、別の空の状態（「まだ投稿がありません」）を出す。

### 4. 主な操作と保存の仕方

- 主な操作は、投稿を読むこと。メンバーが 0 人のときだけ、「メンバーを管理」が主なボタンになる。
- 新着はホームと同じ設定に従う: 自動で差し込む設定が偽なら溜めてボタンに件数を出し、真なら先頭にいるときに差し込む（ADR-0077。フォーカスがフィードの中にある間は差し込まない）。
- 投稿への操作は、ホームと同じく押すとすぐ効く。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 新しい投稿のボタンを押す | その場。投稿が一覧の上に入り、フォーカスは `h1` へ移る |
| 投稿にお気に入り・ブースト・ブックマークを付ける | ホームと同じ。その場で形が変わり、失敗はトースト |
| 「メンバーを管理」「リストを管理」を押す | 画面の遷移（`/lists`） |
| 続きの読み込みが失敗する | その場。一覧の終わりに `RegionError` |
| 存在しない・持ち主でないリストを開く | その場。「見つかりません」を出し、`/lists` へのリンクを置く |

### 6. 入口と出口

- 入口: リストの一覧の行の名前。
- 出口: リストの一覧、投稿の詳細、プロフィール（名前とアバター）。
