## ルール（`/admin/rules`）

`manage_rules` を持つ管理者が、サーバーのルール（このサーバーについてのページと通報のフォームに出る）を順に見て並べ替え、廃止したルールを見返し、1 つのルールのページか新しいルールのページへ進む画面（FR-705、[§14](../14-admin.md)）。
ルールの編集と廃止は各ルールのページ（[admin-rule.md](admin-rule.md)）、追加は [admin-rule-new.md](admin-rule-new.md) で行い、この一覧にはフォームもダイアログも置かない。並べ替えは順番の見える一覧に残す。

### 1. 使う人と頻度

- 管理者。サーバーを始めるときにルールをそろえ、その後は必要なときに直す。まれ。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| いちばん上のルールを 1 つ下へ動かす | 2 |
| 廃止したルールを見る | 3 |

手順は、管理のメニューで「ルール」を開く 1 つ、行の「下へ」を押す 1 つ。廃止したルールは、絞り込みを開く 1 つと「廃止」を選ぶ 1 つ。

### 3. 情報の優先順位とまとまり

1. ルールの説明と「ルールを追加する」。
2. 有効なルール（絞り込みで廃止したルール。URL の `?filter=retired`）の表（`RecordTable`）: 有効なルールは文（ルールのページへのリンク）・順番・最後の変更・「上へ」「下へ」。廃止したルールは文と廃止の日時。
   有効なルールは 100 までなので 1 ページにまとめ（動かしたルールがほかのページへ行かない）、廃止したルールは増え続けるので 40 ずつのページにする。

### 4. 主な操作と保存の仕方

- 主な操作は「ルールを追加する」（新しいルールのページへのリンク）。
- 「上へ」「下へ」はすぐ送る。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 上へ・下へ | その場。表の並びが変わり、表の上の `StatusMessage`、フォーカスは動いたルールの名前（行見出し）へ |
| 動かせなかった | その場。表の上の `role="alert"` |
| 絞り込みを変える | その場。表を入れ替える（URL が変わる） |
| 文を押す | 画面の遷移。ルールのページ |
| 「ルールを追加する」を押す | 画面の遷移。新しいルールのページ |

### 6. 入口と出口

- 入口: 管理のモードのメニューの「ルール」、ルールのページと新しいルールのページの「すべてのルール」。
- 出口: ルールのページ、新しいルールのページ、メニューのほかの画面。
