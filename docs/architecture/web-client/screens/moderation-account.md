## アカウントの管理（`/moderation/accounts/{id}`）

`manage_accounts` を持つモデレーターが、1 つのアカウントの状態と履歴を見て、処分を出す・解除する画面（FR-714、FR-703、FR-713、[§14](../14-admin.md)）。
通報の詳細と同じ `TriageLayout` で、処分のフォームを要約のすぐ後（広い画面では右の列の先頭）に置く。

### 1. 使う人と頻度

- 通報から来たモデレーター。アカウントの今の制限と処分の履歴を見て、新しい処分を出す。通報ごとに 1 回まで、1 日に数件。
- アカウントを検索したモデレーター・管理者。処分を解除する、ロールを変える、二要素認証を外す、パスワードの再設定のリンクを出す。週に数回まで。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| quickdeals の今の制限を知る | 3 |
| quickdeals に警告を出す（処分の種類を選び、処分を出す） | 5 |
| quickdeals に効いている処分を解除する（確かめて解除する） | 5 |
| quickdeals のメールアドレスと IP アドレスを見る | 4 |

手順は、アカウントの検索から数える。ユーザー名を入れる 1 つ、検索する 1 つ、結果のアカウントを開く 1 つ。今の制限は要約のバッジで開いてすぐ読める。
処分は、種類を選ぶ 1 つと「処分する」の 1 つ（BAN と投稿の削除は確かめのダイアログの 1 つを足す）。解除は「解除する」とダイアログの確定の 2 つ。

### 3. 情報の優先順位とまとまり

1. アカウント（要約）: アバター・名前・ハンドル、状態・サーバー・作成日時、ローカルなら登録とロール。その下の「制限」（`h3`）に、今の制限の `StatusBadge`。
2. 処分する（判断）: 処分のフォーム。各種類に `SeverityMark`（10 段階の重さ、取り消せないものには「取り消せません」）。
3. アカウントへの処分（証拠）: 新しい順の処分と、効いている処分の「解除する」。
4. アカウントへの通報（証拠）。
5. ロール（`manage_roles`、ローカル）、メールの配信、二要素認証、パスワードのリセット（`manage_login_recovery`）、メールアドレスと IP アドレス（ローカル）、投稿の取り直し（`manage_domains`、リモート）: 道具。

### 4. 主な操作と保存の仕方

- 主な操作は、処分のフォームの「処分する」（画面で唯一の `primary`）。
- 保存は、まとめて保存（処分のフォーム、ロール）と、確かめてから送る操作（解除、二要素認証を外す、再設定のリンク）。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 処分する | その場。フォームの上の `StatusMessage`。制限のバッジと処分の履歴が新しくなる。失敗はフォームの下（BAN はダイアログの中） |
| 処分を解除する | その場。履歴の区画の `StatusMessage`、フォーカスはその行の見出しに残る。失敗はダイアログの中 |
| メールアドレスと IP アドレスを見る | その場。区画に出し、見出しにフォーカスを移す |

### 6. 入口と出口

- 入口: 通報の詳細の「アカウントの管理」、アカウントの検索の結果、異議申し立ての詳細、登録の審査。
- 出口: アカウントの検索、通報の詳細（通報の一覧から）、監査ログ。
