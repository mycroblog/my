## お知らせ（`/announcements/$id`）

このサーバーの運営からのお知らせを 1 つ読む画面（FR-726、ADR-0125、[ADR-0130](../../../adr/0130-announcement-page.md)）。通知や Web Push や右帯から、目的のお知らせだけをすぐ読むためにある。
一覧に出るお知らせ（公開中で見え始めたもの。期間の終わったものを含む）を読める。取り下げられたお知らせは読めない。

### 1. 使う人と頻度

ログインしたすべての利用者。お知らせの通知・Web Push・右帯のタイトル・[お知らせの一覧](announcements.md)のタイトルから来る。多くは月に数回。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 右帯（`xl` 以上）のお知らせの区画から、未読のお知らせを開いて読む | 1 |

右帯の区画のタイトルを押す 1 つで、このページが開いて既読になる。

### 3. 情報の優先順位とまとまり

画面の `h1` はお知らせのタイトル（プレーンテキスト。`dir="auto"`）で、文書のタイトルもこれになる。見出しの前に戻るボタンを置く。区画の見出し（`h2`）は置かない。

1. お知らせ（`article`）: 状態の印と公開の日付、本文（サーバーが無害化した Markdown）、期間の終わり、未読のときは「既読にする」。
   - 今見えているお知らせ: 未読には「未読」の印（文字で言う。色だけにしない）。既読には印を付けない。
   - 期間の終わったお知らせ: 「終了」の印と終わった日を出す。既読にする操作は持たない。
2. 「すべてのお知らせ」（一覧へのリンク）

見つからないとき（取り下げられた、または下書き・始まる前・不明なアドレス。区別しない）は、`h1` を「お知らせが見つかりません」にして、取り下げられたかアドレスのお知らせがないことを言う 1 文と「すべてのお知らせ」を出す。

### 4. 主な操作と保存の仕方

- 主な操作は、お知らせを読むこと。
- 保存は、すぐ保存だけ。開くと、未読で期間の中のお知らせを 1 回既読にする（開いた経路は区別しない）。それが失敗したときのために「既読にする」を残す。取り消す操作は置かない。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 開く | 画面の遷移。フォーカスは `h1`（最初に開いたページはブラウザのまま）。既読になると「未読」の印と「既読にする」が消え、ナビゲーションと右帯の未読の数が減る。失敗の理由はお知らせの上 |
| 既読にする | その場。「未読」の印と押したボタンが消え、フォーカスが `h1` に移り、読み上げる。ナビゲーションと右帯の未読の数が減る。失敗の理由はお知らせの上 |
| 読み込みが失敗する | その場。お知らせの位置に `RegionError`（何が起きたか・理由・もう一度試す）。`h1` は「お知らせ」 |
| 見ている間に取り下げられる | その場。ストリームで知り、読み直して、見つからないときの表示に変わる |

### 6. 入口と出口

- 入口: お知らせの通知（通知の一覧と Web Push）。右帯のお知らせの区画のタイトル。[お知らせの一覧](announcements.md)のタイトル。共有されたアドレス。ログインしていないと、ログインの画面へ移り、終えるとここに戻る。
- 出口: 戻るボタン（履歴がなければお知らせの一覧）。「すべてのお知らせ」。本文の中のリンク。ナビゲーションのほかの項目。
