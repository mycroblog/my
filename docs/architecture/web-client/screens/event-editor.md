## イベントのエディタ（`/events/new`・`/events/{id}/edit`）

イベントの題名・説明・日時（または日程の候補）とタイムゾーン・場所・場所を見られる人・公開範囲・定員を書き、まとめて保存する画面（ADR-0161 §4〜§7、§10）。
新しいイベントは一覧の「イベントを作成」から、既存のイベントはその画面の「イベントを編集」（主催者と共同主催者だけ）から開く。

### 1. 使う人と頻度

- イベントを作る利用者。題名と日時を決め、場所を足す。月に数回。
- 主催者と共同主催者。日時や場所を直す。イベントのたびに数回。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 題名と日時を決めて、イベントを作る | 4 |
| オンラインのリンクを添えて、イベントを作る | 7 |
| 2 つの候補の日時を出して、イベントを作る | 7 |

作るのは、題名・開始・終了の入力の 3 つと「イベントを作成」の 1 つ。リンクを添えるときは、「オンラインのリンク」を選ぶ 1 つ、名前と URL の入力の 2 つが加わる。
候補で作るのは、題名の入力の 1 つ、「候補の日時を出して答えてもらう」を選ぶ 1 つ、2 つの候補の開始と終了の入力の 4 つ、「イベントを作成」の 1 つ。

### 3. 情報の優先順位とまとまり

区画は見出しの代わりに `fieldset` の凡例で分け、次の順に並べる。どの区画にも新しい種類の場所（通話のルーム・日程の候補）を足せるよう、場所は種類ごとのまとまりにする。

1. イベントについて: 題名（必須、1 行で 100 文字まで）、説明（3,000 文字まで、残りの文字数。プレーンテキストで URL がリンクになること）。
2. 日時: イベントのタイムゾーン（設定の画面と同じ、表示の言語の名前と UTC との差の一覧。既定は利用者のタイムゾーン）、開始と終了（`datetime-local`。値はイベントのタイムゾーンの時刻で、欄の説明に「{地名} のタイムゾーンの時刻」）。
   タイムゾーンを変えても入力した時刻（壁時計）はそのまま。既定のタイムゾーンは、利用者が選ぶまで利用者の設定に従う（設定が画面の後から届いても）。
   新しいイベントでは、その上に「日時の決め方」（今決める（既定）/ 候補の日時を出して答えてもらう）。候補を選ぶと、開始と終了の代わりに候補ごとの凡例「候補 {n}」の区画（開始と終了、2 つ目からは「外す」）が並び、
   「候補の日時を足す」で 20 個まで足す（最初は 2 つ）。候補はイベントの画面で答えを集め、そこで日時を決める。候補の追加・取り下げ・確定はイベントの画面で行い、エディタでは変えない。
   日程の調整中のイベントは、日時を入れると日時が決まって候補からの選択が終わることを言い、空のままなら調整を続ける。
3. 場所: 「現地で集まる」（場所の名前・住所・地図のリンク）と「オンラインのリンク」（名前と URL）をチェックボックスで足す。リンクはこのサーバーの外へ出るもので、サーバーは取りに行かないことを言う。
   通話がオンで、利用者がルームを開ける（または通話の場所がすでにある）ときは「通話のルーム」のチェックボックス（開始の時刻にイベントが見える人のためのルームが開くこと）と、選ぶと「許可なしで話せる人」
   （参加した全員 / ホストのフォロワー / ホストがフォローしている人 / ホストと相互フォロー / ホストが許可した人だけ（既定））を足す。通話を出さないときは、ある通話の場所を変えず「そのまま残ります」と言う（変更は場所をまとめて送るので、残す場所を送り直す）。
   その下に「場所とリンクを見られる人」（承認した参加者だけ（既定）/ イベントが見える全員）。
4. 参加できる人: 「イベントを見られる人」（このサーバーの全員 / 主催者のフォロワー / 主催者がフォローしている人 / 主催者と相互フォロー / 招待した人だけ）。共同主催者には無効にし、主催者だけが変えられることを言う。定員（任意、0 か空は上限なし、10,000 まで）。
5. 送信の帯（`FormActionBar`）: 「イベントを作成」/「保存」と「キャンセル」（一覧かイベントの画面へ戻る）。サーバーの拒否の理由はその上に出す。

### 4. 主な操作と保存の仕方

- 主な操作は送信（「イベントを作成」/「保存」）。まとめて保存で、変更したものだけを送る（場所はどれかが変われば全部）。
- 送る前に確かめる: 題名、開始と終了（開始は今より後、終了は開始より後で 7 日まで）、各候補の開始と終了（同じ規則で、同じ日時の候補は 1 つ）、定員、場所の名前と URL（`http` / `https`）。最初に失敗した欄にフォーカスを移し、欄の下に理由を出す。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| イベントを作成 / 保存 | ボタンが待ちを示し、成功すると読み上げてイベントの画面へ遷移する。欄の誤りは欄の下、サーバーの拒否（作れない利用者・通話を使えない・回数の上限）は送信の帯の上 |
| 候補の日時を足す / 外す | その場。候補の区画が加わる / 消える |
| キャンセル | 画面の遷移（一覧かイベントの画面）。下書きは残さない |

### 6. 入口と出口

- 入口: イベントの一覧の「イベントを作成」、イベントの画面の「イベントを編集」。
- 出口: イベントの画面（保存の後）、一覧かイベントの画面（キャンセル）。見えないイベント、主催していないイベント、中止したイベントの編集の画面は、変えられないことと戻るリンクだけを出す。
