## プロフィール（`/@{acct}`）

1 つのアカウントが誰かを読み、その人との関係を決める画面（FR-204、FR-205、FR-301〜FR-303）。このサーバーとほかのサーバーのアカウントの両方を出す。
ログインしていなくても読め、そのときはフォローの代わりにログインへのリンクを出す。

### 1. 使う人と頻度

- ログインした利用者が、投稿・通知・検索・フォローの一覧から来て、その人をフォローするか決める。毎日数回。
- 自分のプロフィールを確かめる利用者。ときどき。
- ログインしていない人が、共有されたリンクから来る。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| ほかの人をフォローする | 1 |
| フォローをやめる | 2 |
| ほかの人をミュートする | 2 |
| ほかの人の新しい投稿を通知で受け取る | 1 |
| フォロー中の人をリストに入れる | 3 |
| フォロワーの一覧を開く | 1 |

フォローをやめるのは、「フォロー中」を押す 1 つと、確かめのダイアログの 1 つ。ミュートは、「その他」のメニューを開く 1 つと、項目の 1 つ。
新しい投稿の通知は、見出しのベルのボタンを押す 1 つ（ほかのサーバーの相手は、先にフォローが承認されている必要がある）。
リストに入れるのは、「その他」のメニューを開く 1 つ、「リストに追加」を選ぶ 1 つ、リストのチェックを入れる 1 つ（リストがまだないときは、リストの一覧への案内を出す）。
通報は通報のダイアログの手順（カテゴリ・投稿・コメント）を通るので、ここでは数えない。

### 3. 情報の優先順位とまとまり

見出しの区画（`ProfileHeader`）に、要約を先に置く。プロフィールはナビゲーションの項目ではない（タイムラインや通知の名前から開く）ので、
画面の上に戻るボタンを置く（`staticData.back`。来た画面へ、履歴がなければホームへ）。

1. **見出しの区画**: ヘッダー画像・アイコン・名前（`h1`）・ハンドル・役割のバッジ、関係の印（「フォローされています」「フォローのリクエストが来ています」「ミュート中」「承認制」「ボット」）、
   フォローのボタン、新しい投稿の通知を切り替えるベルのボタン、「その他」のメニュー（リストに追加・ミュート・ブロック・通報）、プロフィールの文・補足の項目・参加した日・フォローとフォロワーの数（それぞれの一覧へのリンク）。
2. 移転の知らせ（移転したアカウントだけ）。
3. この人がいる音声チャットのルーム（あるときだけ）。
4. **投稿**: タブ（投稿・返信を含む・ブーストなし）。投稿のタブは固定した投稿から始める。

### 4. 主な操作と保存の仕方

- 主な操作は、フォローのボタン（`@my/ui` の `FollowButton`）。フォローしていないときだけ塗った主な見た目にし、見出しの区画で唯一の主なボタンにする。
  フォロー中・リクエスト中・ブロック中は、それぞれのアイコン付きの静かな見た目（枠線）にする。押すとやめる（確かめてから）ので、押せることは保ち、主な操作より軽く見せる。
- 新しい投稿の通知のベル（ADR-0123）は、アイコンだけのトグルボタン（`IconToggleButton`。名前とツールチップは「新しい投稿を通知」で、オンとオフで変えない）。
  オンの間はベルを塗りの形にし、状態は形と `aria-pressed` が伝える（色だけに頼らない）。相手には知らせない。
  - このサーバーの相手は、フォローの有無を問わず押せる。
  - ほかのサーバーの相手は、フォローが承認されている間だけ押せる。フォローしていない（承認待ちを含む）ときは押せない状態で出し、ボタンの下の行に「フォローすると新しい投稿を通知できます。」と出す。この行はボタンの説明（`aria-describedby`）にもなる（押せないボタンはツールチップを出さないため）。
  - ブロック中の相手と、このサーバーがほかのサーバーをフォローできない間のほかのサーバーの相手（フォローしていないとき）には出さない。
  - フォローの一覧と通知の行のフォローのボタンには付けない（プロフィールだけ）。
- 関係を読み込んでいる間は、ボタンと同じ大きさの場所を取って待つ（ボタンを消さない。読み込みが終わっても並びが動かない）。
- 保存は、すぐ保存（フォロー・新しい投稿の通知・ミュート・ブロックは押すとすぐ送る）。フォローをやめる・リクエストを取り消す・ブロックとその解除は、確かめのダイアログを通る。

- 「リストに追加」は、自分が承認済みでフォローしている相手のプロフィールにだけ出す（自分・フォローしていない人・リクエスト中の人には出さない。ADR-0122）。
  選ぶと、自分のリストを並べたダイアログ（`Dialog`）を開き、リストごとに `Checkbox`（入っているリストは入れた状態）を置く。チェックの入れ外しはすぐ保存し、閉じるボタンだけがある。
  リストが 50 個で上限に達しているときは作れないことを言い、1,000 メンバーのリストのチェックは入れられない状態にして理由を添える。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| フォローする | その場。ボタンが処理中になり、塗りの見た目から「フォロー中」（承認制なら「リクエスト中」）の静かな見た目に色の移り変わり（`duration-fast`）で変わる。フォーカスはボタンに残り、結果を読み上げる（`useNotice` の `inPlace`）。失敗はトースト |
| フォローをやめる・ブロック・解除 | 確かめのダイアログの後、その場。ボタンの見た目と文言が変わる。失敗はトースト |
| ミュート・解除 | その場。関係の印に「ミュート中」が出入りし、結果を読み上げる。失敗はトースト |
| ベル（新しい投稿の通知）を押す | その場。ベルが塗りの形（オン）か線の形（オフ）にすぐ変わり、フォーカスはボタンに残り、結果を読み上げる（`useNotice` の `inPlace`）。失敗はトーストで、ベルは元の形に戻る |
| リストに追加・外す | ダイアログの中のその場。チェックが処理中を経て入れ外しされ、フォーカスはそのチェックに残り、「⁦友人⁩ に追加しました」「⁦友人⁩ から外しました」を読み上げる。失敗はチェックの隣に理由を出し、チェックを元に戻す |
| 通報 | 通報のダイアログ。手順の位置を文言と区切りの形（`Stepper`）で示し、送ると完了の手順を出す |

### 6. 入口と出口

- 入口: 投稿の名前とアイコン、通知、検索の結果、フォローとフォロワーの一覧の行、メンションのリンク、共有されたリンク。
- 出口: フォローとフォロワーの一覧、リストの一覧（「リストに追加」のダイアログの「リストを管理」）、投稿の詳細、自分のプロフィールなら設定のプロフィール。
