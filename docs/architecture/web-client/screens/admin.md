## 管理のトップ（`/admin`）

管理者が、サーバーがうまく動いているかを開いてすぐ知る画面（ADR-0058、[§14](../14-admin.md)）。
管理のモードのメニューの複製ではなく、状態の要約を置く。各画面へはメニューから行く。保存する操作はない。

### 1. 使う人と頻度

- ジョブのキューとエラーを見る管理者（`manage_jobs`・`manage_errors`）。失敗したジョブ・キューの滞留・未解決のエラーがないかを確かめる。1 日に 1 回から数回。
- それ以外の管理の権限だけを持つ管理者。メニューから画面を開く。この画面にはほとんど来ない。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 失敗したジョブ・キューの待ち時間・未解決のエラーがあるかを知る | 1 |
| 失敗したジョブの一覧を開く | 2 |
| 未解決のエラーの一覧を開く | 2 |

手順は、ナビゲーションの「管理」を開く 1 つ、タイルを押す 1 つ。

### 3. 情報の優先順位とまとまり

1. サーバーの状態: 閲覧者のロールが見られるものの `StatTile`。タイル全体がその画面へのリンクで、注意が要るときは警告のアイコンと言葉の印を持つ。
   - 失敗したジョブ（`manage_jobs`）: `dead` のジョブの数。1 件以上で危険の印「再実行が必要」。失敗したジョブの一覧（`/admin/jobs?state=dead`）へ。
   - ジョブの最長の待ち時間（`manage_jobs`）: 最も古い待ちのジョブが待っている長さ（分・時間・日）。待ちがなければ「待ちなし」。15 分で注意、1 時間で危険の印「滞留」。ジョブの画面へ。
   - 未解決のエラー（`manage_errors`）: 未解決のエラーのグループの数（最初のページより多ければ「N+」）。1 件以上で注意の印「確認が必要」。エラーの画面へ。
   - 数を読み込む間は「読み込み中」、読めなかったときは「読み込めませんでした」をタイルの値に出す。

使える画面が 1 つもないロールには理由を `EmptyState` で出し、画面はあるが上の権限のどれもないロールには、メニューから画面を開くように案内する。

### 4. 主な操作と保存の仕方

- 主な操作は、注意の印のあるタイルを開くこと。
- 保存する操作はない。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| タイルを押す | 画面の遷移。そのタイルの画面 |

### 6. 入口と出口

- 入口: アプリのナビゲーションの「管理」、管理のモードのメニューの「概要」。
- 出口: ジョブの画面、エラーの画面、メニューのほかの画面。「アプリに戻る」。
