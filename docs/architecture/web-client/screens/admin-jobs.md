## ジョブのキュー（`/admin/jobs`）

`manage_jobs` を持つ管理者が、ジョブのキューが滞っていないか、失敗したジョブがないかを知る画面の最初のページ（ADR-0004、[§14](../14-admin.md)）。
数は `StatTile` で出し（ADR-0110）、ジョブそのものは次のページ（[ジョブの一覧](admin-jobs-list.md)）に置く。`h1` の下の `LocalNav` で「キューの状態」と「ジョブの一覧」を行き来する。

### 1. 使う人と頻度

- 管理者。管理のトップのタイル（ジョブの最長の待ち時間）とメニューの「ジョブ」から来る。1 日に 1 回から数回、問題があるときはその都度。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| キューが滞っていないか（最長の待ち時間）を知る | 1 |
| 失敗したジョブがいくつあるかを知る | 1 |
| どの型のジョブが待たされているかを知る | 1 |

手順は、管理のトップのタイルかメニューの「ジョブ」で画面を開く 1 つ。どれも開いただけで読める。

### 3. 情報の優先順位とまとまり

1. キューの状態: 最長の待ち時間（15 分で注意、1 時間で危険の印「滞留」）と、待ち・実行中・リトライ待ち・失敗の件数の `StatTile`。状態のタイルはジョブの一覧のその状態（`/admin/jobs/list?state=…`）へのリンクで、失敗が 1 件以上なら危険の印「再実行が必要」。
2. キューの種類と、型ごとの状態ごとの件数と待ち時間。

一覧できないキュー（Cloud Tasks）では、失敗のタイルだけを出し、ほかは一覧できない理由を書く。

### 4. 主な操作と保存の仕方

- 主な操作はない（読むページ）。タイルからジョブの一覧へ進む。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 状態のタイルを押す | 画面の遷移。ジョブの一覧のその状態 |
| `LocalNav` の「ジョブの一覧」 | 画面の遷移。ジョブの一覧（未完了） |

### 6. 入口と出口

- 入口: 管理のトップのタイル「ジョブの最長の待ち時間」、管理のモードのメニューの「ジョブ」、ジョブの一覧の `LocalNav`。
- 出口: [ジョブの一覧](admin-jobs-list.md)、メニューのほかの画面。
