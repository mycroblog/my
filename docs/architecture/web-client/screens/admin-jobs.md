## ジョブのキュー（`/admin/jobs`）

`manage_jobs` を持つ管理者が、ジョブのキューが滞っていないか、失敗したジョブがないかを知り、失敗したジョブを再実行する画面（ADR-0064、[§14](../14-admin.md)）。
数は `StatTile` で先に出し（ADR-0113）、一覧はタブで状態ごとに分ける。タブは URL に置く。

### 1. 使う人と頻度

- 管理者。管理のトップのタイル（失敗したジョブ・ジョブの最長の待ち時間）から来る。1 日に 1 回から数回、問題があるときはその都度。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| キューが滞っていないか（最長の待ち時間）を知る | 1 |
| 失敗したジョブがいくつあるかを知る | 1 |
| 失敗したジョブを 1 つ再実行する | 3 |
| 失敗したジョブが失敗した理由を読む | 2 |

手順は、管理のトップのタイルかメニューで画面を開く 1 つ、失敗のタイルかタブを押す 1 つ、「再実行」を押す 1 つ。数を知る作業は画面を開いただけで済む。

### 3. 情報の優先順位とまとまり

1. キューの状態: 最長の待ち時間（15 分で注意、1 時間で危険の印「滞留」）と、待ち・実行中・リトライ待ち・失敗の件数の `StatTile`。状態のタイルはそのタブへのリンクで、失敗が 1 件以上なら危険の印「再実行が必要」。その下にキューの種類と型ごとの件数。
2. ジョブの一覧: 「未完了」・「待ち」・「実行中」・「リトライ待ち」・「失敗」のタブ（名前の後に件数の `Badge`）と、選んだ状態のジョブ。各ジョブは最後のエラー・ペイロード・試行の履歴（disclosure）を持つ。

一覧できないキュー（Cloud Tasks・SQS）では、失敗のタイルと失敗のタブの件数だけを出し、ほかは一覧できない理由を書く。

### 4. 主な操作と保存の仕方

- 主な操作は、失敗したジョブの「再実行」。
- 確かめずにすぐ送る（再実行は何も壊さない）。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| タイルを押す | その場。そのタブを選ぶ（URL が変わる） |
| タブを選ぶ | その場。そのタブの一覧（URL が変わる） |
| 再実行 | その場。ジョブが一覧から消え、フォーカスは次のジョブのボタンへ。結果はトースト |
| 試行の履歴 | その場。disclosure を開いて読む |

### 6. 入口と出口

- 入口: 管理のトップのタイル、管理のモードのメニューの「ジョブ」。
- 出口: メニューのほかの画面。
