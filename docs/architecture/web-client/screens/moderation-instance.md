## 連合先のサーバー（`/moderation/instances/{domain}`）

`manage_domains` を持つ管理者が、1 つの連合先のサーバーの状態（[federation.md §7.3](../../federation.md)）と、このサーバーがそこへ送ったものとその応答（`GET /admin/instances/{domain}/deliveries`）を読み、
止まった配送を再開するページ（[§14](../14-admin.md)）。

### 1. 使う人と頻度

管理者（`manage_domains`）。利用者から「投稿やフォローが相手のサーバーに届かない」と知らされたとき（連合の不具合の報告のほとんどが、まずこの問いになる）と、配送が止まったサーバーを再開するとき。週に数回より少ない。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| アクティビティがサーバーに届いたかを確かめる | 1 |
| 伏せた配送の送信者・アクティビティの ID・受信箱を表示する | 1 |
| このサーバーのアカウントの配送に絞り込む | 2 |
| 配送を再開する | 1 |

手順は、ページを開いたところから数える。届いたかは、配送の区画の新しい順の一覧で、種類・日時と試行の結果・状態コードを読む 1 つ。表示は伏せた配送の「伏せた項目を表示」を押す 1 つ。
絞り込みは「このサーバーのアカウント」にユーザー名を入れ、「絞り込む」を押す 2 つ。アクティビティの ID での絞り込みも同じ 2 つ。

### 3. 情報の優先順位とまとまり

`h1` はドメイン（`DomainName`）で、その下に「連合先のサーバーに戻る」のリンクを置く。

1. 状態（見出しのないカード）: 状態・その状態になった日時・理由（最新の `instance_availability_events`）・失敗した日数・最後に失敗した日・最後に配送を再開した日時と、失敗の日数があるか停止中なら「配送を再開する」とその説明。
2. 配送（`h2`）: 説明（新しい順で、試行は 30 日残り、アクティビティの中身は出さない）、絞り込みのフォーム（`role="search"`）、配送の一覧と「さらに表示」。
   - 絞り込みは「アクティビティの ID」と「このサーバーのアカウント」（ユーザー名。ドメイン付きはフォームの検証で断る）の 2 つの欄。アカウントの欄の説明が、アカウントで絞り込むたびに監査ログに記録されることを、送る前に言う。アクティビティの ID の欄は記録されないので言わない。
     絞り込みはページの state に置き、URL に置かない（S3 の例外）。アカウントでの絞り込みは実行のたびに監査ログに残るので、リンクやリロードからではなく、管理者が送ったときだけ実行する。同じ理由で、アカウントでの絞り込みの結果はひとりでに取り直さない。
     アカウントはユーザー名を `GET /accounts/lookup` で ID に直してから `account_id` で送る。知らないユーザー名は、一覧の代わりの `RegionError` でそう言う。
   - 配送は 1 件ずつ見出し（`h3`、アクティビティの種類）と記録の日時、送信者（`@username`、削除されたアカウントはそう言う）・受信箱（共有受信箱は注記付き）・アクティビティの ID・アクティビティの記録の日時の説明リスト、試行の一覧（`h4`「試行」、古い順。結果・日時・状態コード・署名の方式・エラー）。
   - 伏せた配送（`mask` がある）は、送信者・アクティビティの ID・個人の受信箱を「非表示」とし、なぜ伏せたか（公開範囲の区分か、フォロワーを承認制にしたアカウントのフォローか）を文で言い、「伏せた項目を表示」と、表示が監査ログに記録されることの説明を置く。
3. モデレーション（`h2`）: そのドメインのドメインへの処分の画面（`/moderation/domain-actions?domain=…`）へのリンク。
4. 投稿の取り直し（`h2`）: [§14](../14-admin.md) の「投稿の取り直し」。
5. 履歴（`h2`）: 停止と再開の新しい順の `RecordTable`（出来事・日時・理由）。

### 4. 主な操作と保存の仕方

- 主な操作は「配送を再開する」（失敗の日数があるか停止中のときだけ）。すぐ保存で、確かめない。
- 「伏せた項目を表示」はその配送の伏せた値を `POST /admin/instances/{domain}/deliveries/{id}/reveal` で読む。答えはその配送の mutation にだけ持ち、キャッシュしない（絞り込みを変えるかページを離れると、また伏せる）。成功したら監査ログのキャッシュを無効にする。
- 何も変えない操作（読む・絞り込む）は保存を持たない。アクティビティの中身は API が返さず、どこにも出さない。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 配送を再開する | その場。状態が「配送中」になり、ボタンがなくなる。一覧と履歴を無効にし、結果を知らせる。失敗はトースト（`danger`）で、状態とボタンを残す |
| 伏せた項目を表示 | その場。値が出てボタンがなくなるので、フォーカスはその配送の見出しへ移り、`StatusMessage`（`role="status"`）が表示したことと監査ログに記録されたことを言う。失敗はトースト（`danger`）で、伏せたままボタンを残す |
| 絞り込む | その場。一覧を最初のページから読み直す（読み込み中は `Spinner`、失敗は `RegionError` ともう一度試す）。合うものがなければ空の状態。「絞り込みを解除」で欄を空にしてすべての配送に戻る |
| さらに表示 | その場。続きのページを一覧の下に足す。失敗は一覧の下の `RegionError` で、押せばまた試す |
| 「ドメインへの処分」を押す | 画面の遷移。そのドメインのドメインへの処分の一覧へ |
| 「連合先のサーバーに戻る」を押す | 画面の遷移。連合先のサーバーの一覧へ |

### 6. 入口と出口

- 入口: 連合先のサーバーの一覧（`/moderation/instances`）の行のドメインのリンクと、一覧の上の「サーバーを開く」（ドメイン・ハンドル・URL。配送に失敗していないサーバーは一覧に出ないので、届いたかを確かめるときはここから開く）。
  リモートアカウントの管理のページと通報の対象のリモートアカウントの「アカウントのサーバーを開く」、監査ログのドメインの項目の「サーバーのページを開く」。URL を直接開いてもよい。
- 出口: 一覧と、ドメインへの処分の一覧。失敗のないサーバーも「配送中」として開ける。ホスト名でない値は `RouteError`、権限がなければ `AdminError` が足りない権限を示す。
