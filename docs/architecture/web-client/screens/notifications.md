## 通知（`/notifications`）

自分への反応（フォロー・メンション・ブースト・お気に入り・リアクション・引用）と、サーバーからの知らせを新しい順に読む画面（FR-205）。
上から流し読みして、返事が要るもの（メンション）を拾う画面なので、種類を文の動詞より先に形で示し、メンションにはその場から返信できるようにする。

### 1. 使う人と頻度

ログインしたすべての利用者。毎日、ナビゲーションの未読の数を見て開く。運営の人は、通報や登録の申請の知らせもここで受け取る。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 通知を開き、いちばん新しい通知を読む | 1 |
| メンションだけに絞る | 2 |
| メンションに返信する | 4 |
| フォローしてくれた人をフォローし返す | 2 |
| お気に入りされた自分の投稿を開く | 2 |

通知を開くのはナビゲーションの「通知」の 1 つ。絞り込みはタブの 1 つが増える。メンションへの返信は、通知の行の「返信」・本文の入力・送信の 3 つが増える。
フォローし返すのは、行のフォローのボタンの 1 つが増える。投稿を開くのは、行の投稿の引用（リンク）の 1 つが増える。

### 3. 情報の優先順位とまとまり

画面の `h1`（「通知」）は見た目から隠す（ナビゲーションの今いる項目が示す）。区画の `h2` は持たず、上から次の順に並べる。

1. 種類の絞り込みのタブ（すべて・メンション・フォロー・ブースト・お気に入り）
2. 通知の一覧（`feed`）: 1 行 1 通知（同じ投稿へのお気に入りとブーストは 1 行にまとめる）。各行は、アバターの角の種類の印（お気に入りの星・ブーストの輪・フォローの人・メンションの `@`・リアクションの顔・引用・投票・運営の盾など）、
   何が起きたかの文、時刻、関係する投稿の引用か知らせの中身、次の操作（返信・フォローし返す・行き先のリンク）
3. 一覧の終わり: 続きの読み込み

### 4. 主な操作と保存の仕方

- 主な操作は、通知を読んで、その行の次の操作に進むこと（メンションへの返信、フォローし返す、投稿や知らせの行き先を開く）。
- 保存の操作はない。開いた時点で既読の位置が進む。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| タブを選ぶ | その場。一覧がその種類だけになり、アドレスに残る |
| メンションの「返信」 | 投稿のフォームのシートが、そのメンションへの返信として開く。送った結果はトースト |
| フォローし返す | その場。ボタンがフォロー中に変わる |
| 投稿の引用を押す | 画面の遷移（投稿の詳細） |
| 一覧の読み込みが失敗する | その場。一覧の位置に `RegionError`（何が起きたか・理由・もう一度試す） |

### 6. 入口と出口

- 入口: ナビゲーションの「通知」（未読の数のバッジ付き）。Web Push の通知を押したとき。ログインしていないと、ログインの画面へ移り、終えるとここに戻る。
- 出口: 投稿の詳細、プロフィール、投稿のフォーム（返信）、運営の知らせの行き先（アカウントの状態・通報・登録の申請など）。
