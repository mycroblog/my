## 通知（`/notifications`）

自分への反応（フォロー・メンション・ブースト・お気に入り・リアクション・引用）、通知を選んだ人の新しい投稿と、サーバーからの知らせを新しい順に読む画面（FR-205）。
上から流し読みして、返事が要るもの（メンション）を拾う画面なので、種類を文の動詞より先に形で示し、メンションにはその場から返信できるようにする。

### 1. 使う人と頻度

ログインしたすべての利用者。毎日、ナビゲーションの未読の数を見て開く。運営の人は、通報や登録の申請の知らせもここで受け取る。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 通知を開き、いちばん新しい通知を読む | 1 |
| メンションだけに絞る | 2 |
| 通知を選んだ人の新しい投稿だけに絞る | 2 |
| メンションに返信する | 4 |
| フォローしてくれた人をフォローし返す | 2 |
| お気に入りされた自分の投稿を開く | 2 |
| 案内からこの端末でプッシュ通知を受け取る（ブラウザの許可の確認は数えない） | 2 |
| 保留された通知のリクエストを開く | 2 |

通知を開くのはナビゲーションの「通知」の 1 つ。絞り込みはタブの 1 つが増える。メンションへの返信は、通知の行の「返信」・本文の入力・送信の 3 つが増える。
フォローし返すのは、行のフォローのボタンの 1 つが増える。投稿を開くのは、行の投稿の引用（リンク）の 1 つが増える。
リクエストを開くのは、一覧の上のリクエストの行の 1 つが増える（リクエストがあるときだけ。[ADR-0158](../../../adr/0158-notification-policy.md) §7）。

### 3. 情報の優先順位とまとまり

画面の `h1`（「通知」）は見た目から隠す（ナビゲーションの今いる項目が示す）。区画の `h2` はプッシュ通知の案内だけが持ち、上から次の順に並べる。

0. プッシュ通知の案内（条件を満たすときだけ。[ADR-0086](../../../adr/0086-email-delivery.md)）: `@my/ui` の `Section` の `band`。見出し・説明（あとから通知の設定でもオンにできること）・「オンにする」「閉じる」。モーダルにせず、一覧の操作を妨げない。

   出すのは次をすべて満たすときだけ。読み込み中と取得の失敗では出さないので、オンの人に一瞬出ることはない。
   - サーバーが Web Push を送り（`push_server_key`）、ブラウザに Push API と Service Worker がある
   - サイトの通知をブロックしていない
   - このログイン（トークンの系列）の購読がないと分かっている
   - 通知の設定の行を読み込めた（登録する種類がそのすべての行の種類）
   - このブラウザでこのアカウントが案内を閉じていない（閉じる・設定のスイッチをオフにすると残り、案内かスイッチでオンにすると消える）

   右帯の通知には出さない。
1. 通知のリクエストの行（リクエストが 1 つ以上あるときだけ。[ADR-0158](../../../adr/0158-notification-policy.md) §7）: 通知の振り分け（[通知の設定](settings-notifications.md)）が保留した通知の差出人の数と通知の数を、
   `Callout` の中の 1 つのリンク「{N} 人からの通知のリクエスト」と、その下の説明（「振り分けで保留した通知が {M} 件あります。受け入れるか閉じるまで、ここには出ません」）で出す。リンクは[通知のリクエスト](notifications-requests.md)へ行く。
   数は `GET /notifications/requests/summary` をルートの loader が読み（失敗しても画面は開き、行を出さない）、ストリームの `notification_requests` が答えの数でキャッシュを置き換えるので、再読み込みなしで出たり消えたりする。どのタブでも同じ位置に出す。右帯の通知には出さない。
2. 種類の絞り込みのタブ（すべて・メンション・フォロー・ブースト・お気に入り・新しい投稿）: 各タブは名前の前に、その種類の行の印と同じアイコン（`NotificationKindIcon`。すべては通知のベル）を出し、
   どのタブがどの行を残すかを形でも示す（P3）。アイコンは飾りで、タブの名前は文字が伝える
3. 通知の一覧（`feed`）: 1 行 1 通知（同じ投稿へのお気に入りとブーストは 1 行にまとめる）。各行は、アバターの角の種類の印（お気に入りの星・ブーストの輪・フォローの人・メンションの `@`・リアクションの顔・引用・投票・運営の盾など）、
   何が起きたかの文、時刻、関係する投稿の引用か知らせの中身、次の操作（返信・フォローし返す・行き先のリンク）。
   新しい投稿（`status`。プロフィールのベルで通知を選んだ人の投稿、ADR-0086）の行は、鳴っているベルの印（プロフィールのベルと同じ形）と「〜さんが投稿しました」の文、その投稿の引用（投稿の詳細へのリンク）を出す。返信のボタンは持たない（メンションではないため）。
   お知らせの通知（`announcement`）は差出人がいないので、アバターの代わりにお知らせの印を置き、お知らせのタイトルを見出しの文にする。取り下げられたお知らせと期間の終わったお知らせの通知は出さない（ADR-0125 §2）。
   返信・ブースト・引用の承認の依頼の通知（`reply_request`・`boost_request`・`quote_request`、ADR-0155 §10）は、相手が承認を求めていることを文にし、行き先のリンク「依頼を確かめる」で[承認の依頼](settings-interaction-requests.md)へ行く。
   自動削除の上限の通知（`auto_delete_limit`、ADR-0151 §7）は、上限があなたの投稿に適用されることを文にし、中身に、上限で消え始める日（`time`）と上限の日数を出し、行き先のリンク「削除される投稿を確かめる」で[自動削除の設定](settings-auto-delete.md)（いつから何が消えるかと、その数）へ行く。
   予約投稿の公開の失敗の通知（`scheduled_status_failed`、ADR-0156 §8）は、予約した投稿を公開できなかったことを文にし、中身に、理由と公開する予定だった日時（`time`）と、下書きが残っていて直して予約し直せることを出す。行き先のリンクは持たない
4. 一覧の終わり: 続きの読み込み

最新の通知は、`xl` 以上のタイムラインの画面の右帯にも出す（[アプリの外枠](../09-app-shell.md)）。そこから見ても既読にはならない。

### 4. 主な操作と保存の仕方

- 主な操作は、通知を読んで、その行の次の操作に進むこと（メンションへの返信、フォローし返す、投稿や知らせの行き先を開く）。
- 保存の操作はない。開いた時点で既読の位置が進む。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| タブを選ぶ | その場。一覧がその種類だけになり、アドレスに残る |
| メンションの「返信」 | 投稿のフォームのシートが、そのメンションへの返信として開く。送った結果はトースト |
| フォローし返す | その場。ボタンがフォロー中に変わる |
| 投稿の引用を押す | 画面の遷移（投稿の詳細） |
| お知らせの通知を押す | 画面の遷移（お知らせの一覧のそのお知らせ。見出しにフォーカスが移る） |
| 一覧の読み込みが失敗する | その場。一覧の位置に `RegionError`（何が起きたか・理由・もう一度試す） |
| 案内の「閉じる」 | その場。確かめずに案内が消え、選んでいるタブにフォーカスが移る。購読しない。このブラウザでこのアカウントには案内を出さなくなる |
| 案内の「オンにする」で購読できた | 案内が消え、選んでいるタブにフォーカスが移る。トースト（オンにしたこと。「種類を選ぶ」で通知の設定へ） |
| 案内の「オンにする」でブラウザの確認を選ばずに閉じた、購読か登録に失敗した | その場。案内に理由を出して残り、もう一度押せる |
| 案内の「オンにする」でブラウザにブロックされた | その場。案内に理由と「閉じる」だけが残り、「閉じる」にフォーカスが移る。次に画面を開くと出ない |
| リクエストの行を押す | 画面の遷移（[通知のリクエスト](notifications-requests.md)） |
| 通知が保留される・リクエストが受け入れられるか閉じられる（ほかの端末でも） | その場。リクエストの行の数が変わるか、行が出る・消える。読み上げない（一覧の通知と同じく割り込まない） |

### 6. 入口と出口

- 入口: ナビゲーションの「通知」（未読の数のバッジ付き）。Web Push の通知を押したとき。ログインしていないと、ログインの画面へ移り、終えるとここに戻る。
- 出口: 案内のトーストの「種類を選ぶ」で[通知の設定](settings-notifications.md)。リクエストの行で[通知のリクエスト](notifications-requests.md)。お知らせの通知を押すと、[そのお知らせの画面](announcement.md)。投稿の詳細、プロフィール、投稿のフォーム（返信）、運営の知らせの行き先（アカウントの状態・通報・登録の申請・自動削除の設定など）、承認の依頼。
