## アカウント（`/settings/account`）と無効化の後の画面（`/deactivated`）

自分のデータのアーカイブと、アカウントの無効化・削除をする画面（FR-008、[ADR-0089](../../../adr/0089-account-migration-move.md)）。
無効化を終えると、すべてのセッションが切れるので、ログアウトして `/deactivated` に移る。ログインしていなくても開ける画面で、URL の `deletion_due_at` から削除の日付を出す。
再有効化は、ログインの後にサーバーが描画する状態の画面（`internal/interface/authpages`）で行う。そこにも削除の日付を出す（[account-status.md](account-status.md)）。

### 1. 使う人と頻度

- ログインしたすべての利用者。アーカイブは年に数回。無効化と削除は、離れようとするときの一度だけで、ためらいながら読む。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 設定からデータのアーカイブを頼む | 2 |
| アカウントを無効化し、削除の日付を確かめる | 4 |
| アカウントを削除する | 4 |

無効化は、設定のメニューから「アカウント」を開く 1 つ、「アカウントを無効化…」を押す 1 つ、パスワードかコードを入れる 1 つ、確かめて「無効化する」を押す 1 つ。

### 3. 情報の優先順位とまとまり

1. データのエクスポート: 説明、アーカイブを頼むボタン、アーカイブの一覧（状態・期限・大きさ・ダウンロード）。
2. アカウントの無効化: 説明、無効化の間に起きること（届かないこと、ほかのサーバーで凍結されたように見えること、アプリの認可をやり直すこと）、できないときはその理由、「アカウントを無効化…」。
3. アカウントの削除: 説明、「アカウントを削除…」。

### 4. 主な操作と保存の仕方

- 主な操作は、アーカイブを頼むこと。無効化と削除は取り消しの重い操作なので、`danger` のボタンで離して置き、確認のダイアログを通す。
- 無効化のダイアログは、削除の日付（`GET /accounts/deactivation` の `deletion_due_at`）を先に出してから、確認を求める。確認は、パスワードがあればパスワード、なければパスキーか連携先のログインで、二要素認証を使う人は「代わりに認証コードを使う」で切り替えられる。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| アーカイブを頼む | その場（`StatusMessage`）、一覧に増える |
| 無効化を確かめる | 成功は `/deactivated` への遷移（削除の日付・戻り方・ログインへのリンク）。パスワードやコードの誤りはダイアログの中 |
| 無効化ができない（処分・削除の予約中・移転済み・登録の審査中・支援が続いている・最後の管理者・再有効化から 24 時間たっていない） | その場に理由を出し、ボタンを出さない。支援は支援の画面へのリンク、24 時間は次にできる日時を添える |
| 削除を確かめる | 画面の遷移（トップ）。パスワードの誤りはダイアログの中 |

### 6. 入口と出口

- 入口: 設定のメニューの「アカウント」。
- 出口: `/deactivated` からログイン（`/login`）。ログインの後は状態の画面に入り、再有効化か削除を選ぶ。
