## ルール（`/admin/rules/{id}`）

`manage_rules` を持つ管理者が、1 つのルールを確かめ、文と補足を直し、要らなくなったルールを廃止するページ（FR-705、[§14](../14-admin.md)）。
廃止したルールも開ける（通報が ID で挙げ続ける）が、変えられない（`PUT` は 409）ので事実だけを出す。

### 1. 使う人と頻度

- 管理者。ルールの言い回しを直すときと、ルールをやめるとき。まれ。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| ルールに補足を足す | 3 |
| ルールを廃止する | 3 |

手順は、ルールの一覧で文を押す 1 つ、補足を入れる 1 つ、「保存する」を押す 1 つ。廃止は、文を押す 1 つ、「廃止」を押す 1 つ、確かめのダイアログの「廃止」を押す 1 つ。

### 3. 情報の優先順位とまとまり

1. このルールについて: 文・補足・状態（有効か廃止か）・順番（有効なルールだけ）・追加・最後の変更・廃止の日時。
2. ルールを編集する（有効なルールだけ）: 文と補足のフォームと 1 つの「保存する」。
3. ルールを廃止する（有効なルールだけ）: 廃止は元に戻せず、通報はルールを残すことの説明と「廃止」。

### 4. 主な操作と保存の仕方

- 主な操作は「保存する」。
- まとめて保存する（1 つのフォーム、`FormActionBar`）。廃止は確かめてから送る。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 保存する | その場。`FormActionBar` の `role="status"`、「このルールについて」も変わる |
| 保存できなかった | その場。`FormActionBar` の `role="alert"`（入力は残す） |
| 廃止する | その場。フォームと廃止の区画が消え、「このルールについて」の `StatusMessage` に出して、フォーカスはその見出しへ |
| 廃止できなかった | その場。ダイアログの中のエラー |

### 6. 入口と出口

- 入口: ルールの一覧の文、ルールを追加した後。
- 出口: 見出しの下の「すべてのルール」で一覧へ。
