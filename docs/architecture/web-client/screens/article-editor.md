## 記事のエディタ（`/articles/new`、`/articles/{id}/edit`）

記事（[ADR-0160](../../../adr/0160-articles.md)）を書き、公開し、予約し、公開した記事を編集する画面。
投稿のフォーム（[compose.md](compose.md)）とは別の画面で、題・要約・カバー画像・ハッシュタグと Markdown の本文を、サーバーが描画するプレビューの横で書く。
新しい記事は書いている間ずっとサーバーの下書き（[ADR-0156](../../../adr/0156-drafts-and-scheduled-posts.md)）で、どの端末からも下書きの画面（[drafts.md](drafts.md)）から書き継げる。

### 1. 使う人と頻度

ブログや日記のように長い文章を書く利用者。週に一度から月に数度、1 回に数十分書く。途中で止めて、別の端末や別の日に書き継ぐことが多い。
サーバーが記事を書ける人を権限 `create_articles` のロールに限っているとき（`article_authoring` が `permission`）は、その人たちだけが新しい記事を書く。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 題と本文を書いて公開する | 3 |
| 画像を 1 枚本文にドロップして公開する | 4 |
| 本文の一部を太字にする | 2 |
| 記事を予約する | 5 |
| ほかの端末と競合した下書きを、新しい下書きとして保存する | 1 |

手順は、`/articles/new` を開いた状態（投稿のフォームの「記事を書く」から来る 1 つを数えない）から数える。公開は、題の入力・本文の入力・「公開する」の 3 つ。
画像は、ドロップの 1 つを足す（アップロードを待つのは手順に数えない）。太字は、選択と「太字」（または Ctrl+B）の 2 つ。
予約は、題と本文の入力の 2 つに、「予約する」・時刻の入力・ポップオーバーの「予約する」の 3 つ。競合の後は「新しい下書きとして保存」の 1 つ。

### 3. 情報の優先順位とまとまり

画面の `h1`（「新しい記事」、編集では「記事を編集」）がフォームの名前になる。広い列（`wideMain`）で、フォームとプレビューを横に並べ（コンテナの幅が `2xl` から）、狭いときはフォームの下にプレビューを置く。

1. フォーム（見出しなし。`h1` が名前）: 題、要約（500 文字までの残り）、カバー画像（選ぶ・差し替える・外す、説明の欄、処理中・失敗の知らせ）、
   本文の上のボタン（「太字」「リンク」「画像を追加」）、本文（Markdown の `textarea`。画像のファイルをドロップ・貼り付けできる）、ハッシュタグ、言語と公開範囲（`direct` はない。編集では公開範囲を出さない）、
   「センシティブな内容にする」、自動保存の状態と競合の知らせ、送信のバー（「公開する」と「予約する」。編集では「変更を保存」だけ）
2. プレビュー（`h2`「プレビュー」）: 記事のページ（[status.md](status.md)）と同じ見た目で、題・要約（空ならサーバーが本文から作ったもの、とその旨）・カバー・サーバーが描画した本文。
   その下に、本文のバイト数と画像の数をサーバーの上限と並べて出し、超えていれば理由を出す
3. 下書きの画面へのリンク「下書きと予約投稿」（新しい記事だけ）

### 4. 主な操作と保存の仕方

- 主な操作は「公開する」。題と本文がなければ、その欄の誤りと送信のバーで理由を出して送らない（ボタンは無効にしない、G23）。画像のアップロード中も同じ。
- 新しい記事は、書くのを止めて少し経つ（1.5 秒）と、下書きとして自動で保存する（すぐ保存）。最初の保存が `POST /drafts`、次からは読んだ版を `If-Match` にした `PUT /drafts/{id}` で、保存は 1 つずつ順に送る。
  何も書いていない間は保存しない。画面を離れるときに保存していない変更があれば、そのとき保存する。
- 下書きの画面の「編集する」から来た記事は `GET /drafts/{id}` で読み直した版（`ETag`）から始める（`?draft=<id>`）。
- ほかの端末の保存の後の版から保存すると 412 になり、何も上書きしない。自動保存を止め、書いた文章はエディタに残したまま、「新しい下書きとして保存」（`POST /drafts`）で別の下書きにできる。そうすると自動保存が続く。
- 「公開する」は、今の内容を下書きに保存してから `POST /drafts/{id}/publish` で公開する（下書きは公開と同じトランザクションで消え、記事は 1 回だけ公開される）。「予約する」は保存してから `PUT /drafts/{id}/schedule`。
- 公開した記事の編集（`/articles/{id}/edit`、記事の「その他の操作」の「編集」から）は、`GET /statuses/{id}/source` の題・要約・カバー・ハッシュタグ・本文から始め、「変更を保存」で `PUT /articles/{id}` を送る（まとめて保存）。自動保存はしない。
- 本文の画像は、ドロップ・貼り付け・「画像を追加」のどれでも、投稿の添付と同じく位置情報などを落としてから `POST /media` でアップロードし、終わったらカーソルの位置に `![](media:<ID>)` を 1 段落として入れる。
  代替テキストは角かっこの中に書く（本文の説明で知らせる）。サーバーは処理の終わった画像だけを本文に出すので、プレビューは画像の処理が終わると描画し直す。
- プレビューは、本文と要約が 0.5 秒変わらなければ `POST /articles/preview`（保存しない、公開と同じ描画）で作り直し、次の描画が届くまで前の描画を出しておく。
- 「太字」は選択を `**` で囲み（囲まれていれば外す）、「リンク」は選択をリンクの文字にして URL の `https://` を選択する。どちらも本文にフォーカスを戻す。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 書く（新しい記事） | 少し後に送信のバーの上の印が「下書きを保存しています…」から「下書きを保存しました」に変わる。変えると印は消え、次の保存で再び出る |
| 自動保存が失敗する | 印が「下書きを保存できていません」になり、その下に理由と、次の変更でもう一度保存すること |
| 自動保存が競合する | 印が「保存できていません」になり、知らせ（`role="alert"` の `Callout`）と「新しい下書きとして保存」が出る。文章はそのまま |
| 画像をドロップする | 本文の下に「N 枚の画像をアップロードしています…」、終わるとカーソルの位置に画像の Markdown が入り、処理が終わるとプレビューに画像が出る。画像でないファイルは理由を出して入れない |
| 公開する | ボタンが送信中になり、終わると「記事を公開しました」のトーストと記事のページへの遷移。失敗はバーに理由（自動審査の拒否を含む）を出し、画面に残る |
| 予約する → 時刻 → 予約する | 範囲の外はポップオーバーの中で欄の誤り。通れば「<日時> に予約しました」のトーストと下書きの画面への遷移 |
| 変更を保存（編集） | 「記事を更新しました」のトーストと記事のページへの遷移。失敗はバーに理由 |

### 6. 入口と出口

- 入口: 投稿のフォームの「記事を書く」（記事を書ける人だけ）、下書きの画面の記事の下書きの「編集する」、自分の記事の「その他の操作」の「編集」。
  記事を書けない人が `/articles/new` を開くと、書けないことと、公開した記事は編集できることを空の状態で出す。
- 出口: 公開と編集の保存は記事のページへ、予約は下書きの画面へ移る。ページの見出しの戻るボタンで前の画面へ（書いた内容は下書きに残る）。
