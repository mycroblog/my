## 古い投稿の自動削除（`/settings/auto-delete`）

選んだ日数より古い自分の投稿を、サーバーが 1 時間ごとに削除する設定の画面（FR-118）。決まりの全体をまとめて保存する。
サーバーに保持の上限があり、投稿を長く残す権限（`keep_posts_longer`）を持たない利用者には、上限と、上限がこの人の投稿をどう消すかも示す（FR-121、[ADR-0151](../../../adr/0151-auto-delete-server-default-and-maximum.md)）。
登録のときにサーバーの既定から写した値も、ほかの値と同じく自分の設定として出し、既定から来たことは示さない。

### 1. 使う人と頻度

古い投稿を残したくない利用者。始めるときに 1 回設定し、残す条件を見直すときに、年に数回。削除は元に戻せないので、保存の前に条件と、その条件で消える投稿の数を確かめる。
上限のあるサーバーの利用者。上限に縛られたという通知から来て、いつから何が消えるかを確かめ、設定を上限の内に直す。上限が有効になったか厳しくなったときに 1 回。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 設定のメニューから来て、90 日より古い投稿の自動削除を始める | 5 |
| ピン留めした投稿を残すようにする | 3 |
| 自動削除を止める | 3 |
| 保存する前に、メディアのある投稿を残すと消える投稿がいくつ減るかを確かめる | 2 |
| 上限に縛られたとき、いつから上限で消えるかと、その時に消える数を確かめる | 1 |
| 上限に縛られたとき、オフの設定をオンにし、上限の許さないお気に入りの例外を外して保存する | 4 |

手順は、設定のメニューの「古い投稿の自動削除」を開く 1 つ、値を変える数（選択肢を開いて選ぶものは 2 つ）、保存する 1 つ。消える投稿の数は条件を変えるとその場で変わるので、確かめるだけなら保存の手順はない。
上限の作業は、通知の「削除される投稿を確かめる」か設定のメニューから開く 1 つから数える。いつからと消える数は開いたときに上限の区画にある。

### 3. 情報の優先順位とまとまり

画面の先頭に、何が起きるか（削除は元に戻せない、ブーストは消さない）を言う。その後に次の区画を並べる。区画の外に操作を置かない。

0. このサーバーの上限（上限がこの人に効くときだけ）: 投稿を残せる最長の日数と自動削除をオフにできないことの 1 文、このサーバーで残せるもの（許された例外の一覧。ピン留めの数を限るときはその数。ないときは、ないこと）。
   縛られている（保存した設定より上限の方が多く消す）ときは、その下の `Callout` に、上限で消え始める日（`time`。まだ知らせていなければ「まもなく」）、それまでは自分の設定のとおりであること、その後の実効の設定（日数と残るものの一覧）、その時に消える数（実効の設定のプレビュー、図）、設定を上限の内に直せば自分で決め続けられることを出す。
1. 自動削除: 自動で削除するか（`Checkbox`）と、削除する投稿の古さ。
2. 残す投稿: ピン留め・ブックマーク・お気に入りにした投稿・メディアのある投稿・投票のある投稿。
3. 残す公開範囲: 公開範囲ごとのチェックボックス（公開範囲の名前は投稿のフォームと同じ定義を使う）。
4. 反応の多い投稿: ブーストとお気に入りの数のしきい値。
5. この条件で削除される投稿: 上の条件で今消える投稿の数（図。保存の前でも、自動削除がオフでも数える。1,000 件で止めて「1,000+」）と、そのうち古い 3 件。消えるものを、保存の前に形で見せる（ADR-0110 P3）。

最後に、画面の下に固定した送信の帯（`FormActionBar` の `sticky`）を置く。

上限が効く間は、入力を上限の許す範囲に絞る。

- 自動削除のチェックボックスは、オンならオフにできない（無効にして、上限がオンに保つことを説明に書く）。
- 古さの選択肢は上限の日数までで、上限の日数そのものを含む。
- 上限が許さない例外（残す投稿・公開範囲・反応の数）は、外れているなら無効にして、上限で使えないことを説明に書く。
- 保存した値が上限を超えている（オフ、上限より長い日数、許されない例外）ときは、その値を残したまま欄を無効の値（`aria-invalid`）にし、直し方を欄のエラーに書く。直せるように、その欄は操作できる。
- 消える数の区画の説明は、上限を当てて数えていることを言う（サーバーのプレビューは上限を当てて数える）。

### 4. 主な操作と保存の仕方

- 主な操作は「保存する」。
- 保存は、まとめて保存だけ。フォームの中に `Switch` を置かない（§21 の L3 の検査）。
- 保存していない変更があるまま別の画面へ行こうとすると、確かめのダイアログを出す。
- 上限を超える値がある間は送らない。ブラウザの制約検証が送信を止め、最初の印の付いた欄にフォーカスを移す。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 条件を変える | その場（値と、「この条件で削除される投稿」の数と例が変わる。数え直す間は前の数を残す。数えられなければ区画の中に理由） |
| 保存する | その場。送信の帯のボタンの隣に、保存した決まり（「90 日より古い投稿を削除します」か「自動削除はオフです」）か失敗の理由。上限の内に直して保存すると、上限の区画の縛られていることの知らせが消える |
| 上限を超える値のまま保存する | その場。何も送らず、最初の印の付いた欄にフォーカスが移り、欄の下に直し方 |
| サーバーが拒否（`422`） | その場。送信の帯に理由を出し、`detail` が名指す項目の欄の下にも出す。入力は残す |

### 6. 入口と出口

- 入口: 設定のメニューの「アカウントとデータ」のまとまり。上限に縛られたという通知（`auto_delete_limit`）の「削除される投稿を確かめる」。
- 出口: 設定のメニュー。削除はサーバーが後で行い、自分のプロフィールの投稿の一覧から消える。
