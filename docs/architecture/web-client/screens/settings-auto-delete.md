## 古い投稿の自動削除（`/settings/auto-delete`）

選んだ日数より古い自分の投稿を、サーバーが 1 時間ごとに削除する設定の画面（FR-118）。決まりの全体をまとめて保存する。

### 1. 使う人と頻度

古い投稿を残したくない利用者。始めるときに 1 回設定し、残す条件を見直すときに、年に数回。削除は元に戻せないので、保存の前に条件を読み直す。

### 2. 作業

| 作業 | 最短の手順の数 |
| --- | --- |
| 設定のメニューから来て、90 日より古い投稿の自動削除を始める | 5 |
| ピン留めした投稿を残すようにする | 3 |
| 自動削除を止める | 3 |

手順は、設定のメニューの「古い投稿の自動削除」を開く 1 つ、値を変える数（選択肢を開いて選ぶものは 2 つ）、保存する 1 つ。

### 3. 情報の優先順位とまとまり

画面の先頭に、何が起きるか（削除は元に戻せない、ブーストは消さない）を言う。その後に次の区画を並べる。区画の外に操作を置かない。

1. 自動削除: 自動で削除するか（`Checkbox`）と、削除する投稿の古さ。
2. 残す投稿: ピン留め・ブックマーク・お気に入りにした投稿・メディアのある投稿・投票のある投稿。
3. 残す公開範囲: 公開範囲ごとのチェックボックス（公開範囲の名前は投稿のフォームと同じ定義を使う）。
4. 反応の多い投稿: ブーストとお気に入りの数のしきい値。

最後に、画面の下に固定した送信の帯（`FormActionBar` の `sticky`）を置く。

### 4. 主な操作と保存の仕方

- 主な操作は「保存する」。
- 保存は、まとめて保存だけ。フォームの中に `Switch` を置かない（§21 の L3 の検査）。
- 保存していない変更があるまま別の画面へ行こうとすると、確かめのダイアログを出す。

### 5. 操作ごとの結果の出し方

| 操作 | 結果（その場・トースト・画面の遷移） |
| --- | --- |
| 条件を変える | その場（値だけが変わる） |
| 保存する | その場。送信の帯のボタンの隣に、保存した決まり（「90 日より古い投稿を削除します」か「自動削除はオフです」）か失敗の理由 |

### 6. 入口と出口

- 入口: 設定のメニューの「アカウントとデータ」のまとまり。
- 出口: 設定のメニュー。削除はサーバーが後で行い、自分のプロフィールの投稿の一覧から消える。
