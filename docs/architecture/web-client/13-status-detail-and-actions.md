## 13. 投稿の詳細と投稿への操作

`features/status` が投稿のカード（`StatusCard`）と操作、投票、投稿の詳細と編集履歴の画面を受け持つ（FR-106〜109、FR-112、FR-113、FR-116）。タイムラインなどの一覧は、このカードを `index.ts` から使う。

- **アドレス**: 投稿の詳細は `/@{acct}/status/{id}`（`routes/@{$acct}_.status.$id.tsx`、ADR-0018）。`acct` はローカルのアカウントではユーザー名、リモートでは `username@domain` で、読みやすさのためだけにあり、投稿は ID で引く。
  `_` で、プロフィールの画面（`/@{acct}`）のレイアウトの下に入らないようにする。カードの時刻はこのアドレスへのリンクになる（ブーストはブーストされた投稿へ）。
- **公開範囲**: どのカードも、時刻の下に投稿の公開範囲（ADR-0017）を、段階ごとに形の違うアイコンと名前で出す（`@my/ui` の `VisibilityMark`。`PostCard` の `visibility` は必須で、投稿でない通知の行だけが `null` を渡す。色だけに頼らない、G13）。
  名前は `article` の名前の終わり（作者・時刻の後）にも入る。公開範囲の並び・名前・説明は `features/compose` の 1 つの定義（`hooks/visibilityMessages.ts`、`index.ts` から export）を、投稿フォーム・設定・カードが共有する。
- **画面**（[screens/status.md](screens/status.md)）: 見出しは `h1`「投稿」で、その前に戻るボタン（`staticData.back`。ナビゲーションの項目でない画面の共通の形。§9）を置く。その下に返信先の投稿（`h2`「スレッドの前の投稿」、古い順）、投稿そのもの（焦点の投稿）、返信（`h2`「返信」、深さ優先）を並べる。
  - 焦点の投稿は `PostCard` の `highlighted`（`surface-raised` の面と、行頭側の `accent` の線）で区別し、本文を `text-lg` にする。
    `article` の名前は、見えない `label`「開いている投稿」で始め、作者・時刻が続く（スクリーンリーダーと ARIA スナップショットで、スレッドのほかの投稿と名前で区別できる）。
    頭の時刻はほかのカードと同じ相対時刻（G8）で、自分へのリンクはない。本文と操作の列の間の `details` に、省略しない日時（`<time>`）と、0 でない操作の数の文言（「返信 2 件」「ブースト 3 件」「お気に入り 12 件」）を並べる。
  - 返信のつながりは、アバターの列を通る線（`PostCard` の `lineAbove` / `lineBelow`）で示す。並んだ 2 つの投稿の下の方が上の方への返信（`in_reply_to_id`）のときだけ線でつなぐ。
    つながる先が下にあるカードは、狭い幅でも本文をアバターの列の外に置き、線が本文と重ならないようにする。線は飾りで、スレッドの構造は見出しと順序が伝える。
  - スレッドの前の投稿が読み込まれて焦点の投稿の上に入ったら、焦点の投稿を 1 回だけ画面の上端（ページの下に残りが少なければ、届くところ）までスクロールする（描画の前、`useLayoutEffect`。`features/status` の `useRevealOnce`）。
    ルーターのスクロールの復元は同じコミットの後（`onRendered`）で新しい画面を上端に戻すので、そのときはその後にもう一度スクロールする。戻るで復元した位置は動かさない。
    フォーカスは `h1` のまま動かさない（外枠は `h1` に `preventScroll` でフォーカスを移すので、このスクロールを戻さない）。
  ローダーは投稿を待ち、スレッド（`GET /statuses/{id}/context`）は待たずに読み込み始める。スレッドの失敗は返信の区画に `RegionError`（`h3` の何が起きたか・理由・「もう一度試す」）を出し、投稿は表示したままにする（E1）。
  返信がないときは、返信の区画に `EmptyState`（`h3`「まだ返信はありません」）を出し、サインインしていれば、その説明と「返信する」のボタン（`useReply()`）で最初の返信へ導く（G14）。
  見つからない投稿は、ホーム（サインインしていなければランディングページ）へのリンク（`HomeLink`）も出す。
  見えない投稿と存在しない投稿はどちらも 404 で、ルートの `errorComponent` が「投稿が見つかりません」を出す。
- **操作**: 返信（`useReply()`、§12。ボタンはアイコンだけで数を持たない）、会話を読む（一覧のカードだけ。返信が 1 件以上あるとき、返信のボタンの隣に、吹き出しのアイコンと返信の数の、投稿の画面へのリンク `IconButtonLink`「返信 N 件を読む」。N は見せている数と同じ形（Y2）。書くことと読むことを分ける）、ブースト・お気に入り・ブックマークのトグル（`@my/ui` の `IconToggleButton`。名前は状態で変えず `aria-pressed` で示す。数を出している間は、見えている数を名前に含める（「お気に入り、3」。WCAG 2.5.3、Y2。ツールチップは「お気に入り」のまま）。オンのアイコンは塗りつぶしで、色だけに頼らない。押した直後にへこみ（`data-pressed` の `scale-95`、動きを減らす設定では沈んだ塗り）、数は `@my/ui` の `ActionCount` で、変わると新しい数が下から入る）、
  リアクションの選択（後述）、「その他の操作」のメニューの「リンクをコピー」と、自分の投稿だけの「編集」「プロフィールに固定」「削除」、他人の投稿だけの作者への操作と通報（後述）。サインインしていない間は操作を出さない。公開範囲がブーストを許さない投稿（他人のフォロワー限定・ダイレクト）は、ブーストのボタンを無効にする。
- **作者への操作**（FR-301〜FR-303。`hooks/useAuthorActions.ts`）: 他人の投稿の「その他の操作」のメニューは、線で区切って、作者のフォロー・ダイレクトメッセージ・ミュート・ブロックを、通報の前に並べる。ブーストではブーストされた投稿の作者を指す。自分の投稿とサインインしていない間は出さない。
  名前は作者の短いハンドルを含む（「@bob をミュート」。投稿のミュートと読み違えない。ドメインは長くなるので入れず、投稿のカードが全部を見せている）。規則はプロフィールと同じで、`features/relationship` の `useRelationship` と確かめのダイアログ（`RelationshipConfirmDialog`）を共有する。フォローはすぐ送り（鍵のある作者には「フォローをリクエスト」、フォローされていれば「フォローバック」）、リクエスト中は取り消し、フォロー中はフォローをやめ、どちらも確かめる。ほかのサーバーの作者へのフォローは、相手が応じるまでリクエスト中の状態になる。インスタンスがほかのサーバーをフォローしない間（ADR-0006）は新しいフォローを出さない。ミュートはすぐ切り替え、ブロックとブロックの解除は確かめる。ブロック中は、フォローとダイレクトメッセージを出さず、「ブロックを解除」だけを出す。
  - **関係の読み込み**: 投稿は関係を持たないので、メニューが開いたときに読む（`useRelationship` の `enabled`）。一覧の投稿の数だけ要求を送らず、同時に開いたものは `GET /accounts/relationships` の 1 回にまとまり、読んだ関係はキャッシュから出す。読み終わるまで、関係による項目（フォロー・ミュート・ブロック）は関係のない人の言葉のまま無効にして同じ場所に出す（`aria-disabled`）。ダイレクトメッセージは関係を待たない。
    読み込みの失敗では、その 3 つの代わりに、何が起きたか・理由・もう一度試せることを言う 1 つの項目を出し、選ぶと読み直す（メニューは閉じる。開き直しても読み直す）。無効の項目はキーボードで止まれず、失敗を読み上げられないので、失敗は押せる項目にする。サーバーが関係を返さない（アカウントがない、閲覧者をブロックしている）ときは、作者への操作を出さない。
  - **結果**: メニューは閉じて結果の置き場がないので、結果と失敗はトーストで出す（§16 の G24。プロフィールのボタンはその場で切り替わるので読み上げだけ）。ミュートとブロックの後は、投稿の一覧を取り直し、その作者の投稿は一覧から消える。投稿の画面の投稿そのものは出したまま。
  - **ダイレクトメッセージ**: `features/compose` の `useDirectMessage()`（§12）。
- **モデレーターのリンク**: `manage_accounts`（アカウントの管理の画面の権限）を持つ閲覧者には、他人の投稿のメニューの最後に、線で区切って「このアカウントをモデレーションで開く」「この投稿をモデレーションで開く」のリンク（`MenuItem` の `href`）を出す。投稿ごとの画面はなく、後者はアカウントの画面を `?status=<投稿の ID>` で開く（[screens/moderation-account.md](screens/moderation-account.md)）。権限は表示を決めるだけで、サーバーが確かめる。
- **絵文字リアクション**（FR-116、ADR-0051 §10、ADR-0091 §7）: 操作の列の「リアクションする」（アイコンのボタンとツールチップ）が、ポップオーバーに投稿フォームと同じ絵文字のピッカーを開く（`features/emoji` の `ReactionPickerButton`。§12「絵文字のピッカー」）。
  節は同じく よく使う → このサーバーのカスタム絵文字 → Unicode の 9 グループで、検索・節のボタン・肌の色のメニューもそのまま使い、よく使う絵文字と肌の色は投稿フォームと共有する。Unicode 絵文字のデータはボタンにポインタが乗ったとき・フォーカスしたとき・開いたときに読み、届くまではスピナーを出す。
  データはサーバーと同じ `EMOJI_VERSION` から作るので、選べる Unicode 絵文字（肌の色の付いたものも）はすべてサーバーが受け入れる（ADR-0051 §6）。ほかのサーバーのカスタム絵文字は出さない。
  選ぶとポップオーバーを閉じ（フォーカスはボタンに戻る）、選んだ肌の色の絵文字でリアクションする。1 つの投稿のリアクションは 1 つの枠なので、Shift を押しながら選んでも閉じる。
  投稿の下（`PostCard` の `reactions`、本文と操作の列の間）に、絵文字ごとの数を「リアクション」の `group` に並べる。Unicode とこのサーバーのカスタム絵文字は `ToggleButton`（名前は見えている絵文字と数で始まる「{emoji} {数}、この絵文字でリアクション」（WCAG 2.5.3、Y2）、自分のものは `aria-pressed`）で、押すとその絵文字で加わり、もう一度押すと外す。
  ほかのサーバーのカスタム絵文字は、ボタンにせず絵文字と数だけを出す（ADR-0051 §7）。列の終わりの「リアクションした人」は、付けた人の一覧（`GET /statuses/{id}/reactions`、新しい順、各行はプロフィールへのリンクと絵文字。続きは「さらに表示」のボタン）をダイアログで開く。
  お気に入りとリアクションは 1 つの枠（ADR-0051 §6）なので、どちらの操作も `useLikeSlot` の 1 つの mutation の `scope` で順に送り、押した時点でお気に入り・自分のリアクション・それぞれの数をすべての写しで入れ替え、失敗したら押す前の枠に戻してトーストで理由を知らせる。
- **投票**（FR-112）: 投票のある投稿は、本文の下（CW があればその中、添付の前）に投票の区画（`section`「投票」）を出す（`components/StatusPoll.tsx`、`hooks/usePoll.ts`）。
  サインインしていて、まだ回答しておらず、締め切り前なら、単一選択は `RadioGroup`、複数選択は `fieldset` の `Checkbox` で選び、「回答する」で `POST /statuses/{id}/poll/votes` を送る（選ぶまで無効）。
  サーバーの答えを待ち、答えの `poll` で投稿のすべての写しを置き換えてトーストで知らせる（`cacheVoteAnswer`）。断られたら理由をトーストで知らせ、投稿に無効化の印を付けて読み直す（締め切り・編集による投票の差し替え・ほかの端末での回答）。
  それ以外（回答済み・締め切り後・サインインしていない・モデレーションの画面）は、選択肢ごとの割合（数字と、飾りの `aria-hidden` の棒）と、自分が選んだ選択肢の「あなたの回答」を「投票の結果」の一覧に出す。
  作者が締め切りまで票数を隠す投票は、締め切りまでサーバーが選択肢ごとの票数を返さないので、割合と棒を出さずに選択肢だけを並べ、その下に締め切り後に票数が出ることを書く。
  区画の下に投票者数（分からなければ票数）と締め切り（相対時刻。過ぎたら「締め切りました」）、ほかのサーバーの投票ではその集計がそのサーバーの最後に送ったものであることを書く。選択肢は利用者の文なので `dir="auto"` と投稿の `lang` で出す。
- **翻訳**（FR-120、ADR-0148）: 投稿のカードは、操作の帯に「翻訳する」のアイコンのトグルを持ち、訳を出している間は本文の直後に、何が起きたかと戻し方を言う 1 行を出す（`components/StatusCard.tsx`、`components/StatusActions.tsx`、`components/StatusTranslationNote.tsx`、`hooks/useStatusTranslation.ts`）。
  - **出す条件**: 翻訳の手段（`hooks/useTranslator.ts`）があり、投稿が UI の言語でないとき。手段を決めるのは `useTranslator` だけで、手段はサーバー（`POST /statuses/{id}/translation`）とブラウザの内蔵翻訳（`api/browserTranslation.ts`）である。ブラウザで訳せるのは、`translation.browser` が真で、ブラウザに Translator API があり、言語の組を `Translator.availability()` が `unavailable` と言わないときである。サインインしていて、`GET /instance` の `translation.providers` にその投稿の `visibility` を受け取れる提供元があるときはサーバーを先に使い（ADR-0148 §6、§12）、サーバーが断れば（`422` の `translation-unavailable`・`translation-unsupported-language`、`429` の上限、`503` の `translation-failed`、そのほかの `5xx`）、ブラウザで訳せるならブラウザが引き継ぐ。`visibility` は作者が選んだ公開範囲で、上限を受けた作者の投稿はサーバーが断るので、この形で訳す。断られた投稿は、カードがある間は次に押すとブラウザに直接渡す（モデルのダウンロードには押した操作が要り、サーバーを待つ間に切れることがあるため）。ブラウザで訳せなければサーバーの断りを伝える。提供元がない投稿とサインインしていない読者には、はじめからブラウザを選ぶ。ブラウザの手段はサーバーにも提供元にも何も送らないので、公開範囲を問わず、サインインも要らない。カードの残りは `Translator` の答え（`TranslatedPost`）だけを見るので、手段を足すときに変えるのはこのフックと、`TranslatedBody`・`TranslatedBy` の種類である。
    UI の言語かどうかはサーバーが作者の本文を探す規則（ADR-0148 §8）と同じに比べ（`isInLanguage`）、`und` は UI の言語と見なさず、ボタンを出して提供元に任せる。ブラウザの手段では、`und` の投稿には Language Detector API があって `unavailable` でないときだけボタンを出し、押してから言語を検出する（検出のモデルのダウンロードに読者の操作が要るため）。信頼度が 0.5 未満なら検出できなかったものとして扱う。`Status.visibility` は作者が選んだ値で実効の公開範囲ではないので、上限を受けた作者の投稿ではサーバーが断ることがあり、その理由はカードの中に出す。モデレーションの画面のカード（`withActions` が偽）には出さない。
  - **見せ方**: 求められるまで原文を出し、訳は本文・CW・投票の選択肢・代替テキストを同じ場所で置き換える。答えは `dir="auto"` のまま、`lang` を訳の言語にする。答えにない部分（CW、代替テキスト）は原文のまま残す。投票は表示だけが変わり、回答は選択肢の番号で送る。
    訳を出している間は、本文の直後（CW があればその外の後ろ、投票・添付より前）に `PostCardNote` の 1 行を出す。行は「{原文の言語}から翻訳 · {手段} · 原文を表示」で、何が起きたか・誰が訳したか・戻し方を 1 か所で言う。言語名は `Intl.DisplayNames` で UI の言語に合わせ、原文の言語が分からない（`und`）ときは「機械翻訳」とだけ書く。手段は提供元の名前（`url` があれば `ExternalLink`、`logo_url` があれば飾りの画像）、ブラウザの手段では「お使いのブラウザ ({ブラウザ})」で、名前は `navigator.userAgentData.brands` の Google Chrome・Microsoft Edge・Opera から取る（ほかのブラウザでは名前を省く）。サーバーが作者自身の文章を返したときは、前半の代わりに機械翻訳でないと書く。翻訳中（モデルのダウンロード中は進み具合も）と失敗の理由もこの行に出すので、押した後に何が起きているかは本文のすぐ下で分かる。行は `article` の説明に入る。
  - **ブラウザの訳の入れ方**（ADR-0148 §8、§12）: 仕様は出力にマークアップが混ざり得るとするので、出力を HTML として解析しない。`sanitizedHtmlNodes`（`@my/ui`）がサーバーのサニタイズした本文の構造をデータにし、サーバーの `fragment.go` と同じ考え方でブロックの境目ごとの断片にして、メンション・ハッシュタグ・リンク・`:shortcode:`・`code`・`pre` は `⟦1⟧` の印に、飾りは `⟦1⟧…⟦/1⟧` の対に置き換える。訳は印の位置で構造に戻し、印の間の文字はテキストのまま `PostContentNodes` が React のテキストノードとして描く。この経路に HTML のシンクはなく、Trusted Types のポリシーも足さない。印が壊れた訳は見せない。モデルが印を保たない組があるので（Chrome の en から ar は印を数字にする）、そのときは印の間を 1 つずつ訳し直し、それでも印が揃わなければ失敗にする。
  - **操作とフォーカス**: 操作の帯の「翻訳する」は、ほかの操作と同じ大きさのアイコンのトグル（`IconToggleButton`、ツールチップと `aria-pressed`。訳を出している間が押された状態で、もう一度押すと原文に戻る）で、ブックマークの後・「その他の操作」の前に置く。翻訳中は `isPending`。カードが狭い（`@sm` 未満）ときは帯から外し、「その他の操作」のメニューの「翻訳する」「原文を表示」（翻訳中は「翻訳しています…」で無効）で選ぶ。メニューには幅を問わず置く。
    トグルを押してもフォーカスは動かない。行の「原文を表示」を押すと行が消えるので、フォーカスは帯のトグルへ、帯にないときは「その他の操作」のボタンへ移す。メニューから選んだときは、閉じたメニューのボタンに戻る。
    操作の帯のないカード（モデレーションの画面、通報のコメント）は、本文の直後に「翻訳する」の文字のボタンを置き、翻訳中はその文言が「翻訳しています…」「翻訳モデルをダウンロードしています… {進み具合}」に変わる。訳が出るとボタンの場所に行が入るので、フォーカスは行の「原文を表示」へ移し、それを押すと戻ったボタンへ移す。
    進み具合は `monitor` の `downloadprogress` の `loaded` で、モデルが手元にある（`available`）ときは見せない。結果は `useNotice` の `inPlace` で読み上げ、失敗は行の `InlineError`（`alert`）で伝え、問題の `type` ごと、ブラウザの手段では `BrowserTranslationError` の理由ごとの文にする（E2）。ダウンロードを伴う `create()` は読者の操作の直後でないと `NotAllowedError` で断られ、押した操作は数秒で切れる（別のモデルのダウンロードを待つと切れる）ので、押し直せば続きから進むことをこの文で伝える。
  - **状態**: 送信は押したときだけ走る mutation で、答えは投稿の版（`edited_at`）と言語ごとの Query のキャッシュ（`statusTranslationQueryOptions`）に入れる。キャッシュはメモリだけで、ブラウザの保存にもオフラインのタイムラインにも入らず、利用者が変わると消える。どちらを出すかはカードの state で、開いた CW と同じくカードがアンマウントされると原文に戻る（押し直してもリクエストはない）。編集で版が変わると原文に戻る。
- **引用**（FR-114、ADR-0069 §5）: `quote` のある投稿は、本文・投票・添付の後（CW があればその中）に、引用された投稿を `@my/ui` の `QuoteCard`（名前「引用された投稿」の `group`）で出す（`components/QuotedStatus.tsx`、`hooks/useQuoteView.ts`）。
  中身は引用先の作者（アバター・名前・ハンドル。名前はプロフィールへのリンク）、時刻（引用先の投稿の画面へのリンク）、本文と添付（引用先の CW はその中に）で、投票・リンクのカード・操作の列は出さない。引用は 1 段で、引用先の引用は出さない。
  承認待ち・拒否・取り消し・削除・閲覧できない・ブロックは、引用先の代わりにその理由の文だけを出す。引用先の作者かサーバーをミュートしているときは、理由の文の後ろに CW と同じ disclosure（Y8）で引用先を隠し、「引用された投稿を表示」で開く。
- **キーワードフィルターで畳んだ投稿**（FR-209、ADR-0157 §2・§10）: 照合はサーバーが行い、`Status.filtered`（閲覧者の `warn` のフィルターのうち一致したもの）が空でない投稿を畳む。ブーストは行の `filtered` で畳む。
  タイムライン・スレッド・プロフィールのカード（`components/StatusCard.tsx`）は、投稿の代わりに `@my/ui` の `FilteredPost`（名前が「フィルターに一致: {名前}」の `article` と「表示する」のボタン）を出し、作者・本文・添付を描かない。読み上げはフィルターに一致したことだけを伝え、中身は表示するまで読まれない。
  「表示する」を押すと、その場で投稿のカードに置き換わり、フォーカスがその `article` に移る。開いた状態はカードの state で、カードがアンマウントされると畳み直す。一致したフィルターが複数なら名前を UI の言語の並べ方（`Intl.ListFormat`）でつなぐ。
  引用された投稿だけが一致したときは、引用の部分だけを、ミュートした作者の引用と同じ disclosure（Y8）で「フィルターに一致: {名前}」の後ろに隠す。通知の行は、CW と同じく本文を引かずに「フィルターに一致: {名前}」だけを出す。
- **引用する・引用の管理**（FR-114、ADR-0069 §3〜§5）: 操作の列のブーストの後に「引用」（アイコンのボタンとツールチップ）を置き、`useQuote()`（§12）で投稿フォームを開く。`Status.permissions` の `quote` が `denied` の投稿（と `permissions` のない投稿）では無効にする。
  自分の投稿の「その他の操作」のメニューは、「返信・ブースト・引用できる人を変える」（`components/InteractionPolicyDialog.tsx`。投稿フォームと同じ `InteractionPolicyFields` で、投稿の公開範囲が決める種類は無効。選ぶとすぐ、変えた種類だけを `PUT /statuses/{id}/interaction_policy` で送り、答えで投稿のすべての写しを置き換えてトーストで知らせる。
  変更は投稿ごとに 1 つずつ、選んだ順に送る。承認済みの交流は残り、新しい選択で認められる承認待ちの依頼はサーバーが承認する）と、
  「この投稿の引用」（`/@{acct}/status/{id}/quotes`、`routes/@{$acct}_.status.$id_.quotes.tsx`。サインインが要る画面で、`GET /statuses/{id}/quotes` を `TimelineFeed` で出す）を持つ。
  自分の投稿を承認済みで引用している投稿のメニューには「この引用から自分の投稿を外す」を出し、`DELETE /statuses/{quoted}/quotes/{quoting}/approval` が成功したら、引用している投稿のすべての写しの引用を取り消しの状態にしてトーストで知らせる。
- **交流の許可と承認待ち**（ADR-0155 §7、§10）: 返信とブーストを出すかは、投稿が運ぶ `Status.permissions`（閲覧者ごとの `allowed` / `pending` / `denied`）だけで決め、投稿ごとに問い合わせない。
  `reply` が `denied` の投稿は返信のボタンを出さない（返信の数のリンクは残る）。`announce` が `denied` の投稿と、公開範囲が閲覧者のブーストを許さない投稿は、ブーストのトグルを無効にする（数は残し、すでにしたブーストは取り消せる）。
  ブーストした答えが `boost_approval: pending`（作者の承認待ち）なら、トグルは押されていない状態で無効になり、操作の列の末尾の `Hint` で「あなたのブーストは作者の承認待ちです」と言い、トグルの説明にもする。読み上げも「ブーストの承認を作者に求めました」にする。断られた（`rejected`）ブーストも同じ場所でそう言う。
  閲覧者自身の返信で、返信先の作者がまだ承認していないもの（`Status.approval`）は、カードの詳細の行に「承認待ち: この返信はあなたにだけ見えます」（断られたものは「断られました: …」）を出す。
- **承認の依頼**: 自分の投稿への承認待ちの返信・ブースト・引用は設定の「承認の依頼」（[screens/settings-interaction-requests.md](screens/settings-interaction-requests.md)）で答える。
  答えると（`features/status` の `cacheAnsweredRequest`）、答えの投稿の返信・ブーストの数と、引用・返信している投稿をすべての写しに入れ、スレッド（`GET /statuses/{id}/context`。承認した返信は上のどの投稿のスレッドにも入り得る）すべてに無効化の印を付け、表示中のものは取り直す。スレッドは再読み込みなしで承認した返信を出す。
- **ハンドル**: アカウントのハンドルは `@{acct}`（`lib/handle.ts` の `handleOf`）で出す。`acct` はこのサーバーのアカウントではユーザー名なので `@username`、ほかのサーバーのアカウントでは `@username@domain` になる。
  ローカルかどうかは API の `acct` で判断し（`isRemoteAcct`）、ドメインを文字列で比べない。タイムライン・投稿の詳細・通知・プロフィール・フォローの一覧・設定・サイドバーで同じにする。
- **ほかのサーバーのアカウントと投稿**（`acct` にドメインがあるもの）: 名前の横のハンドルは `@username@domain` で出す。カードの操作の列の末尾に、元のサーバーの投稿のページ（`url`、なければ `uri`）へのリンクを置く。
  リンクはホスト名だけを見せ、アクセシブルネームはそのホスト名を含む文（「{host} で元の投稿を開く」）にする。サインインしていない間も出す。
  プロフィールは各タブの投稿の一覧の上に「このサーバーが受け取った投稿だけを表示しています」と、元のサーバーのプロフィール（`Account.url`）へのリンク「{host} で見る」を置き、投稿が無いタブでは空の表示の説明と操作に同じものを出す（`TimelineFeed` の `origin`、ADR-0006）。
  どちらのリンクも `ExternalLink` で、外部へのリンクのアイコンを付けて新しいタブで開く（Y12）。投稿のリンクのアクセシブルネームは「{host} で元の投稿を開く（新しいタブで開きます）」になる。
  タブの最初のページが `remote_fetch_started` を返したら（client-api.md）、一覧の上に「元のサーバーから最近の投稿を取得しています」を出して `useNotice` の `inPlace`（polite）で 1 回読み上げ（Y7。表示はページと同時に現れるので、それ自体はライブリージョンにしない）、
  4 秒後にそのアカウントの投稿の一覧に無効化の印を付けて表示中のタブを 1 回だけ取り直し、取り直しの成否にかかわらずキャッシュの最初のページから `remote_fetch_started` を外して表示を消す（`timeline/hooks/useRemoteFetch`）。失敗は知らせない。
  画像は `preview_url` で表示する。アップロードでは `small` の静止版、リモートの添付ではメディアプロキシの URL で、リモートの添付は `variants` を持たない。
  アップロードの画像・アバター・ヘッダーは `variants` を `@my/ui` の `Picture`（`lib/images` の `imageSources`）に渡し、表示する大きさに合う版をブラウザーが `srcset` / `sizes` で選ぶ。
  アニメーションの動く版は `<source media="(prefers-reduced-motion: no-preference)">` にだけ置き、設定「アニメーションを自動で再生する」（このブラウザーの localStorage `my:display:autoplay`、`lib/autoplay`、既定はオン）がオフなら、投稿（`PostCard`）とプロフィールのヘッダー（`ProfileHeader`）の単位で動く版にする（ADR-0005 §6。`@my/ui` の `useAnimationScope` と `AnimationsPlayContext`）。アイコン・表示名と本文・CW・リアクションのカスタム絵文字・添付の画像と `gifv` が、ポインタを重ねている間、キーボードのフォーカスが中にある間、投稿のタップ（中のリンク・ボタンなどの操作、スクロールや長押しは除く）からもう一度のタップか画面の外に出るまでの間、まとめて動く。投稿そのものをフォーカスの止まり先には足さない。1 枚の画像もポインタを重ねている間は動く。`prefers-reduced-motion: reduce` のときはどれも動かさない（動く版は同じ `<source media>` の後ろにだけ入れる）。説明のある画像にはマスの右下（書字方向の末尾側）に飾りのノートのアイコンの小さなバッジが付き、説明のない画像にはバッジを付けない（Y9）。CW はローカルの投稿と同じ disclosure で出す。
  動画と音声（`type` が `video` / `audio` / `gifv`）は `url` を `MediaGrid` のマスで再生する（`MediaItem` の `playback`）。動画は `<video>` にアップロードのポスターの `large`（リモートの添付はポスターなし）を `poster` に、音声はポスターをマスの背景にして下端に `<audio>` を置く。
  どちらもブラウザーの操作部（`controls`）を持ち、自分では再生を始めない。名前は説明（なければ、画面には出さない「説明なし」）で、字幕のファイルはない（ADR-0005 は字幕を扱わない）ので、内容は説明が伝える。
  `gifv`（GIF の代わりの音のない短い動画）は、設定「アニメーションを自動で再生する」がオンで `prefers-reduced-motion: reduce` でない間だけ、操作部なしで音を消して繰り返し再生し、それ以外は操作部を出して止めておく。
  センシティブな画像を隠している間と、画像の読み込み中は、添付の `blurhash` のぼかし（`@my/ui` の `Blurhash`。自前の復号器が 32 × 32 ピクセルに復号して `<canvas>` に描き、飾りとして `aria-hidden`）をそのマスに出し、読み込み終えたら外す。`blurhash` のない添付と復号できないものは、マスの地の面（`bg-surface-sunken`）が代わりになる。読み込めなかった画像と音声は、その場所に失敗の印と「もう一度試す」（`@my/ui` の `MediaLoadFailure`）を出し、押すと読み込み直す。音声は「再生」を押してから音が出るまで、ボタンが脈打って待ちを示す。
- **連合の向きの注記**（FR-413、[ADR-0006](../../adr/0006-federation-protocol-scope.md)、`lib/federation.ts`）: インスタンスが外へ送らないモード（`off` / `inbound`。`useFederation()` の `reachesRemote` が偽）のとき、ほかのサーバーの投稿の操作の列の終わり（ホスト名の隣）に、1 行の注記「連合先には届きません」（`@my/ui` の `Hint`）を常に出す。
  操作の前に分かるように、操作の後のトーストにはしない。注記は返信・ブースト・お気に入りの説明（`aria-describedby`）にもする。リアクションのピッカー（`features/emoji`）には説明を付けず、見える注記で伝える。
  このモードでは引用の依頼を送れないので、ほかのサーバーの投稿には「引用」を出さない。
  `GET /instance` の `federation.mode` が届くまでと読めないときは `both`（設定の既定値）とみなし、すべての操作を出す。サーバーが 403 `federation-restricted` で断ったら、`refetchInstanceOnFederationRestricted` が `GET /instance` を取り直し、断られるようになった操作をすぐ出さなくする（断られた理由は、断られた場所にその problem の題で出す）。
- **画像のビューア**: タイムライン・投稿の詳細・編集履歴の添付画像は、マス全体がボタン（名前は画像の代替テキスト、`aria-haspopup="dialog"`）で、押すとその画像を元のサイズで開く（`@my/ui` の `MediaGrid` の `viewerLabels` と、内部の `MediaViewer`）。
  元のサイズは、アップロードでは `variants.large`（アニメーションは `variants.animated.large` を `Picture` の動く版にする）、リモートの添付ではメディアプロキシの `url` で（`lib/images` の `originalImage`）、画面に収まるように縮めて出す。
  ビューアは共有の `Dialog`（Y11）で、見出しは「画像 {位置} / {枚数}」、画像の下に代替テキスト（ないときは「説明なし」）を出す。× ボタン・背景の押下・Esc で閉じ、フォーカスは開いた画像に戻る。
  複数枚のときは「前の画像」「次の画像」のボタンと左右の矢印キー（RTL では向きが逆）で移動し、端では反対の端に回る（押したボタンが無効になってフォーカスを失わないため）。新しい画像は `aria-live="polite"` で名前が読まれる。
  指で横に払っても移動する（行の始まりの向きへ払うと次の画像。RTL では逆）。画像の下の位置（「3 / 3」）は、動画と音声も含めたマスの位置と数で数え、グリッドと合わせる。読み込み中は画像のぼかしとスピナーを、読み込めなかったときは失敗の印と「もう一度試す」を出す。
  説明のある画像の角の説明の印はそれ自体がボタン（名前は「代替テキスト」）で、押すと説明を開いた状態でビューアを開く。
  隠しているセンシティブな画像と、閉じた CW の中の画像はボタンにならない。開いている画像は URL に置かない（S3 の例外。タイムラインのどの画面からでも開けるので、再読み込みで開き直すにはルートごとに投稿を取り直す必要があるため）。
- **楽観的更新**（S8）: 同じ投稿がタイムラインのページ・ブースト・スレッド・投稿の query に同時にあるので、`api/cache.ts` がキャッシュの答えを形（`Status`・`items`・`pages`・`ancestors` / `descendants`）で見分け、すべての写しを書き換える。
  トグルは押した時点で状態と数を変え、失敗したらその 1 回分だけ戻してトーストで理由を知らせる。同じ投稿の同じ操作は TanStack Query の mutation の `scope` で 1 つずつ順に送り、最後に押したものが残る。
  成功の応答の数（他の人の操作を含む）は、その操作の最後の要求の応答からだけ取り込む。結果は `useNotice` の `inPlace` で読み上げる。
- **ブックマークの一覧**（`/bookmarks`、ナビゲーションの「ブックマーク」、FR-113）: サインインが要る画面で、ブックマークした新しい順の投稿をタイムラインと同じ feed（`features/timeline` の `TimelineFeed`）で出す。
  ブックマークの切り替えは一覧に無効化の印を付けるだけで（`refetchType: "none"`）、表示中の一覧は取り直さない。一覧で外した投稿は外した状態のまま残ってフォーカスを保ち、押し直せば戻せる。次に一覧を開いたときに消える。
- **削除**: `alertdialog` で確かめ（最初のフォーカスは「キャンセル」）、サーバーが消してから、投稿とそのブーストをすべての一覧から除き、投稿とスレッドの query を消し、返信先の返信数を 1 減らす。
  詳細の画面で消したときは前の画面に戻る（戻る先がなければホーム）。失敗したらダイアログを残してトーストで理由を知らせる。
- **編集**（FR-109）: モーダルのダイアログ（`components/EditStatusDialog.tsx`）で、投稿フォーム（§12）の部品（本文の `TextArea` と文字数、CW のトグルと入力欄、画像の代替テキストの一覧 `AttachmentList`、センシティブのチェックボックス、言語の `Select`）を使う。
  投稿フォームの下書きは共有して保存されるので、編集はそこに入れず、ダイアログの中だけの state にする（閉じると消え、書きかけの新しい投稿を上書きしない）。
  開くたびに `GET /statuses/{id}/source` で作者が書いた文を読み直し、本文にフォーカスを移す。読めなければ理由と「もう一度試す」を出す。
  公開範囲と返信先は変えられない（API）ので、その旨を書く。引用している投稿には「引用を外す」のチェックボックスを出し、選ぶと `remove_quote` を送る（引用は付け直せない）。画像は足し外しせず、代替テキストだけを変え、送るときはすべての画像を順に送る（省くと外れる）。サーバーが代替テキストを必須にしているときは、投稿フォームと同じく説明の入力欄を必須にする。
  「保存する」は `PUT /statuses/{id}` を送り、サーバーの答えを待つ。成功したら答えですべての写しを置き換え（`cacheEditedStatus`。一覧の中の位置は変えない）、履歴に無効化の印を付け、トーストで知らせて閉じる。失敗はダイアログの中に `role="alert"` で出し、入力を残す（E2）。
- **編集済みと編集履歴**: `edited_at` のある投稿は、本文と操作の列の間（`details`）に「編集済み」のリンクを出し、編集履歴の画面（`/@{acct}/status/{id}/history`、`routes/@{$acct}_.status.$id_.history.tsx`）へ移る。
  画面は `h1`「編集履歴」、投稿に戻るリンク、版の一覧（`GET /statuses/{id}/history` を新しい順）にする。各版は、作った日時の `h2` が名前を与える `article` で、現在の版か最初の投稿か、前の版から変わったもの（本文・CW・センシティブの指定・添付）、CW と本文と画像をカードと同じ部品で出す。
- **固定**（FR-403）: 自分のダイレクト以外の投稿（サーバーが固定を受け付けるもの）の「その他の操作」のメニューに、「プロフィールに固定」か、固定済みなら「プロフィールへの固定を外す」を出す。
  確かめずに送り、サーバーが答えてから、投稿のすべての写しの `pinned` を応答のものにし、閲覧者の固定された投稿の一覧（`GET /accounts/{id}/statuses?pinned=true`）を無効にして、表示中なら取り直してから結果をトーストで知らせる。
  失敗（固定できる件数の上限の 422 など）はサーバーの理由をトーストで知らせ、何も変えない（E2）。同じ投稿の固定と外すは mutation の `scope` で 1 つずつ順に送る。
  プロフィールの「投稿」のタブは、ルートの loader がそのアカウントの固定された投稿も読み、feed の先頭に固定された新しい順で並べる（同じ投稿は下のタイムラインにも出る）。固定された投稿のカードは、行頭の文脈の行「固定された投稿」を持ち、`article` の名前もそれで始まる。
  ほかのタブには出さない。ほかのサーバーのアカウントでは、このサーバーが知っている固定された投稿だけが出る。
- **スレッドのミュート**（[ADR-0158](../../adr/0158-notification-policy.md) §8）: サインインした閲覧者のどの投稿（自分の投稿も）の「その他の操作」のメニューにも、「このスレッドをミュート」か、`Status.muted` が真なら「スレッドのミュートを解除」を出す。
