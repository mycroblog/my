## 13. 投稿の詳細と投稿への操作

`features/status` が投稿のカード（`StatusCard`）と操作、投票、投稿の詳細と編集履歴の画面を受け持つ（FR-106〜109、FR-112、FR-113、FR-116）。タイムラインなどの一覧は、このカードを `index.ts` から使う。

- **アドレス**: 投稿の詳細は `/@{acct}/status/{id}`（`routes/@{$acct}_.status.$id.tsx`、ADR-0053）。`acct` はローカルのアカウントではユーザー名、リモートでは `username@domain` で、読みやすさのためだけにあり、投稿は ID で引く。
  `_` で、プロフィールの画面（`/@{acct}`）のレイアウトの下に入らないようにする。カードの時刻はこのアドレスへのリンクになる（ブーストはブーストされた投稿へ）。
- **公開範囲**: どのカードも、時刻の下に投稿の公開範囲（ADR-0017）を、段階ごとに形の違うアイコンと名前で出す（`@my/ui` の `VisibilityMark`。`PostCard` の `visibility` は必須で、投稿でない通知の行だけが `null` を渡す。色だけに頼らない、G13）。
  名前は `article` の名前の終わり（作者・時刻の後）にも入る。公開範囲の並び・名前・説明は `features/compose` の 1 つの定義（`hooks/visibilityMessages.ts`、`index.ts` から export）を、投稿フォーム・設定・カードが共有する。
- **画面**: 見出しは `h1`「投稿」、その下に返信先の投稿（`h2`「スレッドの前の投稿」、古い順）、投稿そのもの（焦点の投稿）、返信（`h2`「返信」、深さ優先）を並べる。
  - 焦点の投稿は `PostCard` の `highlighted`（`surface-raised` の面と、行頭側の `accent` の線）で区別し、本文を `text-lg` にする。
    `article` の名前は、見えない `label`「開いている投稿」で始め、作者・時刻が続く（スクリーンリーダーと ARIA スナップショットで、スレッドのほかの投稿と名前で区別できる）。
    頭の時刻はほかのカードと同じ相対時刻（G8）で、自分へのリンクはない。本文と操作の列の間の `details` に、省略しない日時（`<time>`）と、0 でない操作の数の文言（「ブースト 3 件」「お気に入り 12 件」）を並べる。
  - 返信のつながりは、アバターの列を通る線（`PostCard` の `lineAbove` / `lineBelow`）で示す。並んだ 2 つの投稿の下の方が上の方への返信（`in_reply_to_id`）のときだけ線でつなぐ。
    つながる先が下にあるカードは、狭い幅でも本文をアバターの列の外に置き、線が本文と重ならないようにする。線は飾りで、スレッドの構造は見出しと順序が伝える。
  - スレッドの前の投稿が読み込まれて焦点の投稿の上に入ったら、焦点の投稿を 1 回だけ画面の上端（ページの下に残りが少なければ、届くところ）までスクロールする（描画の前、`useLayoutEffect`。`features/status` の `useRevealOnce`）。
    ルーターのスクロールの復元は同じコミットの後（`onRendered`）で新しい画面を上端に戻すので、そのときはその後にもう一度スクロールする。戻るで復元した位置は動かさない。
    フォーカスは `h1` のまま動かさない（外枠は `h1` に `preventScroll` でフォーカスを移すので、このスクロールを戻さない）。
  ローダーは投稿を待ち、スレッド（`GET /statuses/{id}/context`）は待たずに読み込み始める。スレッドの失敗は返信の区画に理由と「もう一度試す」を出し、投稿は表示したままにする（E1）。
  見えない投稿と存在しない投稿はどちらも 404 で、ルートの `errorComponent` が「投稿が見つかりません」を出す。
- **操作**: 返信（`useReply()`、§12）、ブースト・お気に入り・ブックマークのトグル（`@my/ui` の `ToggleButton`。名前は状態で変えず `aria-pressed` で示し、数は説明にする。オンのアイコンは塗りつぶしで、色だけに頼らない）、
  リアクションの選択（後述）、「その他の操作」のメニューの「リンクをコピー」と、自分の投稿だけの「編集」「プロフィールに固定」「削除」。サインインしていない間は操作を出さない。公開範囲がブーストを許さない投稿（他人のフォロワー限定・ダイレクト）は、ブーストのボタンを無効にする。
- **絵文字リアクション**（FR-116、ADR-0052 §5、ADR-0091 §7）: 操作の列の「リアクションする」（アイコンのボタンとツールチップ）が、ポップオーバーに投稿フォームと同じ絵文字のピッカーを開く（`features/emoji` の `ReactionPickerButton`。§12「絵文字のピッカー」）。
  節は同じく よく使う → このサーバーのカスタム絵文字 → Unicode の 9 グループで、検索・節のボタン・肌の色のメニューもそのまま使い、よく使う絵文字と肌の色は投稿フォームと共有する。Unicode 絵文字のデータはボタンにポインタが乗ったとき・フォーカスしたとき・開いたときに読み、届くまではスピナーを出す。
  データはサーバーと同じ `EMOJI_VERSION` から作るので、選べる Unicode 絵文字（肌の色の付いたものも）はすべてサーバーが受け入れる（ADR-0052 §1）。ほかのサーバーのカスタム絵文字は出さない。
  選ぶとポップオーバーを閉じ（フォーカスはボタンに戻る）、選んだ肌の色の絵文字でリアクションする。1 つの投稿のリアクションは 1 つの枠なので、Shift を押しながら選んでも閉じる。
  投稿の下（`PostCard` の `reactions`、本文と操作の列の間）に、絵文字ごとの数を「リアクション」の `group` に並べる。Unicode とこのサーバーのカスタム絵文字は `ToggleButton`（名前は「{emoji} でリアクション」、数は説明、自分のものは `aria-pressed`）で、押すとその絵文字で加わり、もう一度押すと外す。
  ほかのサーバーのカスタム絵文字は、ボタンにせず絵文字と数だけを出す（ADR-0052 §2）。列の終わりの「リアクションした人」は、付けた人の一覧（`GET /statuses/{id}/reactions`、新しい順、各行はプロフィールへのリンクと絵文字。続きは「さらに表示」のボタン）をダイアログで開く。
  お気に入りとリアクションは 1 つの枠（ADR-0052 §1）なので、どちらの操作も `useLikeSlot` の 1 つの mutation の `scope` で順に送り、押した時点でお気に入り・自分のリアクション・それぞれの数をすべての写しで入れ替え、失敗したら押す前の枠に戻してトーストで理由を知らせる。
- **投票**（FR-112）: 投票のある投稿は、本文の下（CW があればその中、添付の前）に投票の区画（`section`「投票」）を出す（`components/StatusPoll.tsx`、`hooks/usePoll.ts`）。
  サインインしていて、まだ回答しておらず、締め切り前なら、単一選択は `RadioGroup`、複数選択は `fieldset` の `Checkbox` で選び、「回答する」で `POST /statuses/{id}/poll/votes` を送る（選ぶまで無効）。
  サーバーの答えを待ち、答えの `poll` で投稿のすべての写しを置き換えてトーストで知らせる（`cacheVoteAnswer`）。断られたら理由をトーストで知らせ、投稿に無効化の印を付けて読み直す（締め切り・編集による投票の差し替え・ほかの端末での回答）。
  それ以外（回答済み・締め切り後・サインインしていない・モデレーションの画面）は、選択肢ごとの割合（数字と、飾りの `aria-hidden` の棒）と、自分が選んだ選択肢の「あなたの回答」を「投票の結果」の一覧に出す。
  作者が締め切りまで票数を隠す投票は、締め切りまでサーバーが選択肢ごとの票数を返さないので、割合と棒を出さずに選択肢だけを並べ、その下に締め切り後に票数が出ることを書く。
  区画の下に投票者数（分からなければ票数）と締め切り（相対時刻。過ぎたら「締め切りました」）、ほかのサーバーの投票ではその集計がそのサーバーの最後に送ったものであることを書く。選択肢は利用者の文なので `dir="auto"` と投稿の `lang` で出す。
- **引用**（FR-114、ADR-0069 §5）: `quote` のある投稿は、本文・投票・添付の後（CW があればその中）に、引用された投稿を `@my/ui` の `QuoteCard`（名前「引用された投稿」の `group`）で出す（`components/QuotedStatus.tsx`、`hooks/useQuoteView.ts`）。
  中身は引用先の作者（アバター・名前・ハンドル。名前はプロフィールへのリンク）、時刻（引用先の投稿の画面へのリンク）、本文と添付（引用先の CW はその中に）で、投票・リンクのカード・操作の列は出さない。引用は 1 段で、引用先の引用は出さない。
  承認待ち・拒否・取り消し・削除・閲覧できない・ブロックは、引用先の代わりにその理由の文だけを出す。引用先の作者かサーバーをミュートしているときは、理由の文の後ろに CW と同じ disclosure（Y8）で引用先を隠し、「引用された投稿を表示」で開く。
- **引用する・引用の管理**（FR-114、ADR-0069 §3〜§5）: 操作の列のブーストの後に「引用」（アイコンのボタンとツールチップ）を置き、`useQuote()`（§12）で投稿フォームを開く。サーバーが `quotable` を偽とする投稿では無効にする。
  自分の投稿の「その他の操作」のメニューは、「引用できる人を変更」（`components/QuotePolicyDialog.tsx`。説明付きの `RadioGroup` で、選ぶとすぐ `PUT /statuses/{id}/quote_policy` を送り、答えで投稿のすべての写しを置き換えてトーストで知らせる。承認済みの引用は残る）と、
  「この投稿の引用」（`/@{acct}/status/{id}/quotes`、`routes/@{$acct}_.status.$id_.quotes.tsx`。サインインが要る画面で、`GET /statuses/{id}/quotes` を `TimelineFeed` で出す）を持つ。
  自分の投稿を承認済みで引用している投稿のメニューには「この引用から自分の投稿を外す」を出し、`POST /statuses/{quoted}/quotes/{quoting}/revoke` が成功したら、引用している投稿のすべての写しの引用を取り消しの状態にしてトーストで知らせる。
- **ハンドル**: アカウントのハンドルは `@{acct}`（`lib/handle.ts` の `handleOf`）で出す。`acct` はこのサーバーのアカウントではユーザー名なので `@username`、ほかのサーバーのアカウントでは `@username@domain` になる。
  ローカルかどうかは API の `acct` で判断し（`isRemoteAcct`）、ドメインを文字列で比べない。タイムライン・投稿の詳細・通知・プロフィール・フォローの一覧・設定・サイドバーで同じにする。
- **ほかのサーバーのアカウントと投稿**（`acct` にドメインがあるもの）: 名前の横のハンドルは `@username@domain` で出す。カードの操作の列の末尾に、元のサーバーの投稿のページ（`url`、なければ `uri`）へのリンクを置く。
  リンクはホスト名だけを見せ、アクセシブルネームはそのホスト名を含む文（「{host} で元の投稿を開く」）にする。サインインしていない間も出す。
  プロフィールは各タブの投稿の一覧の上に「このサーバーが受け取った投稿だけを表示しています」と、元のサーバーのプロフィール（`Account.url`）へのリンク「{host} で見る」を置き、投稿が無いタブでは空の表示の説明と操作に同じものを出す（`TimelineFeed` の `origin`、ADR-0044）。
  どちらのリンクも `ExternalLink` で、外部へのリンクのアイコンを付けて新しいタブで開く（Y12）。投稿のリンクのアクセシブルネームは「{host} で元の投稿を開く（新しいタブで開きます）」になる。
  タブの最初のページが `remote_fetch_started` を返したら（client-api.md）、一覧の上に「元のサーバーから最近の投稿を取得しています」を出して `useNotice` の `inPlace`（polite）で 1 回読み上げ（Y7。表示はページと同時に現れるので、それ自体はライブリージョンにしない）、
  4 秒後にそのアカウントの投稿の一覧に無効化の印を付けて表示中のタブを 1 回だけ取り直し、取り直しの成否にかかわらずキャッシュの最初のページから `remote_fetch_started` を外して表示を消す（`timeline/hooks/useRemoteFetch`）。失敗は知らせない。
  画像は `preview_url` で表示する。アップロードでは `small` の静止版、リモートの添付ではメディアプロキシの URL で、リモートの添付は `variants` を持たない。
  アップロードの画像・アバター・ヘッダーは `variants` を `@my/ui` の `Picture`（`lib/images` の `imageSources`）に渡し、表示する大きさに合う版をブラウザーが `srcset` / `sizes` で選ぶ。
  アニメーションの動く版は `<source media="(prefers-reduced-motion: no-preference)">` にだけ置き、設定「アニメーションを自動で再生する」（このブラウザーの localStorage `my:display:autoplay`、`lib/autoplay`、既定はオン）がオフなら、投稿（`PostCard`）とプロフィールのヘッダー（`ProfileHeader`）の単位で動く版にする（ADR-0054 §3。`@my/ui` の `useAnimationScope` と `AnimationsPlayContext`）。アイコン・表示名と本文・CW・リアクションのカスタム絵文字・添付の画像と `gifv` が、ポインタを重ねている間、キーボードのフォーカスが中にある間、投稿のタップ（中のリンク・ボタンなどの操作、スクロールや長押しは除く）からもう一度のタップか画面の外に出るまでの間、まとめて動く。投稿そのものをフォーカスの止まり先には足さない。1 枚の画像もポインタを重ねている間は動く。`prefers-reduced-motion: reduce` のときはどれも動かさない（動く版は同じ `<source media>` の後ろにだけ入れる）。説明のある画像にはマスの右下（書字方向の末尾側）に飾りのノートのアイコンの小さなバッジが付き、説明のない画像にはバッジを付けない（Y9）。CW はローカルの投稿と同じ disclosure で出す。
  動画と音声（`type` が `video` / `audio` / `gifv`）は `url` を `MediaGrid` のマスで再生する（`MediaItem` の `playback`）。動画は `<video>` にアップロードのポスターの `large`（リモートの添付はポスターなし）を `poster` に、音声はポスターをマスの背景にして下端に `<audio>` を置く。
  どちらもブラウザーの操作部（`controls`）を持ち、自分では再生を始めない。名前は説明（なければ、画面には出さない「説明なし」）で、字幕のファイルはない（ADR-0054 は字幕を扱わない）ので、内容は説明が伝える。
  `gifv`（GIF の代わりの音のない短い動画）は、設定「アニメーションを自動で再生する」がオンで `prefers-reduced-motion: reduce` でない間だけ、操作部なしで音を消して繰り返し再生し、それ以外は操作部を出して止めておく。
  センシティブな画像を隠している間と、画像の読み込み中は、添付の `blurhash` のぼかし（`@my/ui` の `Blurhash`。自前の復号器が 32 × 32 ピクセルに復号して `<canvas>` に描き、飾りとして `aria-hidden`）をそのマスに出し、読み込み終えたら外す。`blurhash` のない添付と復号できないものは、マスの地の面（`bg-surface-sunken`）が代わりになる。読み込めなかった画像と音声は、その場所に失敗の印と「もう一度試す」（`@my/ui` の `MediaLoadFailure`）を出し、押すと読み込み直す。音声は「再生」を押してから音が出るまで、ボタンが脈打って待ちを示す。
- **連合の向きの注記**（FR-413、[ADR-0076](../../adr/0076-federation-direction.md)、`lib/federation.ts`）: インスタンスが外へ送らないモード（`off` / `inbound`。`useFederation()` の `reachesRemote` が偽）のとき、ほかのサーバーの投稿の操作の列の終わり（ホスト名の隣）に、1 行の注記「連合先には届きません」（`@my/ui` の `Hint`）を常に出す。
  操作の前に分かるように、操作の後のトーストにはしない。注記は返信・ブースト・お気に入りの説明（`aria-describedby`）にもする。リアクションのピッカー（`features/emoji`）には説明を付けず、見える注記で伝える。
  このモードでは引用の依頼を送れないので、ほかのサーバーの投稿には「引用」を出さない。
  `GET /instance` の `federation.mode` が届くまでと読めないときは `both`（設定の既定値）とみなし、すべての操作を出す。サーバーが 403 `federation-restricted` で断ったら、`refetchInstanceOnFederationRestricted` が `GET /instance` を取り直し、断られるようになった操作をすぐ出さなくする（断られた理由は、断られた場所にその problem の題で出す）。
- **画像のビューア**: タイムライン・投稿の詳細・編集履歴の添付画像は、マス全体がボタン（名前は画像の代替テキスト、`aria-haspopup="dialog"`）で、押すとその画像を元のサイズで開く（`@my/ui` の `MediaGrid` の `viewerLabels` と、内部の `MediaViewer`）。
  元のサイズは、アップロードでは `variants.large`（アニメーションは `variants.animated.large` を `Picture` の動く版にする）、リモートの添付ではメディアプロキシの `url` で（`lib/images` の `originalImage`）、画面に収まるように縮めて出す。
  ビューアは共有の `Dialog`（Y11）で、見出しは「画像 {位置} / {枚数}」、画像の下に代替テキスト（ないときは「説明なし」）を出す。× ボタン・背景の押下・Esc で閉じ、フォーカスは開いた画像に戻る。
  複数枚のときは「前の画像」「次の画像」のボタンと左右の矢印キー（RTL では向きが逆）で移動し、端では反対の端に回る（押したボタンが無効になってフォーカスを失わないため）。新しい画像は `aria-live="polite"` で名前が読まれる。
  指で横に払っても移動する（行の始まりの向きへ払うと次の画像。RTL では逆）。画像の下の位置（「3 / 3」）は、動画と音声も含めたマスの位置と数で数え、グリッドと合わせる。読み込み中は画像のぼかしとスピナーを、読み込めなかったときは失敗の印と「もう一度試す」を出す。
  説明のある画像の角の説明の印はそれ自体がボタン（名前は「代替テキスト」）で、押すと説明を開いた状態でビューアを開く。
  隠しているセンシティブな画像と、閉じた CW の中の画像はボタンにならない。開いている画像は URL に置かない（S3 の例外。タイムラインのどの画面からでも開けるので、再読み込みで開き直すにはルートごとに投稿を取り直す必要があるため）。
- **楽観的更新**（S8）: 同じ投稿がタイムラインのページ・ブースト・スレッド・投稿の query に同時にあるので、`api/cache.ts` がキャッシュの答えを形（`Status`・`items`・`pages`・`ancestors` / `descendants`）で見分け、すべての写しを書き換える。
  トグルは押した時点で状態と数を変え、失敗したらその 1 回分だけ戻してトーストで理由を知らせる。同じ投稿の同じ操作は TanStack Query の mutation の `scope` で 1 つずつ順に送り、最後に押したものが残る。
  成功の応答の数（他の人の操作を含む）は、その操作の最後の要求の応答からだけ取り込む。結果は `useNotice` の `inPlace` で読み上げる。
- **ブックマークの一覧**（`/bookmarks`、ナビゲーションの「ブックマーク」、FR-113）: サインインが要る画面で、ブックマークした新しい順の投稿をタイムラインと同じ feed（`features/timeline` の `TimelineFeed`）で出す。
  ブックマークの切り替えは一覧に無効化の印を付けるだけで（`refetchType: "none"`）、表示中の一覧は取り直さない。一覧で外した投稿は外した状態のまま残ってフォーカスを保ち、押し直せば戻せる。次に一覧を開いたときに消える。
- **削除**: `alertdialog` で確かめ（最初のフォーカスは「キャンセル」）、サーバーが消してから、投稿とそのブーストをすべての一覧から除き、投稿とスレッドの query を消し、返信先の返信数を 1 減らす。
  詳細の画面で消したときは前の画面に戻る（戻る先がなければホーム）。失敗したらダイアログを残してトーストで理由を知らせる。
- **編集**（FR-109）: モーダルのダイアログ（`components/EditStatusDialog.tsx`）で、投稿フォーム（§12）の部品（本文の `TextArea` と文字数、CW のトグルと入力欄、画像の代替テキストの一覧 `AttachmentList`、センシティブのチェックボックス、言語の `Select`）を使う。
  投稿フォームの下書きは共有して保存されるので、編集はそこに入れず、ダイアログの中だけの state にする（閉じると消え、書きかけの新しい投稿を上書きしない）。
  開くたびに `GET /statuses/{id}/source` で作者が書いた文を読み直し、本文にフォーカスを移す。読めなければ理由と「もう一度試す」を出す。
  公開範囲と返信先は変えられない（API）ので、その旨を書く。引用している投稿には「引用を外す」のチェックボックスを出し、選ぶと `remove_quote` を送る（引用は付け直せない）。画像は足し外しせず、代替テキストだけを変え、送るときはすべての画像を順に送る（省くと外れる）。サーバーが代替テキストを必須にしているときは、投稿フォームと同じく説明の入力欄を必須にする。
  「保存する」は `PUT /statuses/{id}` を送り、サーバーの答えを待つ。成功したら答えですべての写しを置き換え（`cacheEditedStatus`。一覧の中の位置は変えない）、履歴に無効化の印を付け、トーストで知らせて閉じる。失敗はダイアログの中に `role="alert"` で出し、入力を残す（E2）。
- **編集済みと編集履歴**: `edited_at` のある投稿は、本文と操作の列の間（`details`）に「編集済み」のリンクを出し、編集履歴の画面（`/@{acct}/status/{id}/history`、`routes/@{$acct}_.status.$id_.history.tsx`）へ移る。
  画面は `h1`「編集履歴」、投稿に戻るリンク、版の一覧（`GET /statuses/{id}/history` を新しい順）にする。各版は、作った日時の `h2` が名前を与える `article` で、現在の版か最初の投稿か、前の版から変わったもの（本文・CW・センシティブの指定・添付）、CW と本文と画像をカードと同じ部品で出す。
- **固定**（FR-403）: 自分のダイレクト以外の投稿（サーバーが固定を受け付けるもの）の「その他の操作」のメニューに、「プロフィールに固定」か、固定済みなら「プロフィールへの固定を外す」を出す。
  確かめずに送り、サーバーが答えてから、投稿のすべての写しの `pinned` を応答のものにし、閲覧者の固定された投稿の一覧（`GET /accounts/{id}/statuses?pinned=true`）を無効にして、表示中なら取り直してから結果をトーストで知らせる。
  失敗（固定できる件数の上限の 422 など）はサーバーの理由をトーストで知らせ、何も変えない（E2）。同じ投稿の固定と外すは mutation の `scope` で 1 つずつ順に送る。
  プロフィールの「投稿」のタブは、ルートの loader がそのアカウントの固定された投稿も読み、feed の先頭に固定された新しい順で並べる（同じ投稿は下のタイムラインにも出る）。固定された投稿のカードは、行頭の文脈の行「固定された投稿」を持ち、`article` の名前もそれで始まる。
  ほかのタブには出さない。ほかのサーバーのアカウントでは、このサーバーが知っている固定された投稿だけが出る。
