## 8. 削除と消去

| 操作 | 記録するイベント | 消去ジョブが物理削除するもの | 残すもの |
| --- | --- | --- | --- |
| 投稿の削除（FR-108） | `status_deletions` | `statuses`・版と子テーブル・投影の行・その投稿の `favourites` / `reactions` / `bookmarks` / `status_pins`・その投稿についての `notifications`（`notification_dismissals` を含む）と `notification_deleted_statuses` の行 | `status_deletions`（URI = tombstone） |
| アカウント削除（FR-008） | `account_lifecycle_events`（本人による削除は `deleted`、BAN は `deletion_scheduled` → 期日に `deleted`）、消し終えたら `account_erasures` | プロフィールの版と子テーブル・`account_profile_heads`・鍵（秘密鍵と失効）、メールアドレス（確認と主アドレス）・資格情報・1 回限りのトークン・セッション（失効と `session_activity`）・認可コードとアクセストークン（引き換えと失効）・利用者設定・登録の申請（決定と状態）・投稿の自動削除の設定、データエクスポート（要求と結果・アーカイブの Blob）、投稿（上と同じ。`local_statuses` と、だれのものでもその投稿のブースト・お気に入り・リアクション・ブックマーク・ピン留めを含む）、本人のお気に入り・リアクション・ブックマーク・ピン留め・ブースト（件数から引く）・投票への回答、両方向のフォロー（イベントと `follow_edges`・`follow_counters`・`follow_preferences`）・ブロック・ミュート・ドメインのミュート、本人が受けた・本人の操作による・本人の利用者についての通知（`notification_dismissals`・既読位置・`notification_exclusions`・`notification_domain_exclusions` を含む）と Web Push の購読（`push_subscription_alerts` を含む）、`feed_*` の本人の行、お知らせの既読（`announcement_reads`）、本人のアップロード（`media_files` と子テーブル・Blob）、参加者の一覧の掲載の選択（`supporter_listings`）と決済の事業者の顧客（`supporter_customers`）、本人が書いた通話のルームの版（`voice_room_revisions`）の名前と説明（空にする。ADR-0100 §13） | `accounts`（`uri` と `domain`。URI の再利用防止）、`local_accounts` と `account_handles`（ユーザー名の再利用防止）、`users`、ライフサイクル、`status_deletions`（tombstone）、処分の記録（理由・種類・日時）と `feed_author_restrictions`、保持期間で消える `session_origins`・`registration_origins`、招待とロールの付与、インスタンス設定が指すメディア、課金の加入・遷移・決済画面・返金とチャージバックの記録（会計と事業者との照合のため。ADR-0072 §10）、通話のルームとその版（名前と説明を除く）・タグ・ホストの交代・共同ホストの変化・終了（§4.14） |
| BAN | `moderation_actions`（`ban`） + 上記の `deletion_scheduled` | 同上 | 同上 + `signup_blocks` |
| モデレーション記録の保持期間（ADR-0038） | なし（期限は記録の日時から求める。§4.3 記録の保持期間） | 保持期間を過ぎた通報と子テーブル・処分と子テーブル・異議申し立て・監査ログ・`session_origins`・`registration_origins`・解除か期限切れから 30 日の `signup_blocks` | 保全（`retention_holds`）のあるアカウントの記録、未解決の通報、処分が参照する通報、終わっていない処分と審査待ちの異議申し立て |
| 投稿の自動削除（FR-118） | `status_deletions`（`origin = auto_delete`） | 投稿の削除と同じ | 投稿の削除と同じ |
| リモート投稿の保持期間（FR-803） | `status_deletions`（`origin = retention`） | `statuses`・版と子テーブル・投票・投影の行・リモートのアカウントのブースト（§4.4 リモート投稿の保持期間） | `status_deletions`（取得し直しは拒まない）、ローカルのアカウントのブースト・お気に入り・ブックマーク・ピン留め・通知 |
| 通話の参加者の記録の保持期間（ADR-0100 §13） | なし（期限は `voice_room_endings.ended_at` から求める） | ルームの終了から `retention_voice_participants`（既定 90 日、下限 30 日）を過ぎたルームの `voice_room_participations`・`voice_room_participation_ends`・`voice_room_role_changes`・`voice_room_hand_raises`・`voice_room_speak_grants`・`voice_room_invitations` と取り消し・`voice_room_bans` | 通報（`report_voice_rooms`）が指すルームの記録はその通報の保持の期限まで、保全（`retention_holds`）のあるものはいまのとおり。ルームそのもの（§4.14 の残りの表） |

- `Delete`（Actor）は、`active` なフォロワーの inbox と、既知の shared inbox（削除されていないリモートの Actor の `remote_account_heads.shared_inbox_url`）に送ります。
- サービスのクローズ（[ADR-0088](../../adr/0088-service-shutdown-modes.md) §3）は、削除されていないローカルのアカウントすべて（凍結中を含み、移転済みは最後）に同じ宛先へ `Delete`（Actor）を送ります。アカウントごとに `closure_deletes` を 1 行記録し、ライフサイクルは変えず、消去ジョブも動かしません（[federation.md §15](../federation.md#15-サービスの終了)）。データはサーバーが自分では消さず、運営者が停止の後に DB・Blob・バックアップを破棄します。
- 消去は「イベントを記録 → 投影から即時に除外 → 消去ジョブが一定件数ずつ物理削除」の順です。表示から消えるのは即時、物理削除は非同期です。
- アカウント削除の消去は、1 時間ごとのジョブ `account.erase_deleted` が、`deleted` から 7 日を過ぎた、保全（§4.3）の無いローカルのアカウントに行います。
  - モジュールごとの消去（`content` の投稿と操作 → `graph` → `timeline` → `notification` → `instance` のお知らせの既読 → `content` のメディア → `identity` → `account`）を、1 文あたり 100 行（投稿は 100 件）・1 回のジョブで 50 トランザクションまで行い、使い切ったらカーソルを持った次のジョブが続けます。カーソルは最後に終えたアカウントの ID と、途中のアカウントがあればその ID・途中の消去・その消去のカーソル・それまでに残した行があるかで、次のジョブは途中のアカウントの続きから始めます。残す投稿が 1 回のジョブで見きれないほどあっても、毎回先頭から見直さずに後の投稿・後のモジュール・次のアカウントへ進みます。どれも再実行してよい。
  - 削除されていない投稿には `status_deletions`（`origin = account_deletion`）を記録して `content.status_deleted` を発行し（投影・`feed_*` から外れる）、同じトランザクションで行を消します。投稿ごとの `Delete` は送りません（`Delete`（Actor）が代わりを務める）。
  - 有効なフォローは `follow_terminations`（`account_deleted`）で終わらせ、相手の `follow_counters` から引いてから消します。相手のサーバーには何も送りません。
  - 通報か投稿単位の処分が指す投稿（`moderation` の `StatusRetained`）は、削除だけを記録して行を残し、その記録が消えた後の回で消します。それまで `account_erasures` は記録せず、毎回そのアカウントを調べ直します。
  - 本人のアップロードは、Blob（受け取ったままのファイルと各処理結果の版）をトランザクションの外で消してから、同じ回の 1 トランザクションで `media_files` と子テーブル（`uploaded_media`・`media_processing_results`・`media_variants`・`media_focus`・`media_descriptions`）を消します。行が残りの消去の記録なので、Blob の削除に失敗しても次の回が消し直します（存在しない Blob の削除は成功する）。
  - 残した投稿の版が添付するファイルは、投稿と同じく記録が消えた後の回で消します（ADR-0038）。インスタンス設定（§4.9）のどれかの版が指すファイルはインスタンスのものとして残し、消去を止めません。プロフィールの版が指すアバターとヘッダーは、プロフィールと一緒に消えます。
