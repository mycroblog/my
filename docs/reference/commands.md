# Commands

The tasks of the repository and the toolchain they use. Tasks run with go-task ([ADR-0080](../adr/0080-task-runner-go-task.md))
through `scripts/task.sh <task> [VAR=value ...]`, which builds `bin/task` from the version pinned in `tools/go.mod` and never uses
a `task` on PATH (Taskwarrior's command has the same name). `scripts/task.sh --list` lists every task with its description.
Coding agents run the workflow steps through agentkit ([tools/agentkit/README.md](../../tools/agentkit/README.md)).

## How tasks run

- `Taskfile.yml` holds the includes, `check`, `check:changed`, and `generate`. Each area keeps its tasks in
  `tasks/<area>.yml`, named `<area>:<task>` (`go:test`, `web:check`). A new area is a new file there and one line under `includes`.
- The `deps` of a task run in parallel, also inside a context (`go:vet`, `go:lint`, and `go:test` at once). A failed task does not stop
  the others, so one run shows every failure; the exit code is the failed command's own.
- Locally `scripts/task.sh` limits the parallel tasks to half the CPUs (`TASK_CONCURRENCY=N` overrides it), since several agents
  check on one machine; in CI (`CI` set) the concurrency is unlimited. Each line carries its task's name.
- The CI jobs are not tasks ([ADR-0083](../adr/0083-ci-steps-not-tasks.md)): each job of `.github/workflows/ci.yml` sets up its tools,
  generates what its checks read, and runs the checks as parallel workflow steps, each named after the one area task it runs
  (`scripts/task.sh go:vet`; golangci-lint runs through golangci-lint-action, in the steps `go:lint`, `agentkit:lint`, `mykit:lint`, and `mykit:mybot-lint` of the pull-request `lint` job and of the slow suite). To rerun a
  failed step locally, run the task it names. `docs:ci-coverage` fails when a check of `check` runs in no step.
- Generators declare their inputs and outputs (`sources` / `generates`) and skip when the checksums of their inputs have not changed
  since their last run (kept in `.task/`). `--force` runs a task anyway.
- Variables are arguments (`scripts/task.sh go:bin VERSION=v1.2.3`) or environment variables.
- "The slow suite" below is `.github/workflows/slow-suite.yml`: the checks that run as the release gate, nightly, and by hand,
  never on pull requests or in the merge queue ([ADR-0079](../adr/0079-ci-single-gate-merge-queue.md); the table of what runs where is in
  [workflow.md §5](../agents/workflow.md#what-ci-runs-where)).

## Checks across areas

| Task | Purpose |
| --- | --- |
| `check` [`CHECKS="go web"`] | Every offline check, one `<context>:check` per context, the contexts and the checks inside each in parallel: `docs:check`, `go:check`, `i18n:check`, `mail:check`, `api:check`, `ui:check`, `web:check`, `docker:check`, `agentkit:check`, `mykit:check` |
| `check:changed` [`BASE=origin/main`] | `check` of only the contexts changed since the merge base with `BASE` (working tree and untracked files included) and of their dependents (`scripts/changed-contexts.sh`); shared configuration (`Taskfile.yml`, `tasks/`, `scripts/task.sh`, `.tool-versions`, `tools/go.mod`, the workflows) or an unknown path selects every context; `go.mod` selects go, `app/bun.lock` ui and web, `api/` api, `pkg/mykit/`, `pkg/mybot/`, and `internal/platform/platformtest/` mykit, and `locales/` / `tools/i18n/` i18n and web (plus the dependents). It names `shell:check`, and `db:check-all` and `db:lint`, when the shell scripts or the schema changed. CI skips the jobs of the other contexts the same way |
| `generate` | Every generator whose inputs changed since its last run: `api:generate`, `go:sqlc`, `go:config-docs`, `i18n:gen`, `mail:gen`, `web:tokens-gen`, `web:routes-gen`. The generated files Go reads are committed; the ones only the TypeScript clients read are not (except the types of `@mycroblog/mykit`, which its package ships, [ADR-0093](../adr/0093-api-client-library-mykit.md)), and the tasks that read them generate them first ([ADR-0081](../adr/0081-generated-files-policy.md)). Run it once after a clone for an editor's type checks |

## Toolchain

Toolchain versions (Go, golangci-lint, Bun, shellcheck, Node.js) are pinned in `.tool-versions` (asdf / mise).
Atlas Community Edition is pinned and checksum-verified in `scripts/install-atlas.sh` (`scripts/task.sh db:atlas` installs `bin/atlas`).
Go tools (go-task, go-licenses, sqlc, oapi-codegen) are pinned with `tool` directives in `tools/go.mod` and run via
`go tool -modfile=tools/go.mod <tool>` (go-task as `bin/task`, built by `scripts/task.sh`).
The i18n generator and checks are a Bun package in `tools/i18n` with exact versions in `package.json` and a committed `bun.lock`.
The clients live in the Bun workspace `app/` (`app/ui` = `@my/ui`, shipped as TypeScript source; `app/web`) with exact versions,
one committed `app/bun.lock`, and `app/bunfig.toml` (isolated installs, no version younger than two weeks).
Bun installs packages and runs scripts; Vite runs on Node.js — never add `--bun` ([ADR-0025](../adr/0025-web-client-stack.md)).
