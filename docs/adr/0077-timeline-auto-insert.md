# ADR-0077: タイムラインの新着をユーザーの設定で自動で差し込む

- Status: Accepted（1 の既定「偽（オプトイン）」と、2 の対象外のうちローカル・連合を ADR-0127（ローカル・連合のタイムラインにも新着を届け、自動の差し込みを既定にする） が置き換える）
- Date: 2026-10-22
- Deciders: @rosylilly
- Issue: #1016

## Context（背景・課題）

ホームのタイムラインには、リアルタイム更新（FR-207、[ADR-0050](0050-stream-pubsub-across-processes.md)）で新しい投稿が届く。
[ADR-0027](0027-ui-quality-gates.md) は「新しい投稿をタイムラインに自動で差し込まない。『N 件の新しい投稿』ボタン（`role="status"`）にする（WCAG 2.2.2）」と決めており、
Web クライアントは届いた投稿を溜め、`@my/ui` の `NewItemsButton` が押されたときだけ差し込む（web-client.md Y7・§10 のリアルタイム更新）。

一方、新しいデザインシステム（エピック #987）の LayoutTimelineは、
新しい投稿を先頭に自動で差し込み、読んでいる投稿の位置は動かさない形を描いている。
押さなければ新着が見えない形は、流れを眺めたい利用者には手間になる。自動で動く内容は、読んでいる位置を奪い、支援技術の利用者を混乱させるので、誰にでも既定で動かすことはできない（WCAG 2.2.2、NFR-A11Y-1）。

決定者の決定（#1016、原文）:

> タイムラインの自動挿入 : ユーザー設定で自動挿入できるようにする。これは確定なので ADR も Approved として一緒に epic の PR に乗せて良い

この ADR は、その決定の形（設定の置き場所と既定、差し込み方、知らせ方、一時停止、対象、フォーカス、つながらないとき）を決める。

## Decision Drivers（判断基準）

1. 読んでいる投稿の位置とフォーカスを、届いた投稿が動かさないこと（WCAG 2.4.3・3.2.5 の趣旨、Y7 のフォーカスを奪わない）
2. 自動で動く内容を、利用者が止められること（WCAG 2.2.2。既定で動かさない）
3. 支援技術の利用者に、届くたびに読み上げを浴びせないこと（WCAG 4.1.3 を満たしつつ、うるさくしない）
4. 端末をまたいで同じ体験になること
5. 設定がオフのときの今の挙動・キャッシュの方針（[ADR-0045](0045-client-server-cache-policy.md)）を変えないこと

## Considered Options（選択肢）

1. 今のまま、押すまで溜める（ADR-0027 のまま）
2. 誰にでも自動で差し込み、設定で止められるようにする（オプトアウト）
3. アカウントの設定で選んだ人にだけ自動で差し込む（オプトイン）。差し込みはフィードの中にフォーカスや選択がある間は止まる
4. 3 と同じだが、設定を端末（localStorage）に置く

## Decision（決定）

**選択肢 3 を採用する。**

### 1. 設定

- アカウントの設定（`user_preferences`、`GET` / `PATCH /api/v1/preferences`）に真偽値 `timeline_auto_insert`（「新しい投稿を自動で表示する」）を置く。端末をまたいで同じにする。
- 既定は偽（オプトイン）。偽のときの挙動は今のまま（押すまで溜める、web-client.md Y7）。決定者の「自動挿入できるようにする」を、選べるようにすると読む。
- Web クライアントの設定画面で `Switch` で切り替える。

### 2. 対象のタイムライン

- ストリーミングで新しい投稿が届くタイムライン。今はホームだけである。
- ローカル・連合・ハッシュタグ・プロフィールの一覧は新着が届かないので対象外（開いたときに読む）。のちにストリーミングで新着が届くタイムラインが加わったら、同じ設定とこの ADR の規則をそのまま当てる。
- ホームを表示していない間に届いた投稿は、設定に関係なく今のとおりキャッシュの先頭に入る（web-client.md §10）。

### 3. 差し込み方（設定が真で、一時停止していないとき）

- **先頭にいるか** は、フィードの最初の投稿の上端が見えているか（フィードの先頭に置いた目印を `IntersectionObserver` で見る）で決める。
- **先頭にいるとき**: 届いた投稿をすぐ先頭に差し込む。画面は先頭のままで、新しい投稿がそのまま見える。
- **先頭から離れているとき**: 届いた投稿をすぐ先頭に差し込み、差し込んだ高さだけスクロールの位置を足して、読んでいる投稿（画面の上端にかかる投稿）を同じ場所に保つ（スクロールのアンカー）。
  - CSS のスクロールアンカー（`overflow-anchor`）には頼らない。安定版の Safari（macOS・iOS）が対応していない（確認日 2026-10-22、[Can I use](https://caniuse.com/css-overflow-anchor)、[WebKit bug 171099](https://bugs.webkit.org/show_bug.cgi?id=171099)）。
    差し込む前にアンカーの投稿の位置を測り、描画の前（`useLayoutEffect`）に差の分だけスクロールを足す。ブラウザのアンカーと二重に補わないよう、フィードには `overflow-anchor: none` を付ける。
  - 差し込んだ投稿は動きなしで現れる（アニメーションを付けない）。
- **先頭から離れている間のピル**: フィードの上に `NewItemsButton`（`sticky`）を浮かせ、離れてから差し込んだ件数（「N 件の新しい投稿」）を出す。
  - 押すと先頭まで移り（`motion-safe:` のときだけ滑らかに）、タイムラインの見出し（`h1`、`tabindex="-1"`）にフォーカスを移す。押したボタンは消えるので、フォーカスの行き先を見出しにする（設定が偽のときに押したのと同じ）。
  - 利用者が自分で先頭まで戻ったら、件数を 0 に戻してピルを消す。
  - ピルは現れてもフォーカスを取らない。フィードに重なってよいのはピルだけである（LayoutTimeline）。

### 4. 一時停止（WCAG 2.2.2）

- 設定で止められることに加えて、画面の上でその場で止める仕組みを持つ。**フォーカスがフィードの中にある間と、フィードの中の文字を選択している間は差し込まない。**
  - その間に届いた投稿は、設定が偽のときと同じく溜め、`NewItemsButton` が件数を出す。押すと差し込んで見出しにフォーカスを移す（設定が偽のときと同じ）。
  - フォーカスと選択がフィードの外に出たら、溜めた投稿を 3 の規則（先頭にいるか、アンカー）で差し込む。
  - キーボードやスクリーンリーダーで投稿を読んでいる人（フォーカスがフィードの中にある）には、設定が真でも中身が動かない。マウスで読んでいる人は、アンカーで位置が動かない。
- モーダルのダイアログ（投稿のシートなど）が開いている間は、フォーカスがフィードの外のダイアログにあるので一時停止しない。差し込みは今ある投稿の要素を作り直さない（投稿の ID を key にする）ので、閉じたときにフォーカスを戻す先の要素は残る。

### 5. 支援技術への知らせ方

- 差し込んだ投稿を 1 件ずつ読ませない。フィード（`role="feed"`）はライブリージョンにしない。
- 件数は `NewItemsButton` の `role="status"`（polite）だけで知らせる。先頭から離れている間と一時停止の間にピルが件数を出すので、その変化が読み上げられる。
- 先頭にいて一時停止していない間に差し込んだ投稿は知らせない。スクリーンリーダーでフィードを読んでいる人は、フォーカスがフィードの中にあるので一時停止の側にいる（4）。フィードの外にいる人に届くたびの読み上げを足すと、ほかの操作の読み上げを遮る。
- 差し込みで `aria-posinset` は振り直す（`aria-setsize` は分からないので `-1` のまま、Y6）。

### 6. フォーカス

- 差し込みはフォーカスを動かさず、奪わない。フォーカスのある投稿がフィードの中にあれば一時停止するので（4）、その投稿の位置も変わらない。
- フォーカスを移すのは、利用者がピルを押したときだけ（見出しへ）。

### 7. つながらないとき（再接続・溜めた投稿が 200 件を超えた）

- 溜めた投稿が読み込み済みの投稿とつながらない（再接続で 1 ページ分の新着が見つかった、または 200 件を超えた）ときは、差し込まない。間に抜けがあるかもしれないからである。
- 先頭にいて一時停止していないときは、ホームの最初のページだけを取り直す（設定が偽のときに押したのと同じ取り直し）。読んでいる位置は先頭なので、失うものがない。
- 先頭から離れているか一時停止しているときは、取り直さずにピルを出す。押すと最初のページだけを取り直して先頭へ移り、見出しにフォーカスを移す。

### 8. ほかの ADR との関係

この ADR は、次の部分だけを置き換える。どちらの ADR も Accepted のままで、その他の決定と本文は変えない。Status の行に、この ADR が置き換えることを注記する（ADR-0066 が ADR-0016・ADR-0029 にしたのと同じ）。

- ADR-0027 の「部品と画面のルール」の「新しい投稿をタイムラインに自動で差し込まない。『N 件の新しい投稿』ボタン（`role="status"`）にする（WCAG 2.2.2）」。設定が偽のとき・一時停止の間は、この箇条のとおりに動く。
- ADR-0045 の「データの種類ごとの方針」の表の一覧の行の「ホームの新着はストリーミングが『N 件の新しい投稿』に溜める（S10）」。設定が真なら、上の 3・4 のとおりに差し込む。

## Consequences（影響）

- 良い影響
  - 流れを眺めたい利用者は、押さずに新着を見られる。読んでいる位置は動かない。
  - 既定は今のままなので、選ばない利用者と支援技術の利用者の体験は変わらない。
  - フォーカスや選択がフィードの中にある間は動かないので、設定を真にしても、キーボード・スクリーンリーダーで読む人の位置を奪わない。
- 悪い影響・トレードオフ
  - スクロールの補正をクライアントで行うので、投稿の高さが後から変わる（画像の読み込み、CW の開閉）と、補正がずれることがある。メディアの派生が持つ `width` / `height`（ADR-0054）で、画像の枠の高さを読み込みの前に決めることで抑える。
  - 先頭にいてフィードの外にいる支援技術の利用者には、差し込みが知らされない。
  - 状態が 3 つ（溜める・差し込む・一時停止）になり、テストの組が増える。
  - 開いたまま長くいると、ホームのキャッシュの最初のページが伸び続ける。
- 後続で必要になる作業
  - #1017: アカウントの設定に `timeline_auto_insert` を足す（スキーマ・data-model.md・client API）。
  - #1018: Web クライアントの切り替えと、差し込み・アンカー・ピル・一時停止・つながらないときの実装とテスト。

## Pros and Cons of the Options（詳細比較・任意）

### 選択肢 1: 今のまま、押すまで溜める

- 良い点: 中身が勝手に動かず、WCAG 2.2.2 を最も単純に満たす。実装が今のままでよい。
- 悪い点: 流れを眺めたい利用者に毎回押させる。デザインの LayoutTimeline の形と合わない。決定者の決定に合わない。

### 選択肢 2: 誰にでも自動で差し込み、設定で止められるようにする

- 良い点: デザインのとおりの体験を、設定を探さずに得られる。
- 悪い点: 動く内容が既定になり、止める設定を見つけるまで読む位置やスクリーンリーダーの読み上げが乱れる。既定の挙動が変わる。

### 選択肢 3: アカウントの設定で選んだ人にだけ（オプトイン）、フィードの中にいる間は止める

- 良い点: 既定は変わらず、選んだ人だけが自動の差し込みを得る。端末をまたいで同じ。その場の一時停止があるので、設定を真にした人がキーボードで読むときも動かない。
- 悪い点: サーバーの設定の項目が 1 つ増える。状態が増える。

### 選択肢 4: 選択肢 3 の設定を端末に置く

- 良い点: サーバーの変更が要らない。端末ごと（スマートフォンでは自動、PC では溜める）に変えられる。
- 悪い点: 端末ごとに選び直す。ほかの表示の設定（言語・公開範囲の既定）がアカウントの設定にあるのと揃わない。
