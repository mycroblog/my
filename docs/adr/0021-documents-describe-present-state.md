# ADR-0021: リポジトリ内の文書は現在の状態だけを記述し、履歴は git に任せる

- Status: Accepted
- Date: 2026-11-04
- Deciders: @rosylilly
- Issue: #2078

## Decision

- **ソースコード・設計文書・要件・手順書など、リポジトリ内のすべてのファイルは「今」を記述する。** 変更の経緯・旧版との比較・変更履歴の節は書かない。経緯はコミットメッセージと PR の説明に書く。
- **ADR の `経緯` と `採らなかった案` だけは例外とする。** 決定が今の形である理由を読み手が知るために、判断の変遷と却下した案を短く書く。版ごとの変更の記録にはしない。
  - ADR の本文は結論を今の形で書く。「前の案では〜」は本文に書かない（ADR-0000）。
- **Open Questions には未解決の事項だけを書く。** 解決したら、その結論を本文（Decision / Consequences）に現在形で書き込み、項目を消す。完了のチェック（`[x]`）は残さない。
- 外部の事実（価格・制限値）の **確認日と出典** は、記載している値の属性なので書いてよい。

## 経緯

変更の履歴は git（コミット・PR・Issue）が持つ。文書に「初版からの変更」「当初は〜だった」「旧案」などを書くと、履歴が git と二重になり、読み手は現在の決定と過去の経緯を読み分ける必要があり、文書が変更のたびに長くなって「今どうなっているか」が埋もれる。

ADR も同じ規則で「この決定をした」という事実だけを記録していたが、判断の変遷と却下した案は ADR の主な役割なので、節を分けて書くことにした。

## 採らなかった案

- ADR にも経緯を一切書かない: 規則は単純になるが、同じ案が繰り返し提案され、理由が git を掘らないと分からない。

## Consequences

- 文書を読めば現在の状態が分かり、経過は `git log` / `git blame` / PR で辿れる。
- 経緯を知りたい読み手のために、コミットメッセージと PR の説明に「なぜ変えたか」を必ず書く。
- エージェントは、文書を更新するときに変更履歴の節を足さない（AGENTS.md と ADR の手順書に明記する）。
