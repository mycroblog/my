# ADR-0136: 自分のログイン中のブラウザの一覧と個別のログアウト

- Status: Accepted
- Date: 2026-11-02
- Deciders: @rosylilly
- Issue: #1987

## Context（背景・課題）

利用者は、自分のアカウントがどこでログインされているかを見られず、1 つのブラウザだけを終わらせることもできない。
いまできるのは、「認可したアプリ」で Web クライアントを取り消す（今のブラウザも含めてすべてログアウト）か、パスワードを変える（全セッションと、要求した系列以外の全トークンが終わる）ことだけで、パスワードのない利用者には後者がない。
端末をなくしただけで、すべてのブラウザからログアウトすることになる。関連する要件は FR-002、FR-003、FR-004。

ブラウザのログインは 2 つの資格情報でできている（[ADR-0030](0030-web-client-token-handling.md)）。

- **OAuth トークンの系列**（`__Host-my_rt`）: `/api/v1` を使う資格情報。更新のたびに期限が延びる。
- **セッション**（`__Host-my_session`）: ログインと同意の画面の資格情報。期限は 30 日で固定。一次のクライアントには同意を挟まずコードを発行するので、これだけで新しい系列を得られる。

両者は `oauth_authorization_code_redemptions` → `oauth_authorization_codes.session_id` で結ばれるが、1 対 1 ではない。

- 更新はセッションを見ないので、系列はセッションより長く生きる。パスワードの変更でも、要求した系列だけが残り、そのセッションは終わる。
- Cookie をなくして同じセッションからコードを取り直すと、1 つのセッションに複数の系列ができる。
- 同じブラウザでログインし直すとセッションは `replaced` で失効するが、そのセッションの系列は失効しない。

## Decision Drivers（判断基準）

1. なくした端末を、確実に締め出せる（セッションと系列の両方が終わり、取り残しがない）
2. 今のブラウザやサードパーティのアプリなど、選んでいないものは終わらない
3. 利用者に見える 1 行が、利用者の考える「1 つのブラウザ」に近い
4. 新しい保存データを増やさない（ADR-0038 の保持期間に収まる）。依存を増やさない

## Considered Options（選択肢）

1. **セッションを単位に、そのセッションの一次の系列を束ねて 1 行にする**
2. **一次の系列を単位に 1 行にする**
3. **一覧を作らず、「他のブラウザをすべてログアウト」だけを足す**

## Decision（決定）

**選択肢 1 を採用する。** 系列を単位にすると、同じセッションの系列が別の行に見え、系列のないセッションが一覧から漏れて、なくした端末で新しい系列を得られる資格情報が残る。選択肢 3 は実装が小さいが、身に覚えのないログインに気づけず、なくした端末 1 つのために他の端末もログアウトすることになる。

### 1. 一覧の行

利用者のセッションのうち、次のどちらかを満たすものが 1 行になる。

- セッションが有効（失効がなく期限内）
- セッションの状態によらず、そのセッションから始まった **一次のクライアント** の系列に、まだ使えるトークンがある

サードパーティのアプリの系列は数えない。それは「認可したアプリ」の役割で、ここでは終わらない。
一次のクライアントのコードは必ずセッションの中で発行するので（`internal/interface/authpages/authorize.go`）、一次の系列にはセッションがある。

### 2. 行に見せるもの

- ログイン時の User-Agent から求めたブラウザと OS。解釈できなければ元の文字列を見せ、依存は増やさない（Web クライアントの小さな関数）
- ログイン時の IP アドレス。今の場所ではないことが分かる文言にする。位置情報には変換しない
- ログインした日時
- 最後に使った日時: `session_activity.last_seen_at` と、束ねた系列の `oauth_token_family_last_used.last_used_at` の新しいほう（1 時間の精度）
- 今のブラウザの印: API を呼んだアクセストークンの系列が束ねられている行

`session_origins` が無い行（不明、または ADR-0038 の保持期間で消去）は、ブラウザと IP を「不明」と見せる。保存するデータは増やさない。

### 3. API

すべて `x-first-party-only`（ADR-0090 §4）で、利用者本人の分だけを扱う。

| 操作 | スコープ | 動作 |
| --- | --- | --- |
| `GET /api/v1/sessions` | `read:accounts` | 一覧。今のブラウザの行が先頭、以降は最後に使った日時の新しい順 |
| `DELETE /api/v1/sessions/{id}` | `write:accounts` | その行をログアウトする。他人の ID・一覧に無い ID は 404、今のブラウザは 409（ログアウトを使う） |
| `POST /api/v1/sessions/revoke_others` | `write:accounts` | 今のブラウザ以外のすべての行をログアウトする |

### 4. ログアウトで終わるもの

同じトランザクションで、`LockTokenGrants` を取ってから、次を失効させる。

- そのセッション（`logout`。すでに失効していれば何もしない）
- そのセッションから始まった一次のクライアントの系列の全トークン（`user`）

アクセストークンの認証は失効を DB で確かめるので、次の要求から 401 になる。開いているストリーミングは次のハートビートで切れる。
パスワード・二要素認証・サードパーティのアプリは変わらない。画面には、心当たりがないログインにはパスワードの変更と「認可したアプリ」の確認を勧める文を置く。

操作には確認のダイアログだけを出し、パスワードの再入力は求めない。盗まれたブラウザから操作されても持ち主を締め出せるだけで、権限は広がらず、持ち主も同じ操作ができる。

### 5. ログインし直しでの系列の失効

セッションが `replaced` で失効するとき、そのセッションから始まった一次の系列も、同じトランザクションで失効させる。`oauth_token_revocations.reason` に `session_replaced` を足す。
これが無いと、同じブラウザの古い系列が更新トークンの期限まで使える状態で残り、一覧に重複して見える。

### 6. 要件

FR-012 を足す: 「利用者は自分のログイン中のブラウザを一覧し、1 つずつ、または今のブラウザ以外をすべてログアウトできる」。

**覆る条件**: Tauri のアプリ（Cookie のセッションを持たない一次のクライアント）が v0 に入るなら、系列を単位にする必要がある。

## Consequences（影響）

- 良い影響
  - なくした端末だけを、パスワードを変えずに締め出せる。パスワードのない利用者にも同じ手段がある。
  - 身に覚えのないログインに気づける。
  - 同じブラウザでのログインし直しで、使われない更新トークンが残らなくなる。
- 悪い影響・トレードオフ
  - IP と User-Agent はログイン時のもので、今の場所や端末を表さない。更新トークンで使い続ける間に 180 日を超えると「不明」になる。
  - 最後に使った日時は 1 時間の精度しかない。
  - セッションの Cookie が切れたあとに同じブラウザでログインし直すと、古いセッションを特定できず `replaced` にならない。古い系列は別の行として残る（ログアウトできる。更新されなければ 30 日で消える）。
  - ログインの直後、コードを交換する前に別のタブが古い更新トークンを使うと、失効済みとして Cookie が消え、そのタブはログイン画面に戻ることがある。
  - 通知のメールはない。身に覚えのないログインに気づくには、一覧を見る必要がある。
  - ログアウトでは、そのブラウザから認可したサードパーティのアプリは終わらない。
- 対象外（必要なら別の Issue）
  - 新しいログインの通知メール
  - 管理者が利用者のセッションだけを終わらせる操作（いまは処分の `disable_login` などが、ログインの禁止と一緒に行う）
- 後続の作業: #1987 で API、画面、`session_replaced` のスキーマ変更、data-model・画面の設計文書・FR の更新を行う。

## Pros and Cons of the Options（詳細比較・任意）

### 選択肢 2: 一次の系列を単位にする

- 良い点: 実際に API を使う資格情報に直接対応し、一覧のクエリが単純。
- 悪い点: 系列のないセッション（ログインしたがコード交換の前に閉じたブラウザなど）が見えないまま残る。1 つのセッションに系列が複数あると、同じブラウザが複数行に見える。

### 選択肢 3: 「他のブラウザをすべてログアウト」だけ

- 良い点: 画面もクエリも最小で、User-Agent の解釈が要らない。
- 悪い点: どこでログインされているかが分からないままで、利用者の求めた一覧にならない。
