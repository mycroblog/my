# ADR-0132: リンクのカードの取得をドメインごとに止めるルール

- Status: Accepted
- Date: 2026-11-02
- Deciders: @rosylilly
- Issue: #1951

## Context（背景・課題）

決定者の指示: 「サーバー管理から特定ドメインへのクロールを停止したり、画像の取り込みだけをやめさせるなどの設定をできる画面・機能を追加」。

投稿中のリンクのカード（FR-117、[ADR-0062](0062-link-preview-cards.md)）は、サーバーがリンクの先のページと画像を取得して作る。これを運用者が止める手段は 2 つある。

- インスタンス設定 `link_cards`: サーバー全体でカードを止める。ドメインを選べない。
- ドメインへの処分（ADR-0062 §7）: `suspend`（`federation` の制限）で取得を止めてカードを隠し、`reject_media`（`media_fetch` の制限）で画像なしにする。

処分はそのドメインとの **連合** と **投稿のメディア** も止める（federation.md §11）。「画像が重いサイト」「取得をやめるよう頼んできたサイト」のように、連合の相手ではないニュースサイトやブログにも、連合の相手にも、カードの取得だけを止めたい場面で処分は使えない。連合の相手に使えば投稿が届かなくなり、処分の一覧と公開の一覧（FR-706）にも載る。

## Decision Drivers（判断基準）

1. **影響の分離**: カードの取得を止めても、連合と、カード以外のリモートメディアに影響しない
2. **すぐ効き、すぐ戻せる**: ルールの変更が取得済みのカードにもすぐ効き、消せば元に戻る。消した後にまとめて取得し直さない（FR-117 の外部 HTTP の量、ADR-0062 の判断基準 3）
3. **既存との一貫性**: ドメインの正規化・検証・親ドメインへの適用は処分と同じにする
4. **小さく保つ**: 1 サーバーあたり少数のドメインに使う管理者の設定で、読むのはカードの表示のたびなので、1 行ずつの引き当てで済む形にする

## Considered Options（選択肢）

1. **カードの取得だけに効く、ドメインごとのルールを新しく持つ**
2. ドメインへの処分に新しい種類（`no_link_cards` など）を足す
3. `link_cards` と同じインスタンス設定に、ドメインの一覧を文字列で持つ

## Decision（決定）

選択肢 1 を採る。

### 1. 2 つのモード

ルールはドメインごとに 1 つで、モードは次のどちらか。

| モード | 取得 | 取得済みのカード |
| --- | --- | --- |
| `no_fetch`（取得を止める） | そのドメインからページも画像も取得しない | 隠す |
| `no_images`（画像だけ止める） | ページは取得し、画像は取得しない | 画像なしで出す |

- ページの判定は、カードの URL と `card_url`（取得後のページの URL）のホストに当てる。
- 画像の判定は、カードの URL・リダイレクト後の URL・`card_url`・画像の URL のホストのすべてに当てる。`no_fetch` は画像の取得も止めるので、画像の判定では両方のモードが当たる。
- リダイレクトの各段にも当てる（`HTTPRequest.CheckRedirect`）。止めたドメインへのリダイレクトで、ページの取得はそこで終わり、画像はカードに付かない。
- 書き込みと読み出しの両方で判定する。読み出しで判定するので、ルールの追加・変更・削除は取得済みのカードにすぐ効き、カードと画像の行は消さない。`no_images` の間に取り直したカードは画像なしで保存され、ルールを消しても次の取り直し（ADR-0062 §6 の期限）まで画像なしのままになる。
- メディアプロキシは、ルールで止めたホストの **カードの画像** を配らず、取得もしない（404）。カード以外のリモートメディアには当てない。

### 2. ルールの適用範囲

- ホストと親ドメインに当てる。処分と同じ `DomainAndParents` を使う。
- ホストに当たるルールはすべて効く。親に `no_fetch`、子に `no_images` があれば `no_fetch` が効く。処分と同じく、子のルールは親のルールを緩めない。
- ドメインの正規化と検証は処分と同じ（`CanonicalHost`、`ValidDomain`）。U-label と A-label は同じドメインになる。

### 3. 処分との分離

- ルールは `suspend` / `reject_media` と独立して効き、どちらかが当たれば止まる。処分の表（`domain_actions`、`domain_restrictions`）には書かない。公開のドメイン一覧（FR-706）、CSV の書き出し、連合、配送、カード以外のメディアは、ルールを読まない。
- カードは連合しないので（ADR-0062 §7）、ルールは他のサーバーに伝わらない。

### 4. 失敗の記憶とルールの削除

ルールで飛ばした取得は、失敗の記憶（`content.link_card_failure`）に書かない。ルールを消せば、次に投稿がその URL を必要としたときにすぐカードを作る。ルールを消しても一括で取得し直さない。取得済みの投稿のうち、飛ばされた投稿のカードは、同じ URL を次に投稿が必要としたときに作られたカードを共有して現れる。

### 5. データモデル（ADR-0020）

`instance` モジュールの【現在値】`link_card_domain_rules`（`domain` PK, `mode`, `note`, `updated_at`）。

- 所有は `instance`。`link_cards` と同じくサーバーの設定で、`content` は監査の `moderation` に依存できない（`moderation` が `content` に依存している）。`content` は `LinkCardDomains` ポートで読み、プラットフォームがつなぐ。
- イベントと投影にしない。ルールそのものの履歴に意味はなく、誰がいつ何に変えたかは同じトランザクションで書く監査ログ（ADR-0037）に残るので、規約 5 の現在値に当たる。投影と違い再構築の対象でない。
- メモ（`note`）は処分の非公開のメモと同じ 5,000 文字まで。ルールの数の上限は 1,000 で、一覧はページングしない。

### 6. API と権限

- `GET /admin/link_card_domains`、`PUT /admin/link_card_domains/{domain}`（ドメインのルールを設定。あれば置き換える）、`DELETE /admin/link_card_domains/{domain}`。ルールのないドメインの削除は何もしない。
- 権限は `manage_settings`（`link_cards` と同じ、ADR-0058 のサーバー管理）。`manage_domains`（処分）にしない。モデレーションの権限ではなく、サーバーの外への取得の設定なので。
- 監査の種類は対象 `link_card_domain` に `link_card_domain_fetch_stopped`、`link_card_domain_images_stopped`、`link_card_domain_rule_removed`。

### この決定を見直す条件

- サイト運用者からの要望で、`robots.txt` やホストごとの取得の上限（別の issue）だけでは足りないとき、ルールの自動の追加を考える。

## Consequences（影響）

- 良い影響: 連合を止めずにカードの取得だけを止められる。取得を断ってきたサイトに、すぐ、確実に応えられる。
- 悪い影響: カードの表示ごとに、ホストごとの処分の読み出しに加えてルールの読み出しが増える。主キーの引き当てで、表示の流れの N+1 は処分と同じ形のまま残る。
- 悪い影響: 似た目的の場所が 2 つある（処分とルール）。画面の説明で違いを書く。
- `fediverse:creator` の検証（WebFinger）は連合の照会でカードの取得ではないので、`no_fetch` のドメインにも行う。投稿の作者の解決と同じ扱いにする。
- `robots.txt`、ホストごとの取得の上限、ページの robots メタタグ、サイト運用者向けのページは、別の issue で扱う。

## Pros and Cons of the Options（詳細比較・任意）

### 処分に種類を足す

- 良い: 表と画面を増やさない。期限やメモの仕組みを使える。
- 悪い: 処分は `domain_restrictions` に投影して連合の判定に読まれ、公開の一覧・CSV の書き出し・モデレーションの権限に乗る。カードだけの設定をそれぞれから外す分岐が増え、影響の分離（判断基準 1）に反する。

### インスタンス設定に一覧を持つ

- 良い: 表が要らない。
- 悪い: 問い合わせる値を文字列に詰めることになり（ADR-0020 の「問い合わせるデータに JSON を使わない」）、親ドメインの引き当てを読み出しのたびに解く必要がある。1 ドメインの変更が設定全体の版になり、監査の対象も設定のキーになる。
