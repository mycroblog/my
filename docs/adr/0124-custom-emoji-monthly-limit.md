# ADR-0124: カスタム絵文字の作成数の上限を毎月リセットする

- Status: Accepted
- Date: 2026-10-30
- Deciders: @rosylilly
- Issue: #1868

## Context（背景・課題）

絵文字の作成の権限（FR-915）では、`create_custom_emojis` を持つ人の作成数を、プランの上限（FR-910 の「絵文字の作成数の上限」、`supporter_plan_revisions.emoji_limit`）までに抑える。
[ADR-0070](0070-permission-split-emoji-finance.md) §4 は、作成者が自分である存在するローカルの絵文字と、審査中の作成の申請の **合計** を数え、削除すれば枠が空くとしている。
[ADR-0072](0072-supporter-plans-and-roles.md) §11 は、上限の値をプランから導く。

この方式では、上限まで作った人は絵文字を消さない限り新しい絵文字を作れず、サポーターを続けても作れる数が増えない。決定者は、上限を毎月リセットする方式に変えるとした（原文。問い → 答え）:

> カスタム絵文字の上限を毎月リセットへ変更 → カスタム絵文字の追加上限を毎月リセットする方式へ
> カスタム絵文字の月次リセット上限で、何を『その月の作成数』として数えますか？月の区切りはどこにしますか？ → 月内の申請数・UTC

この ADR は ADR-0070 §4 の「数えるもの」と「上限が下がったとき」を置き換える。ポート `CustomEmojiQuota`・上限なしの扱い・ADR-0072 §11 の上限の導き方は変えない。

## Decision Drivers（判断基準）

1. サポーターを続ける人が、毎月新しい絵文字を作れる（決定者の要望）
2. 申請を出してから承認されるまでの間に、上限を超えて作れない
3. 承認する人の手間（却下）を増やさない
4. 数え方が利用者に説明しやすい

## Considered Options（選択肢）

1. 月内に出した作成の申請のうち、承認済みと審査中を数える（UTC の暦月）
2. 月内に承認された数だけを数える
3. 直近 30 日の移動窓で数える

## Decision（決定）

**1 を採用する。**

### 1. 数えるもの

- 利用者がその月（UTC の暦月。1 日 00:00 UTC から翌月 1 日 00:00 UTC まで）に出した作成（`kind = create`）の申請のうち、承認された（`approved`）ものと審査中のものの数。月は申請を出した時刻（`custom_emoji_requests.created_at`）で決める。
- 却下（`rejected`）・取り下げ（`withdrawn`）・失効（`lapsed`）した申請は数えない。
- 承認した絵文字を後で削除しても、その月の数は減らない（枠は戻らない）。
- 画像の差し替えの申請（`image`）は数えない（今と同じ）。
- 管理画面や CLI で作った絵文字は申請ではないので数えない（作る人は上限のない管理者のため）。
- 申請のときに、その月の数が上限以上なら `422` にする（今と同じ）。前の月に出して翌月に承認された申請は、出した月に数える。

### 2. 上限の値

- 上限の値は「1 か月に作れる数」になる。プランの項目の名前を「絵文字の作成数の上限（毎月）」に変え、値の範囲（0〜10,000）と導き方（ADR-0072 §11）は変えない。
- 月の途中で上限が下がったら（プランの変更）、その月のすでに数えた申請は残し、数が上限より少なくなるまで新しい申請だけを断る。上限が上がったら、すぐその分だけ申請できる。
- 上限なしのときは数えない（今と同じ）。

### 3. 画面と API

- 使った数の API（今の `Used`・`Pending`・`Limit`）は、その月の数を返し、次にリセットされる時刻（翌月 1 日 00:00 UTC）を足す。
- 画面は「今月の作成 使った数 / 上限」と、次のリセットの日時を閲覧者のタイムゾーンで出す。
- 管理画面のプランの編集の項目の文言を変える。

### この決定を見直す条件

- 月の初めに申請が集中して、承認する人の負担が問題になったとき（移動窓の 3 にする）。

## Consequences（影響）

- 良い: サポーターを続ける人は、毎月上限まで新しい絵文字を作れる。
- 良い: 審査中の申請も数えるので、申請を溜めて上限を超えることはできない。
- 悪い: 1 人が作れる絵文字の総数に上限がなくなり、ローカルの絵文字は増え続ける。数を抑えるのは承認する人の却下と、作成者自身の削除だけになる。
- 悪い: 削除しても枠が戻らないので、作り直しの申請はその月の枠を使う。
- 悪い: 月の区切りは UTC で、日本では毎月 1 日の 9:00 にリセットされる。画面でリセットの日時を出して補う。
- 後続の作業（Issue にする）: FR-910・FR-915 の文言、data-model §4.4 の数え方、`CountCustomEmojiUsage` のクエリ（両方の方言）、使った数の API と `pkg/mykit`、絵文字の申請の画面とプランの編集の画面の文言、`locales/en`・`locales/ja`、運用文書（`agentkit docs impact` が出すもの）

## Pros and Cons of the Options（詳細比較・任意）

- 2（承認された数だけ）: 却下された申請も審査中の申請も気にしなくてよく単純。ただし審査中の申請は数えないので、月末に大量に申請すると、承認する人が上限を数えて却下しなければならない（判断基準 2・3 に反する）。
- 3（30 日の移動窓）: 月初の集中が起きない。ただし「いつ何件空くか」が申請ごとに違い、説明しにくい（判断基準 4）。
