# ADR-0152: 一人のためのサーバー（single_user）

- Status: Accepted
- Date: 2026-11-07
- Deciders: @rosylilly
- Issue: #2437

## Decision（決定）

[この決定を見直す条件](#この決定を見直す条件) に当たれば覆る。要件は FR-811 で、FR-001・FR-010・FR-011・FR-102・FR-202・FR-308・FR-402・FR-721 が従う。

ビジョン（G1）は一人のサーバーを最小の形に挙げる。一人のサーバーは小さなコミュニティではなく、運営者本人の fediverse での居場所である。インスタンス設定 `single_user` がサーバーをこの形にする。

### 1. 設定と切り替え

- インスタンス設定 `single_user`（bool、既定 `false`）。`manage_settings` を要し、ほかの設定と同じく `setting_changed` として監査ログに残る（ADR-0058）。
- 有効にできるのは、ローカルのアカウントがちょうど 1 つのときだけである。インスタンスの Actor は数えない。
  - 数えるのは、消去の済んでいない（`account_lifecycle_states` が `deleted` でない）ローカルのアカウントのうち、登録が却下された（`user_registration_states` が `rejected`）ものを除いたすべてである。承認待ち・無効化・削除予定・制限中のアカウントも数える。どれも復帰して二人目になりうるからである。
  - 数え直しは設定を保存するトランザクションの中で行い、1 でなければ `422`（problem type `/api/v1/problems/single-user-requires-one-account`、`detail` に数）で断る。CLI（`my instance set`）も同じ検査を通る。
- 無効にするのはいつでもできる。無効にすれば、§2〜§5 で実効値として抑えた設定は保存した値に戻る。
- 有効にしても、どのデータも消さず、どの設定の保存した値も書き換えない。

### 2. タイムラインはホームだけ

- ローカルと連合のタイムラインを出さない。`local_timeline_visibility` と `federated_timeline_visibility` の実効値を `off` にする。
- ハッシュタグのタイムラインとリストのタイムラインは残す。リストは自分のフォローの絞り込みで、ハッシュタグはサーバーが知る投稿を探す手段として、一人でも意味がある。
- 連合そのものは変えない。フォロー・配送・inbox はほかのサーバーと同じに動く。

### 3. 登録は閉じたまま

- `registration_mode` の実効値を `closed` にする（サービスの終了の間と同じ、`EffectiveRegistrationMode`）。保存した値は書き換えず、管理画面では登録の設定を出さない。
- 招待、外部のログインの提供元による登録、登録の審査を止める。外部の提供元でのログインは残る。
- 登録のページ（`/auth/sign_up`）と外部の提供元の登録は、`closed` と同じく登録を受け付けない。CLI によるアカウントの作成（`my admin create`）も、モードの間は断る。どの経路もアカウントを作らない。

### 4. 404 を返す操作

モードの間、次の操作は problem type `/api/v1/problems/single-user-mode` の `404` を返す。全文検索の `search-unavailable` と同じく、型で理由を区別できるようにする。モードを切れば元どおり動く。

| 機能 | 操作 |
| --- | --- |
| ローカル・連合のタイムライン | `getLocalTimeline`・`getFederatedTimeline`・`streamTimeline`（`local`・`federated`） |
| おすすめのアカウント | `listAccountSuggestions` |
| 利用者の招待 | `listOwnInvites`・`createOwnInvite`・`revokeOwnInvite` |
| 管理者の招待 | `listInvites`・`createInvite`・`revokeInvite` |
| 登録の審査 | `listPendingRegistrations`・`approveRegistration`・`rejectRegistration` |
| 登録のブロックリスト | `listSignupBlocks`・`createSignupBlock`・`getSignupBlock`・`liftSignupBlock`・`importSignupBlocks` |

- アカウントの一覧（ディレクトリ）の API は無いので、Web クライアントの人を探す画面のおすすめの欄だけを隠す。アカウントの検索（FR-307）は外のアカウントを探すのにも使うので残す。
- 登録のブロックリストは登録の審査の一部で、登録の無いサーバーでは意味がないので、ほかと同じく隠す。

### 5. 公開範囲 `local`

- 一人のサーバーで `local` はフォロワー限定と同じ意味なので、新しい投稿には使わない（ADR-0017）。
  - `createStatus` は `local` を `422` で断る。`CredentialAccount.posting_limits` から `local` を外すので、投稿の画面は選ばせない。
  - 既定の公開範囲が `local` の利用者の既定は、モードの間 `private` として扱う。`local` を既定に保存することは断る。
  - 通話のルームの開始の投稿（FR-929）は、モードの間 `private` で投稿する。
- すでに `local` の投稿はそのまま `local` で、表示も変わらない。

### 6. ほかのサーバーと利用者への表明

- NodeInfo は `openRegistrations: false` を返し、`metadata.singleUser: true` を加える。
- `GET /api/v1/instance` は `single_user`（bool）を返す。`registrations.mode` は実効値の `closed`、`timelines` の `local` と `federated` は実効値の `off` を返すので、このフィールドを知らないクライアントもタイムラインと登録を出さない。
  クライアントは `single_user` を見て、§4 のほかの機能（おすすめ、招待、登録の審査とブロックリスト）と `local` の公開範囲を、試す前に隠す。

### 7. 最初のページは運営者のプロフィール

- ログインしていない訪問者がサーバーの `/` を開くと、運営者のプロフィール `/@<name>` を出す。ログインへのリンクと、紹介（about）・利用規約・プライバシーポリシーへのリンクを添える。ログインした利用者は今までどおりホームへ行く。
- 運営者は §1 で数えたただ 1 つのアカウントである。

### 8. 残るもの

- モデレーションは運営者自身のために残す: ほかのサーバーからの通報、ドメインのブロック、判定のフック（ADR-0147）。
- 全文検索は、自分の投稿を探すために残す。
- サポーターはモードと独立の設定のままで、一人のサーバーでも寄付を受けられる（ADR-0072）。
- 紹介のページ・利用規約・プライバシーポリシーは、求められる場所があるので残す。
- 管理画面は残し、一人に意味のない項目（登録・招待・登録の審査とブロックリスト・タイムラインの公開・おすすめのアカウントの選択）を出さない。

### この決定を見直す条件

- 一人のサーバーが二人目を迎えたい（家族など）という求めが続けば、§1 の「ちょうど 1 つ」を見直し、少人数のモードを別に考える。

## 経緯

ビジョンの G1 は一人のサーバーを最小の形に挙げるが、今のサーバーはどれもコミュニティの形をしていた: ローカルと連合のタイムライン、登録・招待・登録の審査、おすすめのアカウント、サポーター、参加を誘う最初のページ。

決定者は、設定 `single_user` を、ローカルのアカウントが運営者だけのときに限って有効にし、いつでも切れるものと決めた。ホームだけのタイムライン、閉じた登録、運営者のプロフィールを最初のページにすること、NodeInfo での表明、`local` を出さないこと、一人に意味のない機能を消さずに隠すこと、モデレーション・全文検索・管理画面・文書を残すことも決めた。
数えるアカウントの状態、404 の型、ハッシュタグとリストのタイムラインを残すこと、登録の設定を実効値で抑えることも決定者が選んだ。

## 採らなかった案

- 有効なアカウントだけを数える: 無効化した人の復帰や承認待ちの承認で二人目ができ、それを防ぐにはモードの間それらの操作も断る必要がある。
- `about:blank` の 404 にする: タイムラインを `off` にしたときと同じ形で済むが、サードパーティのクライアントが「無い」理由を区別できない。
- ハッシュタグのタイムラインも隠す: 文字どおりホームだけになるが、一人でも話題を追う手段として使える。
- 有効にするときに `registration_mode` を `closed` に書き換える: 保存した値と実効値が一致するが、モードを切ったときに元の設定に戻らない。
- 一人に意味のない機能のデータを消す: 隠すだけならモードを切って元に戻せる。

## Consequences（影響）

- 一人の運営者は、コミュニティのための画面と設定を見ずに済み、サーバーは本人のプロフィールとして見える。
- モードの検査が登録・タイムライン・招待・審査・投稿の入口に散る。各入口は同じ設定を読む 1 つの判定（`instance.Settings.SingleUser()`）を使う。
- モードを有効にした直後に別の経路でアカウントができる競合は、数え直しを同じトランザクションで行っても PostgreSQL の READ COMMITTED では残る。登録は §3 で設定をトランザクションの中で読み直すので、残るのは同時の数ミリ秒だけで、運営者が手で切り替える操作なので受け入れる。
- 後続の作業: #2438（サーバー）、#2439（Web クライアント）。FR の更新と FR-811 の追加は ADR と同じ変更で行う。
