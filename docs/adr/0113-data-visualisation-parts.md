# ADR-0113: データの図の部品を @my/ui に手書きの SVG で作る

- Status: Accepted
- Date: 2026-10-28
- Deciders: @rosylilly
- Issue: #1646

## Context（背景・課題）

[ADR-0110](0110-web-experience-principles.md) の P3（形で先に伝える）は、数と推移を図で示すことを求める。しかし `@my/ui` には図・メーター・進み具合・数の要約の部品が 1 つもなく
（不定の進み具合の `Spinner` だけ）、管理の画面は数を表と文字で出している。#1638 の管理の画面の点検は、次を指摘した。

- A1: モデレーションと管理のトップに、待ち行列と異常の件数の要約がない。
- A3: 費用と収入（公開の `/about/costs` を含む）が期間の表と文字の行で、推移・内訳の割合・収支が見えない。
- A9: ジョブのキューの状態が、同じ形の数の格子で、失敗が目立たない。
- A10: エラーの発生の推移が、1 日 24 行の表と「24 時間 / 7 日」の文字である。
- A11: サービスの終了の後の配送の進み具合が、数の説明リストで、全体に対する割合が見えない。

図を足すには、2 つの決まりに触れる。

- [ADR-0031](0031-ui-kit-behavior-dependencies.md) の `@my/ui` の依存の許可リストに、図のライブラリがない。
- web-client §16 の G10（`restrict/svg`）は、`@my/ui` の部品にも SVG を描かせず、例外を `app/.oxlintrc.json` に理由とともに挙げたものだけにしている。

画面の規約（web-client §14 の費用・エラー）も表で出すと定めているので、部品の作り方を先に決める必要がある。
図は NFR-A11Y-1（WCAG 2.2 AA）・ADR-0027 の品質ゲート・[ADR-0059](0059-design-tokens-and-instance-theme.md) のサーバーのテーマ・
[ADR-0111](0111-soft-visual-language.md) の面とダークモード・ADR-0009 の RTL に従わなければならない。

## Decision Drivers（判断基準）

1. **アクセシビリティ**: 図の値を、支援技術と強制カラーモードの利用者も同じだけ読めること（表への切り替え、1.4.1 色だけに頼らない、1.4.11 の 3:1）。
2. **テーマとの一致**: 色をトークン（CSS の変数）から取り、サーバーのテーマ・ライトとダーク・強制カラーモードに CSS だけで追従すること。RTL で向きが合うこと。
3. **依存と大きさ**: 公開の `/about/costs` にも載るので、増える JavaScript が小さいこと。依存を増やすなら ADR-0031 の条件（ドメインなし・AGPL と両立・Web と Tauri）を満たすこと。
4. **作る手間と保守**: 最初の部品（数の要約・推移の図・小さな推移・内訳の帯・進み具合）を短い期間で作れ、React Compiler（`app/web` の Vite の設定）と React 19 で問題なく動くこと。
5. **将来の図**: 散布図・拡大・範囲の選択のような、対話の多い図が要るようになったときに広げられること。

## Considered Options（選択肢）

1. **`@my/ui` に手書きの SVG と HTML で部品を作る**（新しい依存なし）
2. **Recharts を許可リストに足し、`@my/ui` で包む**
3. **visx の低水準の部品（`@visx/shape`・`@visx/scale`）を許可リストに足し、`@my/ui` で包む**

Chart.js・ECharts のような canvas で描くライブラリは、図がアクセシビリティのツリーにも CSS の変数にも乗らず、判断基準 1・2 を満たせないので比べない。

## Decision（決定）

**選択肢 1 を採る。** 要る図は、軸 1 本の棒・折れ線と、割合の帯と、数だけである。これらは線形の目盛りと数十行の座標の計算で描け、ライブラリの機能の大半を使わない。
手書きなら、色・向き・動き・読み上げを、すでにある `@my/ui` の部品と同じ規則（トークン・論理プロパティ・`forced-colors:`・`motion-safe:`）で書ける。

### 1. 最初の部品

名前は実装で決める。数と日時の書式は、`@my/ui` がカタログを持たないので（ADR-0031）、書式済みの文字列か書式の関数を props で受け取る。

| 部品 | 描き方 | 役割と読み上げ |
| --- | --- | --- |
| 数の要約（`StatTile`） | HTML | 名前・値・前の期間との差。差は上下の矢印のアイコン（`Icons.tsx`）と「+12%」の文字で示し、色だけにしない。状態（注意・危険）は `Badge` と同じトークン |
| 推移の図（`TrendChart`） | SVG | 期間ごとの棒か折れ線（系列は 3 本まで）。図は `role="img"` で、見出しと要約の文（最大・最新・増減）を `aria-labelledby` と `aria-describedby` にする。「図 / 表」の切り替え（React Aria の `ToggleButtonGroup` を `@my/ui` で包む）で同じデータを `@my/ui` の `Table` で出す。切り替えの選択は URL か `lib/storage` に置く画面の側の状態にする |
| 小さな推移（`Sparkline`） | SVG | 一覧の行の中の折れ線。飾りとして `aria-hidden` にし、同じ行に数を文字で必ず出す |
| 内訳の帯（`BreakdownBar`） | HTML | 項目ごとの割合を 1 本の帯に並べ、凡例に名前・値・割合を文字で出す。帯は `flex` の論理の向きで並ぶので RTL で自然に反転する |
| 進み具合（`ProgressMeter`） | HTML | React Aria の `ProgressBar`（決まった量の進み）と `Meter`（量の度合い）で包み、`aria-valuetext` に「1,234 / 5,000 件」の文を渡す |

SVG を描くのは `TrendChart` と `Sparkline` だけである。帯・進み具合・数の要約は HTML と CSS で描く。

### 2. 規約の変更

- **G10（`restrict/svg`）**: 例外に「データの図（`TrendChart`・`Sparkline`）」を足し、`app/.oxlintrc.json` に 2 つのファイルを理由とともに挙げる。アイコンは今までどおり `Icons.tsx` だけから使う。
- **ADR-0031**: 依存を増やさないので許可リストは変えない。
- **web-client §14**: 費用・収入（`/admin/finance`・`/finance`・`/about/costs`）・ジョブ・エラー・サービスの終了の規約を、図と表の切り替えで出す形に書き直す（後続の issue）。

### 3. 色・テーマ・向き・動き

- **色**: SVG の `fill` と `stroke` は Tailwind のユーティリティ（`fill-*`・`stroke-*`）でトークンから取り、`light-dark()` とサーバーのテーマにそのまま追従させる。
  系列の色は新しい 3 つのトークン `--color-data-1`〜`--color-data-3` にし、ADR-0059 の上書きできるトークンと生成器の一覧に足す。
  各色は面（`surface`・`surface-raised`）に対して 3:1 を満たし、`check-tokens` の対象にする。
- **色だけに頼らない**: 系列は線の形（実線・破線）と凡例の文字でも分ける。差・状態はアイコンと文字を添える。
- **強制カラーモード**: 系列の色は失われるので、`forced-colors:` で線と棒を `CanvasText`、強調を `Highlight` にし、系列は線の形で分ける。帯の区切りは境界線で残す。
- **ダークモードと面**: 図は区画（`surface-raised`）の上に置き、格子の線は `border` のトークンにする。ADR-0111 の影を図の要素には使わない。
- **RTL**: 時間の軸は行の向きに合わせ、RTL では新しい期間を左に置く。SVG は `dir` に従わないので、React Aria の `useLocale().direction` で x の目盛りを反転する。数と日時は `dir="ltr"` の `bdi` で出す。
- **動き**: 描き始めの動きは付けない。値が変わったときの移り変わりだけを `motion-safe:` とトークンの長さ・緩急（`duration-fast`・`ease-standard`）で付ける。

### 4. 検査

部品ごとにストーリー（ライト・ダーク・強制カラー・`ar-XB`・空のデータ・1 点のデータ）と、座標の計算・目盛り・表の切り替えの単体テストを置き、ADR-0027 の axe とスクリーンショットの検査に入れる。

### 見直す条件

- 散布図・拡大・範囲の選択・ツールチップでの点の読み取りのように、対話の多い図が要る画面の要件（ADR-0110 の L1）が出た場合（選択肢 3 を許可リストに足して、その図だけに使う）。
- 手書きの図の計算（目盛り・欠けたデータ・負の値・通貨の違う系列）の不具合が、部品の追加のたびに続く場合。

## Consequences（影響）

- 良い: 依存が増えず、公開の `/about/costs` に足す JavaScript は部品の分だけで済む。色・RTL・強制カラー・動きが、ほかの `@my/ui` の部品と同じ規則で効く。
- 良い: 表への切り替えを部品の必須の形にするので、図を足しても今の表の情報（§14 の規約が守ってきたもの）を失わない。
- 悪い: 目盛りの丸め（1・2・5 の刻み）、欠けた期間、負の収支、通貨ごとの系列の扱いを自分で書いてテストする。ライブラリが解いている端の場合を作り直すことになる。
- 悪い: ツールチップ・拡大・凡例の切り替えのような対話は持たない。値は表への切り替えで読む。
- 悪い: `restrict/svg` の例外が 2 つ増える。図の部品の中では SVG を自由に描けるので、レビューで図以外の絵を入れないよう見る。
- 後続の作業（issue にする）:
  - `@my/ui` に 5 つの部品と系列の色のトークンを足し、G10 と `app/.oxlintrc.json`、`app/ui/README.md` を更新する。
  - web-client §14 の費用・収入・ジョブ・エラー・サービスの終了の規約を図と表で書き直し、画面に当てる（A3・A9・A10・A11）。
  - モデレーションと管理のトップの要約（A1。`StatTile` の並び）。

## Pros and Cons of the Options（詳細比較・任意）

ライセンス・版・依存は 2026-10-28 に npm の registry（`npm view`）で、大きさは同じ日に [Bundlephobia](https://bundlephobia.com/) で確かめた。
Bundlephobia の値はパッケージ全体を minify して gzip したもので、tree shaking 後の実際の増分はこれより小さい（実際の増分は 要検証）。

| 観点 | 1. 手書き | 2. Recharts 3.10.1 | 3. visx 4.0.0 |
| --- | --- | --- | --- |
| ライセンス | AGPL（自前） | MIT | MIT |
| 大きさ（gzip） | 部品の分だけ（数 kB の見込み） | 約 150 kB。依存は Redux Toolkit・immer・`victory-vendor`（d3）など 11 個 | `@visx/shape` 約 11 kB に `@visx/scale` などを足す |
| React Compiler | 自前のコードなので、ほかの部品と同じく compiler と lint に通る | 内部は Redux の store で動く。包む側のコードとの組み合わせは 要検証 | 描くだけの関数の部品で、問題は少ない見込み（要検証） |
| トークン・ダーク・テーマ | クラスでトークンを使う | 色を props の文字列で渡す。`var(--color-…)` を渡せば追従する見込み（要検証） | クラスでも props でも渡せる |
| RTL | 目盛りを自分で反転する | 軸の `reversed` で反転できる（要検証） | 目盛りを自分で反転する |
| 表への切り替え | 自前で作る | 自前で作る（キーボードで点を読む `accessibilityLayer` はある。要検証） | 自前で作る |
| 強制カラー・動き | `forced-colors:`・`motion-safe:` で書く | 描き始めの動きが既定で付き、`isAnimationActive` で止める（要検証）。強制カラーは CSS で上書き | 動きは持たない。強制カラーは CSS で書く |
| 対話（ツールチップ・拡大） | なし | 豊富 | 部品として持つ（`@visx/tooltip` など） |
| ADR-0031 | 変更なし | 許可リストに足す。依存の木が大きい | 許可リストに足す |

- **選択肢 2 の最も強い点**: 棒・折れ線・面・円の図とツールチップ・凡例・軸がすぐ使え、端の場合（目盛り・欠けたデータ）が解かれている。図の種類が増えるほど得になる。
- **選択肢 3 の最も強い点**: 描画を自分で持ちながら、目盛りと形の計算（d3 由来）を借りられる。見直す条件に当たったときの移り先になる。
