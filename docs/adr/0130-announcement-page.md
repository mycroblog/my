# ADR-0130: お知らせの個別ページ

- Status: Accepted
- Date: 2026-11-02
- Deciders: @rosylilly
- Issue: #1933

## Context（背景・課題）

決定者の要望（原文）:

> お知らせの個別ページを実装 `/announcements/01a18bbc-4663-71ea-a2b8-f3f169979c0a` の形式

ADR-0125 §2 は、通知と Web Push を押すと「一覧のページのそのお知らせ」を開くと決めている。個別のページができると、この行き先をどちらにするかを決める必要がある。FR-726 の範囲の決定で、要望そのものは行き先を言っていない。

## Decision Drivers（判断基準）

1. 1 つのお知らせに、変わらないアドレスがある（共有できる、あとから開ける）
2. 通知から開いて、目的のお知らせだけをすぐ読める（古いお知らせでも一覧のページを読み進めない）
3. 取り下げられたお知らせを開いたときに、そのことがはっきり分かる

## Considered Options（選択肢）

1. 通知・Web Push・右帯と一覧のタイトルを個別のページへ向け、`/announcements?id=` をなくす
2. 個別のページを足すが、通知と Web Push は一覧のページのそのお知らせのまま

## Decision（決定）

**選択肢 1 を採る。** ADR-0125 §2 の「一覧のページのそのお知らせ」だけを置き換え、ほかは ADR-0125 のままにする。

- `/announcements/{id}` はログインした利用者のページで、一覧（`GET /announcements/history`）に出るお知らせ（公開中で `ShowsFrom` を過ぎたもの。期間の終わったものを含む）を読める。下書き・取り下げ・始まる前・不明なものは 404 で、ページは見つからないことを言って一覧へのリンクを出す。
- 通知・Web Push・右帯と一覧のタイトルはここへ移る。開くと既読にする（ADR-0125 §2 のまま）。行き先で開いた経路を区別しないので、タイトルから開いたときも既読にする。
- 一覧のページの `?id=` はなくす（v0.1.0 の前なので互換を残さない。ADR-0087）。

## Consequences（影響）

- 一覧のページから、目的のお知らせを探して読み進める処理と、取り下げの注記がなくなる。
- 通知と Web Push で開いたお知らせが取り下げられていても、その 1 件について見つからないと言える。ただし取り下げと不明なアドレスは区別しない（どちらも 404）。
- 一覧のタイトルを押すだけで既読になる。
