# ADR-0168: 画面の上でのフィードバック（決定者とエージェント）

- Status: Accepted
- Date: 2026-11-12
- Deciders: @rosylilly
- Issue: #2863

## Decision（決定）

### 1. 流れ

決定者とエージェントが同じ画面をブラウザで開き、決定者が要素（か範囲）にメモを書き、まとめて送る。送るとエージェントのセッションにすぐ届く。エージェントは同じ画面を自分のブラウザで開いて直し、メモの横に答える（直した・質問・案）。案は画像ではなく、画面の上で切り替えられる実物の variant で出し、選んだ結果もメモと同じ経路で返る。

### 2. メモが運ぶもの

絵ではなく構造を運ぶ。

- メモと、それが付いた要素か範囲
- その要素を作ったソースの場所（開発ビルドだけが付ける）
- その部品の層（ADR-0025 §2）: 直すべき層がエージェントに分かる
- 画面の状態: ルート、ビューポート、テーマ、ロケール、向き、ログイン中のアカウント
- 再現の手がかり: E2E のシナリオ（ADR-0015 §5）とその段
- 補助として、その範囲のアクセシビリティツリーと切り抜いたスクリーンショット

### 3. 置き場と順序

層の外の `@my/devtools` が持ち、開発とプレビューのビルドだけが読み込む。本番のビルドに入らないことを検査で保証する。使える場所は、デモのデータの入った開発サーバー、次に Storybook、次に PR ごとのプレビュー（ADR-0165）の順に広げる。ローカルではメモをリポジトリの外のファイルに置き、プレビューではサーバーの側（PR のコメントなど）に置く。

## 経緯

スクリーンショットを貼って話すやり方は、どの部品の、どのソースの、どの状態かが絵から読めず、ほとんどうまくいかなかった（#2863）。案を画像で見せてから作ると少ない往復で決まったので、案も画面の上の実物で見せる。

## 採らなかった案

- スクリーンショットと文章で続ける: 道具が要らないが、部品とソースと状態が伝わらない。
- PR のコメントだけで受け渡す: 仕組みが要らないが、要素とソースに結びつかず、画面を見ながら書けない。

## 見直す条件

- メモのたびに、エージェントが要素からソースを探し直している: 運ぶものを足す。
- プレビューで使うと、メモの保存が無料の枠や権限の範囲を超える。
