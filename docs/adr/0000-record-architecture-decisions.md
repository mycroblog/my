# ADR-0000: 設計判断を ADR で記録する

- Status: Accepted
- Date: 2026-11-04
- Deciders: @rosylilly
- Issue: #2078

## Decision

- 設計判断は `docs/adr/NNNN-kebab-case-title.md` に [template.md](template.md) の形で記録する。新規作成は `scripts/task.sh docs:adr-new`。
- **ADR は主題ごとに 1 ファイルとする。** 主題を持つ ADR があれば、新しいファイルを足さず、その ADR を直す。ファイルを足すのは、どの ADR も持たない主題だけにする。
- ADR には結論、そこに至る判断の変遷、採らなかった案を書く。決定者の回答の原文は載せない。やり取りの経過は git と Issue が持つ。
- ステータスは `Proposed` → `Accepted` / `Rejected`。Accepted の ADR の結論を変えるときは、本文をその場で書き換え、置き換えた内容のうち読み手に要るものを `経緯` か `採らなかった案` に移す。
- 節番号は変えない。コードと文書が `ADR-NNNN §k` で引用している。節は末尾に足し、内容はその節の中で書き換える。
- ADR を別の ADR に統合した番号は廃番にし、移転先を `docs/adr/aliases.yaml` に書く。古い Issue や PR の引用はそのファイルで解決する。廃番は再利用しない。
- **エージェントは ADR を `Proposed` で起票・改訂してよいが、`Accepted` への変更と、Accepted の ADR の結論の変更は人間の Decider が行う。** Decider が述べた決定は、エージェントが ADR に反映してよい。
- 議論は ADR ごとの GitHub Issue（ラベル `type:adr`）で行い、結論を ADR 本文に反映して PR でマージする。
- ドキュメントの言語: 設計ドキュメント（ADR・要件）は v0 の間は日本語。コード・識別子・コミットメッセージ・コードコメントは英語。

## 経緯

本プロジェクトは複数のコーディングエージェントが並行して自律的に作業する前提で、口頭やチャットで決めたことはエージェントから見えないため、設計判断をリポジトリ内に機械的に辿れる形で残す必要がある。

当初は 1 判断 1 ファイルとし、Accepted の本文を書き換えず新しい ADR で置き換えていた。ADR が 140 件を超えると、1 つの主題の結論が複数のファイルと Status の注記に分かれ、結論を探すエージェントにとってノイズになった。そこで主題ごとに統合し、本文を書き換えてよいことにした。

## 採らなかった案

- 不変の ADR を積み重ねる: 決定の時点の記録として正確だが、経過は git で足り、今の結論を複数のファイルから組み立てる負担のほうが大きい。
- 番号を 0001 から振り直す: 一覧はきれいになるが、書き換えられない古い Issue や PR の番号が別の ADR を黙って指す。
- 決定者の回答の原文を残す: 決定の根拠を示せるが、読み手に要るのは結論と理由で、原文はノイズになる。

## Consequences

- `scripts/agentkit.sh adr list` を見れば、何が決まっていて何が未決かを判断できる。
- 未決（Proposed）の ADR に依存する実装 Issue は `status:needs-decision` で止めておける。
- ADR の過去の版を知るには `git log` を見る。
