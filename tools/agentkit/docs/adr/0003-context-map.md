# ADR-0003: パスと規約の対応表 context-map を、コードを増やすエージェントが保守する

- Status: Accepted
- Date: 2026-10-22
- Deciders: @rosylilly
- Issue: なし

## Context（背景・課題）

変更する場所が決まっても、その場所に効く規約がどの文書のどの節にあるかは、文書を読まないと分からない。
たとえば `docs/architecture/web-client.md` は約 9 万トークン、`data-model.md` は約 9.4 万トークンあり、全体を読むと 1 タスクの予算を使い切る。
パスから節を引ける表があれば `ctx` が必要な節だけを渡せるが、表が古くなれば誤った前提を渡すことになる。
決定者の指示（原文）:

> 人が管理するというかコーディングエージェントがディレクトリやコードを増やした時に保守される対象であってほしいです

## Decision Drivers（判断基準）

- 新しいディレクトリやモジュールを足した変更が、対応表の更新を忘れられないこと
- 文書の見出しが変わったときに、壊れた参照が残らないこと
- 要約を置かず原文の節を指すこと（要約は古くなる）

## Considered Options（選択肢）

1. 人が保守する表
2. エージェントが保守し、CI が網羅と参照を検査する表
3. 表を置かず、パスと文書の対応を推測する

## Decision（決定）

選択肢 2。

- 表は、ディレクトリごとに置く `context-map.yaml`。そのディレクトリ全体について、読む文書の節、利用者と運用者の文書、チェックのコンテキスト、並行作業で同時に触らない共有の場所かを持つ。ファイル単位の対応は持たない。1 つのファイルに効く規約は、コードとそれを検査する仕組みが言う
- 表は、より近い表を持たない配下すべてに効く。文書とチェックは上位のディレクトリの表に足され、共有かどうかは最も近い表だけが決める。表には上位と異なることだけを書き、異なることがないディレクトリは表を持たない
- パターンを書けるのはリポジトリのルートの表だけで、ルート直下のファイルとドットで始まるディレクトリに使う。全体の設定もルートの表が持つ
- 表に注意書きは置かない。規約は、それを検査する仕組みの失敗メッセージに書く
- 検査は次のときに失敗する
  - 追跡しているファイルが、どの表の配下でもなく、除外にも当たらない
  - 表が、上位の表と同じことを繰り返している
  - 文書の参照が、存在しないファイルや見出しを指している
  - 存在しないチェックのコンテキストを挙げている
  - 利用者と運用者の文書が、どの表にも挙がっていない
- どのパスの変更でも、この検査を CI で走らせる。ファイルの追加も見出しの変更も、その PR で検出される

## Consequences（影響）

- 機能を足す変更は、表を変えない。新しいモジュールは、上位と異なる文書があるときだけ、自分のディレクトリに小さな表を 1 つ足す
- 文書の見出しの名前を変えると、対応表も直す必要がある
- ファイル単位の対応を持たないので、1 つのファイルだけに効く文書は表から引けない
