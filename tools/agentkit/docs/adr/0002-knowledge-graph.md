# ADR-0002: 構造の索引と全文検索で前提を引き、結果は CLI で小さく返す

- Status: Accepted
- Date: 2026-10-22
- Deciders: @rosylilly
- Issue: なし

## Context（背景・課題）

[ADR-0001](0001-agentkit.md) の集計のとおり、トークンの大半は、エージェントが grep や cat でファイルの位置を探し、必要以上の範囲を読むことに使われている。
このリポジトリでは前提の参照が識別子で書かれている。Issue は `FR-915`・`ADR-0070`・`overview §6` のように前提を指し、コードの 1,263 ファイルが FR や ADR に言及している。
API は operationId、ハンドラ、app のサービス、adapter、sqlc のクエリ、テーブルを、名前の規約でつないでいる。
決定者の回答（原文）:

> ADR-0002 Accepted

## Decision Drivers（判断基準）

- 1 回の出力を小さくすること、探索のターン数を減らすこと
- 結果が決定的で、外部 API やキーが要らないこと
- 索引が常に作業ツリーと一致していること（更新を忘れられる手順を作らない）
- worktree で並行して動くエージェントが索引を共有できること

## Considered Options（選択肢）

1. ID・アンカー・名前を辺にした構造の索引（ナレッジグラフ）と、SQLite FTS5 の trigram による全文検索
2. 埋め込みベクトルによる検索（RAG）
3. 1 と 2 の併用
4. 提供の形: CLI か、MCP サーバーか

## Decision（決定）

選択肢 1 を、CLI で提供する。

- 節: Markdown の見出し（GitHub と同じアンカー、節番号 `§4.4`、ADR の `ADR-0070#<anchor>`）、要件の表の行（`FR-915`）、Go の宣言、TypeScript のトップレベルの宣言、`schema/*.sql` のテーブル、sqlc のクエリ、OpenAPI の operation とコンポーネント、ロケールのメッセージ
- 辺: 文書のリンクと ID の言及、コードスパン（`ident:`）、Go の import と名前による呼び出し（`name:`）、TS の import・使うコンポーネントとフック・呼ぶ API のパス、クエリが使うテーブル、OpenAPI のパスとファイルの対応
- 生成物（`*.gen.go`、sqlc の出力、`api/openapi.yaml`、疑似ロケール）は索引に入れない
- 置き場所は `$(git rev-parse --git-common-dir)/agentkit/kb.db`。抽出結果は（パス、blob の id）ごとに保存して worktree の間で共有し、各プロセスは自分の作業ツリーの（パス、blob の id）の集合を一時テーブルに作って、それを通して引く。コマンドのたびに差分だけを索引する（初回は約 6 秒、以降は数十ミリ秒）。2 週間使われなかった結果は消す
- 日本語は形態素解析なしで trigram で引き、3 文字未満の語は LIKE で照合する
- 出力の規則: 位置（`path:start-end`）と大きさ（トークンの見積り）を先に返し、本文は求められた範囲だけを返す。上限を超える節は小見出しの一覧を、小見出しのない大きな節は Issue の語を含む段落・表の行・箇条書きの項目だけを返す
- `ctx <issue>` は 1 回の呼び出しで、Issue、要件、ADR の Decision、参照された節、該当する領域の規約（[ADR-0003](0003-context-map.md)）、コードの入口、同じ要件の先行 PR が変えたファイルを、予算（既定 3 万トークン）の中でまとめる
- 埋め込みベクトルは入れない。評価で再現率の不足が分かったときに、検索の差し替えとして別の ADR で決める
- MCP ではなく CLI にする。ツールの定義が全エージェントの文脈に常に載らず、Claude Code 以外のエージェントもシェルから使える

## Consequences（影響）

- 名前による呼び出しの解決は型を見ないので、同名の宣言を取り違えることがある。`trace` は深い層へだけたどり、汎用の名前（`Now` など）と候補の多い名前を除き、方言違い（sqlite / postgres）を 1 行にまとめて雑音を抑える
- 抽出器を変えたら `extract.Version` を上げる。版の違う索引は作り直す
- 効果は `agentkit stats`（セッション記録の集計）で、導入の前後を比べて確かめる
